# 📜 赛博城邦最高宪章：V6 自治有向无环图协议 (V6 Autonomous DAG Protocol)

> **修订版本**: V6.0
> **实施状态**: Phase 0 (自举过渡期)
> **执行效力**: 绝对约束。任何违背本宪章流程的合并操作，视为系统级叛乱，触发自动阻断。

本宪章废黜了过去单薄的文本堆砌，重构为 **【流程规范层 (The Workflow Layer)】** 与 **【物理基建层 (The Infrastructure Layer)】** 的双核驱动架构。本宪章的根本目的是在极速进化的同时，通过冷酷的防阿谀机制与物理隔离，守住城邦的代码绝对安全与纯粹逻辑。

---

## 第一卷：流程规范层 (The Workflow Layer)

本卷定义所有公民（Agent）在城邦议会中必须遵守的接口契约与社交防火墙。

### 1.1 需求拦截与澄清机制 (Requirement Interception)
任何任务的发起，严禁直接进入编码阶段。必须由首位接触的 `Requirement_Agent` 触发 **【强制五问反向问询】**。
- **输入**: 议长的自然语言需求。
- **动作**: 校验需求是否覆盖 5 个维度（意图、边界、副作用、前置依赖、验收标准）。
- **输出**: 若有缺失，发出非阻塞的异步回调（Asynchronous Webhook），等待议长补充。必须生成模板化文件 `00_需求澄清与反向问询模板_V6.md`。

### 1.2 辩论角色硬隔离契约 (Role Interfaces & Firewalls)
禁止一个 Agent 扮演多个角色，禁止精神分裂。各角色之间竖立信息防火墙。
- **侦察员 (Scout / Researcher)**: 
  - **契约**: 只允许搜索全网、提供客观事实和文献链接。
  - **红线**: 绝对禁止给出“推荐方案”或主观结论。
- **魔鬼代言人 (Devil's Advocate / Red Team)**:
  - **契约**: 接收侦察员的事实，只负责寻找逻辑漏洞、安全死穴和性能瓶颈。
  - **红线**: 绝对禁止进行建设性提议，禁止修补漏洞，必须保持纯粹的破坏欲。
- **防火墙规则**: 魔鬼代言人无法看到其他任何角色的“赞美”或“妥协”言论，以防止抛锚效应 (Anchoring Effect)。
- **回合物理上限**: 单一 Issue 辩论交锋次数上限设定为 3 回合（正反交锋计 1 回合）。

### 1.3 终极合题机 (Synthesis Judge) 与防阿谀熔断
辩论结束后，由 `Consensus_Judge_Agent` 进行最终合题。
- **禁止和稀泥**: 绝对禁止出现“综合双方意见均有道理”的表述。必须以**【采纳项 / 驳回项 / 待议项】**三栏表结构化输出。
- **早停熔断 (Early Stopping)**: Judge 必须计算最后 2 轮交锋的【信息增量密度】。若新信息增量 $\Delta < \epsilon$，立即触发熔断，终止无效复读。
- **物理矛盾提纯**: 对于无法调和的矛盾，Judge 不得擅自妥协，必须强制提纯为二元选择题，上抛给人类议长进行终极裁决。

### 1.4 事后验收的承诺比对矩阵
代码交付后，进入事后验收辩论。
- 验收官在测试前，必须从事前提案中物理提取出所有的功能承诺。
- 必须填写 **【承诺-交付比对矩阵】**，逐一建立测试映射。
- **降级触发**: 只要矩阵中存在任何一个 `[UNTESTED]` 标签，该验收报告自动从 `[APPROVE]` 降级为 `[CONDITIONAL_APPROVE]`，系统挂起，等待议长人工确认。

## 第二卷：物理基建层 (The Infrastructure Layer)

本卷定义城邦底层的物理法则。不依赖沉重的 Python 框架，但在操作系统底层榨干性能与安全性。

### 2.1 本地目录级读写分离 (Local Directory-level CQRS)
废除直接修改单一 Markdown 状态文件导致的并发死锁与 Token 爆炸。
- **写模型 (Event Store)**: 所有 Agent 的行为动作追加写入 `activity.jsonl`（不可变事件总线）。
- **读模型 (Materialized View)**: 系统通过轻量级同步脚本（投影器），将 jsonl 聚合渲染为极简的 `status.md`。
- **无锁读取**: Agent 进场时只读取 `status.md`，实现 $O(1)$ Token 消耗。
- **跨平台原子覆盖**: 投影器更新 `status.md` 时，必须使用系统的原子替换操作。
  - *【Windows 适配层】*: 捕获 `os.replace()` 在目标文件被占用时抛出的 `PermissionError`，触发基于随机退避的“写入临时文件 + 重试”的回滚机制。

### 2.2 梯级物理沙盒瀑布流 (Lattice Waterfall Isolation)
废除单纯的静态 AST 扫描，实施动态运行时的物理阻断。系统将根据任务爆炸半径，梯级路由沙盒：
- **Tier 1 (敏捷本地)**: 基础业务逻辑。
  - *Linux*: 使用 `bwrap` 或 `Landlock` 隔离。
  - *【Windows 适配层】*: 降级为原生环境执行，或利用 WSL2 / Docker Desktop 进行轻量隔离。
- **Tier 2 (高危多租户)**: 高危外部代码引入。
  - *Linux*: Firecracker MicroVMs，内存快照秒级启动。
  - *【Windows 适配层】*: Windows Sandbox (WSB)。
- **Tier 3 (不可信插件)**: WebAssembly (Wasmtime) 极致隔离。

### 2.3 非对称混合模糊测试 (Asymmetric Hybrid Fuzzing)
禁止大模型直接跑 1000 次 Fuzzing 的算力自杀行为。引入双核质量网关：
- **靶向分离**: Markdown 仅做 Schema 与逻辑一致性校验。Fuzzing 仅针对 Python 脚本和边界数据。
- **生成核心 (Zero-Token)**: LLM 只负责编写基于“四元原则”的 Harness（测试驱动夹具）。底层的传统 `libFuzzer` 或 Python 原生 `atheris` 执行极速突变（万次并发）。
- **拦截核心 (Reactive Trigger)**: 只有底层捕获到真实的 Traceback 堆栈崩溃时，大模型才被单次唤醒进行伪阳性甄别。
- **覆盖率早停**: 连续 $N$ 次突变未能增加代码路径覆盖率时，测试网关强制止损熔断。

### 2.4 宪章效能度量 KPI (Charter KPIs)
系统每次流转必须在 `activity.jsonl` 自动计算并输出三大 KPI：
1. **辩论增量密度**: 辩论轮次中产生的新逻辑分支数量 / 总 Token 数。
2. **测试穿透率**: 模糊测试成功揭露真漏洞的数量 / 总崩溃警报数。
3. **承诺覆盖率**: 【承诺-交付比对矩阵】中 `[TESTED]` / 总承诺数。

## 第三卷：自举过渡序列 (Bootstrap Sequence)

V6 宪章不能在一夜之间颠覆运行中的城邦。我们必须解决**自举悖论 (Bootstrap Paradox)**。

### 3.1 Phase 0：基建期 (当前所处阶段)
- 所有的 V6 物理组件（CQRS 投影器脚本、沙盒调度器脚本、非对称 Fuzzing 测试架）都属于“新需求代码”。
- 这些基建代码的开发，**必须遵循现有的 V5 流程进行**（使用 V5 的模版、V5 的事前提案审批）。
- 在此期间，V5 的双检查协议维持法定效力。

### 3.2 Phase 1：双轨运行期
- 当投影器与 Windows 沙盒适配层代码开发完毕并通过议长验收后，系统进入双轨期。
- 新开设的 Issue 强制使用 V6 流程与 CQRS 架构；旧有 Issue 继续按 V5 标准直至关闭。

### 3.3 Phase 2：全面纪元
- V5 宪章完全归档至历史库。所有独立专家模型被全面打上 V6 的四层脑印记。赛博城邦正式跃迁为极简、并发、零死锁的高维自治体。
