# 议案：教学系统全栈路径重构方案

## 1. 议案背景
城邦主理人已将原 `localStudy` 的教学文件打散移植入城邦的 `01`, `02`, `03`, `06` 公域架构。但由于目录拆分，原先 `.md` 文件内部互相引用的硬编码相对路径（如 `学习期prompt/`、`复习巩固期prompt/`）全部断裂，导致导师系统面临无法拉取协议的死锁风险。

## 2. 物理修改通报
基于“防损耗法则”，本次行动在 `agent/Hyperion_Path_Refactor` 独立沙盒分支上完成了共计 28 处路径的重新缝合，具体如下：

### 2.1 启动入口的修复 (06_Silicon_Index)
*   **修改文件**：`窗口初始化指令.md`
*   **执行动作**：
    *   将指向 `学习期prompt/数学知识路线图_知识点版.yaml` 等 5 个客观事实文件的路径，重定向至 `../01_Research_Reports/`
    *   将指向导师核心 Prompt 的路径，重定向至 `../02_Protocols/数学架构师导师System_Prompt_v5.6.md`
    *   将 7 个复习用的子执行提示词路径，统一下沉映射至 `../03_Daily_Execution/`

### 2.2 核心导师架构的修复 (02_Protocols)
*   **修改文件**：`数学架构师导师System_Prompt_v5.6.md`
*   **执行动作**：
    *   内部对 `交叉练习`、`即时编码` 的出题协议调用，全部路由指向 `../03_Daily_Execution/`
    *   学情追踪与归档写入动作，精确对接至 `../03_Daily_Execution/数学间隔重复调度表.md`

### 2.3 复习调度的修复 (02_Protocols)
*   **修改文件**：`复习巩固期总调度prompt.md` 及 `复习执行协议.md`
*   **执行动作**：
    *   `活跃区`、`拖延表`、`毕业表` 的物理读写点彻底指向 `03_Daily_Execution` 层，保障第2层作为纯粹算法核心不被脏数据污染。
