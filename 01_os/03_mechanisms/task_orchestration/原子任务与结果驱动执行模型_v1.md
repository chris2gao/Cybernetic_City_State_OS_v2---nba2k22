# 原子任务与结果驱动执行模型 v1（语义规范与最小参考实现）

> 状态：Core PR #23 已合并的 G/R/A/D 语义参考实现；本文件继续作为基础语义规范。
> 范围：任务建模语义、跨模型工作习惯和一个可运行的**内存中参考执行帮助器**。不新增生产调度引擎、权限或 Workflow 阶段。
> 扩展：新的[Human 审定任务原型与执行编译候选](最小任务原型与执行编译契约_v1.md)在**首次可复用任务设计**时让 Human 逐项审核最小条件和动作，不等于每次运行/每个工具调用都重新审批。

## 0. 为什么需要

2026-11-11 NBA2K22 [Issue #40 现场事故](https://github.com/chris2gao/Cybernetic_City_State_OS_v2---nba2k22/issues/40#issuecomment-6796587612)：一次约一小时的实机研究任务完成了 16 项 Native 资格试写，但实际比赛模拟为 0，赛后采集和机制分析为 0。程序可按自身资格脚本“成功”退出，Human 的研究目标却毫无闭环产出。教训不是增加更多资格门，而是使 **业务节点的真实完成条件** 始终约束执行顺序与内部 Loop。

## 1. 最小模型

一个有意义的任务 T = (G, R, A, D)：

- **G · Goal（目标）**：Human 或上层任务期望产生的具体业务结果，而非要生成的辅助材料。
- **R · Ready（最小执行条件）**：当前节点必须具备的必要输入、真实前置依赖、运行环境与已覆盖的操作授权。条件已满足就应执行，不能预先附加“也许有用”的 SHA、Git 提交、文档与资格环节。
- **A · Action（动作）**：利用现有命令、函数、工具或组合子任务，实际生产 G 的操作；底层可有多个函数调用，不能机械地把每次工具调用变成 OS 新任务。
- **D · Done（点亮条件）**：可独立观察且可供下游使用的真实业务结果，以及与 G 相称的最小充分证据。命令退出码或某个内部测试通过只证明它本身；若 G 要求完成比赛，D 必须包含真实赛果，不能以资格试写成功替代。

**原子性的边界是“最小的业务可完成单元”，而非每个脚本、每个字节写入或具有数据库 ACID 属性的不可分割事务。** 同一个操作可包含必要的自动安全检查、Native Getter 读回、失败诊断，不把这些内容升格为新的外部流程。

### 就绪与点亮

1. 识别当前未完成的业务节点，按 R 检查 **必要条件**。已满足便执行 A；不为不相关检查阻塞。
2. 如果 R 未满足，指出具体缺项。已授权范围内的局部修复归入当前节点内部 Loop；真实安全、权限或目标边界不可绕过。
3. 执行 A，观察 D。只有 D 成立才“点亮”；局部成功、辅助完成与未知结果均不能自动点亮。
4. 进入下一个有实际业务价值的就绪节点。D 不成立时先修当前节点的实际阻塞，不无期限扩展基础设施。
5. 报告进度时优先报告 **完成的真实节点及产出**。若长期只增加文件、测试或回执而没有业务节点点亮，首先重新检查执行路线，而不是继续准备。

此处“点亮”是执行者与任务交接使用的 **语义判断**，不是新增数据库状态机、机器权限令牌、独立审核或每节点 Git 快照。

## 2. 递归组合：元素 → 执行链 → 任务 → 系统

组合任务仍采用 T = (G, R, A, D)：

- G：父任务的实际业务目标；R：父任务开始需要的最小输入、范围与授权。
- A：多个子任务的依赖关系，可以是顺序、可证实的并行或条件分支；子任务依旧使用 G/R/A/D。
- D：父任务 **独立的** 业务验收条件；不能仅以“所有子任务退出码为零”自动推定父目标已满足。

例如一轮 NBA2K22 研究是组合任务，A 包含“采集 → 干预 → 模拟 → 再采集 → 分析”。五步可以是业务原子节点；其父任务的 D 是取得足以进入下一轮分析/决策的干预后真实证据。更大的机制研究任务又由多轮研究组合而成，是否形成可信机制结论由其自身 D 判断。

一个节点之下可以继续拆分，但 **仅在结果本身独立可消费、存在真实依赖/故障隔离需要时拆分**。不要为 SHA、单独 Getter、每行日志或每次 PowerShell 命令无条件生成新节点。

## 3. 模型智能：可以优化路线，不能替代成果

Human/发送者提供保底执行链。接收模型可提出更好路线：消除多余操作、复用可靠中间数据、合并节点、改变顺序、在相互独立且获授权时并行执行。

允许采用新路线的前提：

- **保留 G 与 D**：最终目标、必要观测和验收不缩水；不以技术准备产物替代业务成果。
- **遵守 R 的必要边界**：依赖、授权、数据与目标一致性不被隐含跳过。
- **有充分、任务相关的理由**：能说明比保底路线更快、更可靠或更有信息量；不要求先建新的通用优化系统。
- **不阻断已经 Ready 的保底节点**：未经证实的优化应视作候选；既有路线可安全执行时优先产生第一份真实结果。
- **失败可定位**：如果更优路线无法维持 G/D 或产生 UNKNOWN，返回可执行的现有节点或如实报告真实 blocker，禁止盲目重放不可逆/Native动作。

改变任务目标、不可逆边界、额外 Native 操作范围或新受保护行为的“优化”不属于自主实现选择，仍按现有 Human 决策与权限处理。

## 4. 对现有 Core 机制的映射

| 已有机制 | 本模型的接入方式 | 明确不做 |
| --- | --- | --- |
| 任务包 / 跨模型交接 | 既有 `objective` 标明 G，消息 `content` / `requested_action` 说明当前执行链的首个 Ready 节点与 D；接收者恢复主次关系 | 不新增必填字段或通信层 |
| Workflow 05 步骤拆分 | 把 B/需求所要求的成果组织成有意义的节点与依赖，不能只拆成技术准备清单 | 不新增第八阶段 |
| Workflow 06 执行 | 在当前授权内，Ready 即优先执行；每个节点用真实 D 判定工作成果 | 不要求每个子任务独立 Git/Run/审核 |
| Workflow 07 测试执行 | 验证实现满足上层目标及冻结测试，不能只验证内部动作成功 | 不取代正式独立审核 |
| `evidence_driven_iteration` | Loop 服务当前未点亮节点：识别缺项 → 尝试真实动作 → 观察 D → 修复真正阻断 → 继续 | 不让 Loop 成为无关准备工作的自由队列 |
| `minimum_work_unit_output` | 继续用于正式派单、交付与审核的输出说明；与本模型的“业务原子执行”分开 | 不将每次工具调用纳入正式 MWU |
| PRMS / Git / 发布门 | 保留原有 material source mutation、发布和受保护动作边界；普通业务循环不重复制造候选源码版本 | 不取消真正需要的精确身份与安全校验 |

**优先级关系**：Human 的 G/D > 业务节点的 R/A > 对该业务必需的辅助操作 > 非必要文档、重复 SHA、流程装饰。已有安全/授权边界是约束，不能被此优先级绕开。

## 5. 最小示例：NBA2K22 一轮真实实验

| 节点 | G | R（必要） | A | D（真实结果） |
| --- | --- | --- | --- | --- |
| 采集 | 得到当前基线 | 正确世界线已加载，可读 | 执行现有采集命令 | 实际游戏基线可供本轮使用 |
| 干预 | 应用预定实验剂量 | 目标UID/字段/值域/授权满足 | 执行现有批量 Native 修改 | 实际Native读回与目标一致 |
| 模拟 | 完成计划比赛 | 正确场次待赛、模拟获授权 | 执行现有日历模拟命令 | 真实比赛结束并能定位GameID |
| 再采集 | 得到赛后变化 | 模拟产物已产生 | 执行当前适用采集命令 | 可用的赛后数据与比赛对应 |
| 分析 | 形成有效观察 | 前后数据与实验分组可关联 | 执行现有比较/统计分析 | 产生可检验观察、局限与下一轮依据 |

父任务 Done = 获得**完整的一轮**可解释实机证据；16 次资格写入、0 次模拟时，尽管干预能力可用，父任务仍未完成。

## 5a. 从原子任务语义到真正可复用的执行能力

G/R/A/D 定义了可独立观察的业务单元，但**仅凭四元素不保证 Action 已绑定可复用工具**。
当模型运行中仍需临场查询接口、生成脚本或追加假设性前置时，说明这个任务的执行原型尚未成熟。

系统级补足发生在阶段 05→06：Human 与模型共同审定每条最小 Ready/Done、必要操作、
已实现函数/脚本的版本与副作用，把原型绑定为可反复实例化的任务调用；
执行 Loop 复用已经批准的原型，而不是每次重新组织操作。
新的能力缺口停止受影响 Action，保留父 Goal 未完成并向 Human 请求局部裁决。
详细边界见[最小任务原型与执行编译契约 v1](最小任务原型与执行编译契约_v1.md)。

## 6. 第一版的边界与验证

参考运行代码是 `01_os/06_execution/task_orchestration/atomic_tasks.py`；相应可运行的七项行为回归是 `test_atomic_tasks.py`。它以可信 Python Callable 作为 Ready/Action/Done 适配器，支持顺序组合、递归组合、观察真实 Done、必要条件阻断、父任务独立完成条件与**单个 Executor 实例内**的未知副作用防自动重放；不解释 YAML/JSON 命令，不自动推断授权，不运行任意 Shell，不实施并行调度，也不跨进程保证幂等。

场景验收见 [原子任务场景验证_v1.md](原子任务场景验证_v1.md)。单元测试只验证参考代码自身行为，**没有**证明模型已经遵守指令、实际游戏链路成功、生产Workflow被替换或已获得自动运行权限。业务接入须由领域的现有Native/数据/模拟工具提供动作函数与可信读回；跨窗口重启的副作用核对仍由领域Journal承担。新的执行图调度算法或持久化状态设计需要独立的实际需求，不作为本版前置条件。
