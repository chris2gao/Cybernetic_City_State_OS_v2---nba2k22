# 工作集与归档 v1

机器契约是 `工作集与归档契约_v1.yml`。本文件说明它为什么长这样。

## 它治理可见性，不治理体积

在 `d9a18b57` 上实测三个量：

| 量 | 值 |
|---|---|
| 树里有多少内容 | 12,676,439 B / 1,781 tracked files |
| 一次完整路径枚举返回多少 | **209,761 B** |
| 启动 bootstrap 无条件读多少 | **61,534 B / 1,068 行 / 5 个文件** |

第三个量是固定的，而且**不含任何累计面**——`AGENTS.md` 第 9 条禁止 default-preload
`01_os/_runs/**`，该禁令实际生效。所以"仓库变大所以每次加载变贵"不成立，
物理搬移历史文件对默认加载的收益是 **0**。

成本落在枚举与检索：`_runs` 占枚举字节 61.2%，`_communication` 29.0%，
合计 **90.52%**。对八个"路由任务时真的会搜的词"做无过滤全树检索，
历史面命中占 **69.3%–94.0%**（`registry` 92.9%、`lifecycle` 94.0%、
`risk_tier` 93.1%）。一次无过滤检索的代价是答案所需的 3–15 倍。

完整测量见
`01_os/_runs/run-20260828-t3-archive-and-big-task-workflow-001/02_测量/`。

## 为什么不是一行 `.ignore`

把 `01_os/_runs/` 加进 `.ignore` 能一次去掉 90% 的枚举噪声。它被否决，因为它把
**噪声换成了假阴性**：搜"历史里有没有这条证据"会静默返回空，而调用者不知道自己
被过滤了。本仓已经为假阴性付过学费（`AGENT_WORKING_DISCIPLINE.md` 第 3 节：
一个被误判成学习者标识的路径片段）。

所以契约写死三条：`global_silent_exclusion: prohibited`、
`tool_must_report_excluded_counts: true`、
`filtered_result_may_claim_exhaustive: false`。
`visible_set.py --list` 每次都在 stderr 报出隐藏了多少个文件、多少字节路径文本，
并指出加宽开关是 `--include-hidden`。**过滤过的结果永远不许自称穷举。**

## 谁被隐藏：需要证明已完成，不是没有证据表明还活着

一个组只有在**被正面判定为终态**之后才隐藏。open 可见，unknown 也可见。

这一条曾经写反。早期实现把 unknown 与 terminal 一起隐藏，报出 89% 的枚举削减——
而被隐藏的恰恰是那 68 个仓库无法为其状态背书的组，收益的绝大部分正来自隐藏它们。
独立审核 T3-IR-001 判定该行为 blocking 并要求修正。

修正后的实测（当前树，`09_rebaseline/visible_set_measure_v3.json`）：

| 量 | 值 |
|---|---:|
| 一次完整枚举字节 | 216,886 |
| 默认可见 | 156,078 |
| 排除 | **60,808（28.04%）** |
| 排除中来自 communication 面 | **60,808（100%）** |
| 排除中来自本机制的终态判定 | **0** |

也就是说：**本机制目前对 `_runs` / `_dev` 的枚举削减是 0 字节**，因为终态组是 0 个。
28.04% 全部来自 communication 面，而那条策略由
`communication_system/导航与归档契约_v1.yml` 早于本机制定义，本机制只是把它工具化。
这个数字必须这样报，不能写成"本机制削减了 28%"。

可见与可归档是两个问题：unknown 在这里可见，在 `archive_group.py` 里依然不可归档，
因为归档要求逐字符命中终态枚举。两处都有 validator 漂移守卫，改回去会红。

## 为什么先做生命周期，后做搬移

`archive/` 至今是空的，不是因为缺搬移代码——communication 的 `archive_task.py`
早就在，234 行。缺的是判据。实测 50 个 run 组里：

- 32 个有 `run.yml`，18 个没有；
- `run.yml` 里出现 **24 种互不相同**的自由文本状态串，且几乎都写在 `status:` 而不是
  `lifecycle:` 下；
- 能被机器判为终态、因而可归档的：**0 个**。

`01_os/开发入口与单窗口任务规范_v1.md` 第 5 节早就声明了七个合法状态，实测无一被使用。
所以本机制的第一交付物是**生命周期分类 + 校验**，第二才是搬移能力。
顺序反过来就是在没有判据的情况下动历史，那是大扫除，不是归档。

`lifecycle.py` 因此**拒绝猜**：不在枚举里的一律 `unknown`，`unknown` 一律
`not_archivable`。宽松解析会把 24 种自由文本全部"分类"成功，然后给出一个自信的错答案。

## 归档资格的四个条件

四条全部成立才可归档，任一不可判即 fail closed：

1. `state_is_terminal` —— 字面在终态枚举里；
2. `closure_record_physically_readable` —— `run.yml` 声明一个组内相对路径，
   该文件可读、是 mapping、带 `completion_pointer` / `human_acceptance` /
   `exclusion_or_deferral` 之一。调用者给布尔值不算数；
3. `reference_safety_verified` —— 组外没有任何 tracked 文件提到该组路径；
4. `no_private_runtime_inside_group` —— 组内没有 tracked 的 `_runtime`。

`archive_group.py` **故意没有 force 开关**。契约写着未解引用 blocked、
无证据 rebinding 禁止；给一个覆盖开关等于提供一条"看起来合规地违约"的路。

## 归档不是删除

`secure_erasure_claim: false`、`deletion: false`。归档是 `os.replace` 搬移，
Git 历史仍完整可达。重复归档是成功不是错误（`already_archived: true`），
因为一个不能重跑的清理没人敢跑第二次，而半成品状态恰恰是需要重跑的。

## 本版本没有对真实历史执行迁移

搬移能力已实现且被测（正例、非终态拒绝、自由文本状态拒绝、活引用拒绝、
tracked `_runtime` 拒绝、路径逃逸拒绝、幂等），但**只在临时 Git 仓 fixture 上运行**。
对真实 `_runs` 的迁移是运营动作，需要逐 run 的引用安全证明和终态判据，
不属于产生本机制的那个任务的 objective。

## 用法

```bash
# 一个任务默认该看到什么
python 01_os/06_execution/boot/context_management/working_set/visible_set.py --list

# 历史本身就是主题时的加宽开关
python .../visible_set.py --list --include-hidden

# 枚举成本前后对照
python .../visible_set.py --measure

# 某个组现在能不能归档，为什么不能
python .../archive_group.py --repository-root . --group 01_os/_runs/<run-id> --dry-run

# 契约与代码的漂移守卫
python .../validate_working_set.py
```

## 边界

- 字节不是 token。上面所有数字都是**返回字节**，是 token 的上界代理，不是账单。
- 未测墙钟时间。本版本只测返回量，不声称 `rg` / `git grep` 的耗时是瓶颈。
- 索引不是权威：`index_is_not_authority: true`，物理树才是。
- communication 面保留它自己的归档器与契约；本文件把形状上升为通用，不替换它。
- 本机制不判断某个 run "应该"归档；它只判断某个 run 现在**能不能**归档。
