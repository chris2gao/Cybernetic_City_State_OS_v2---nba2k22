## 2. 根因是否被推翻

**没有。它保持成立，并且在这 20 个提交里略微恶化了。**

设计所依赖的命题是"仓库无法机器区分已完成的 run 与在跑的 run"。当前 master 上：

- run 组从 50 增至 53，自由文本状态串从 24 种增至 **27 种**；
- 能被机器判为终态的仍然是 **0 个**；
- communication 的 `archive/` 仍然是空的。

三个月的开发只是又添了三个各自即兴命名的状态词。因此按 rebaseline 指令的条件，
**保持现有架构，不重新设计**。

累计面占枚举 90.52% → 90.20%、隐藏 89.33% → 89.19%，属数值波动，不改变结论方向。

## 3. 一个必须自己报的反向数字

启动 bootstrap 的固定加载**变贵了**，而这是唯一每个窗口都要付的量：

| 提交 | 五个 bootstrap 文件合计字节 |
|---|---:|
| `d9a18b57`（原 base） | 61,534 |
| `6757bee2`（当前 master，不含 T3） | 68,313 |
| `d603ab60`（当前候选） | **73,879** |

其中 master 自身增长 **+6,779**（authorization simplification 与 MWU 进入常驻面），
**T3 自己贡献 +5,566**（三份常驻文档 +91 行 −1 行）。

这不是被隐藏的成本：T3 的主张是"成本在枚举与检索，不在默认加载"，而 T3 自己往默认加载
里加了 5.5 KB。以当前候选计，隐藏掉的枚举字节是 192,613，加进默认加载的是 5,566，
比值约 35:1。但**枚举不是每次都发生，bootstrap 每次都发生**，所以这两个数字不能直接相抵。
独立审核应当把"常驻面增量是否值这个价"当作一个独立判断项，不接受执行者的比值论证。
