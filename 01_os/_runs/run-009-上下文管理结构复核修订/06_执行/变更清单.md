# run-009 变更清单

## 原因

- F-02：活动 D2 决定与阶段六/boot 入口仍把 worktree 当成可启用的真访问边界。
- F-03：`CORE_MANIFEST.yml` 将已经由 core 跟踪的共享 OS run-001 至 run-008
  错分为 domain-owned run traffic。

## 修复

- 将未版本化 D2 以 Git rename 保留为 `决定_谁执行_v0.1.md`，标明 superseded；
  新建活动 `决定_谁执行_v0.2.md`，保留现有后端执行角色裁决并修正边界语义。
- 活动导航、开发设计、boot、registry、阶段六入口与 validator 只加载/引用 D2 v0.2。
- 将 `01_os/_runs/` 定义为 core-owned `os_development_run`，只保存共享
  OS/workflow/mechanism 的开发、研究、迁移与验证证据。
- 将领域业务与领域 workflow 流量固定到 domain-owned
  `.ai/PROGRAM_RUNS/<run-id>/`；两类 `_runtime/` 都忽略且不得跟踪。
- validator 新增 D2 版本、活动假边界、双 run root 所有权、runtime ignore 和
  run-001 至 run-008 历史存在性检查。

## 历史与边界

run-001 至 run-008 不移动、不删除、不重写。D2 v0.1 和 run-008 只保留历史判断与
复核链路，不作为活动加载入口。现有 DACL 证据仍只覆盖受测正常读取路径，不宣称强隔离。
