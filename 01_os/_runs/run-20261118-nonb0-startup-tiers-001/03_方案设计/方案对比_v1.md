- `repository_publisher_authority_v1.yml` 会被 PRMS `catalog.py` 的 `B0_PATHS` 和阶段协同推演的 `test_task_scope_readiness.py` 读取。它只能调层，不能改内容。

- 拆分沿用上一任务的方法：原文移动；原处保留节标题与“何时读”指针；用还原核对脚本证明与基线逐字相同。

## 3. 三个方案

### 方案 A：只调层，不改任何正文

- `TASK_CONTINUITY.md` 从启动必读改为按动作读取，触发条件是“保存或恢复任务、轮换窗口、交班时”。`prms/README.md`（1,664 字节）仍留在启动层。
- `os-publication` 的两个启动文件改为按动作读取：
  - `repository_publisher_authority_v1.yml`：commit、push、开 PR 或请求受保护动作确认之前读；
  - `.githooks/README.md`：启用守卫或 push 被守卫拒绝时读。
  - 发布相关的启动规则仍由 B0（AGENTS 的 Git Workflow、开发入口 §11 第 4 类）覆盖。
- **预计**：审核、开发、特色内容开发 ≈ 105.9 KB；规划 ≈ 113.4 KB；教学或使用 ≈ 90.2 KB（降 8–16%）。

### 方案 B（推荐）：A，再把三份大 README 拆成“启动核心 + 按动作细则”

- `task_orchestration/README.md`（11.2 → 约 4.9 KB）：
  - 留在启动层：开头概述与文件表、“原子任务”、“两条边界”、“大不等于危险”、“边界”、“测试”。
  - 四节 Human 裁决重述（原型、双模式、拒绝记录、自报，约 3 KB）与 DISCIPLINE §0.1–§0.4 内容相同，各改为一行指针；只属于本 README 的指针原样保留，例如 `reviewed_prototypes.py`、`execution_mode_gateway.py`、`execution_decision_audit.py`、`agent_self_report.py`。
  - “最小可运行参考实现”“为什么存在”“默认内部迭代与系列审核”“Development Loop evidence”四节原文移到同目录的 `README_按动作细则_v1.md`，原处保留节标题与“何时读”。
- `minimum_work_unit_output/README.md`（4.1 → 约 1.8 KB）：“What the machine checks, and what they do not prove”一节原文移到细则，触发条件是“写或校验正式 MWU 产出时”。
- `06_execution/task_discipline/README.md`（5.9 → 约 4.2 KB）：“为什么存在”是设计理由，“复核状态”是历史状态，两节原文移到细则。
- **预计**：审核、开发、特色内容开发 ≈ 95.6 KB；规划 ≈ 103 KB；教学或使用 ≈ 83.9 KB（比现在降 17–24%）。

### 方案 C：B，再对 B0 做第二轮分层

- DISCIPLINE §0.1–§0.4（原型、双模式、拒绝记录、自报，约 7.3 KB）改为按动作读取：标题与一行“何时读”留在原处，正文原文移到 `os_entry` 细则。它们的 canonical 契约 `最小任务原型与执行编译契约_v1.md` 本来就在 `os-task-orchestration` 的按动作读取里。

- **预计**：审核、开发 ≈ 84.8 KB；规划 ≈ 92.2 KB；教学或使用 ≈ 73.1 KB。
- **代价**：DISCIPLINE 与 AGENTS 是 Codex、Antigravity 不经 skill 直接读取的跨供应商常读文件。§0.1–§0.4 是 Human 定为 Core-wide 的裁决，改成按动作读后，这些供应商在启动时只能看到标题与指针。这是语义层面的取舍，需要 Human 明确决定。
