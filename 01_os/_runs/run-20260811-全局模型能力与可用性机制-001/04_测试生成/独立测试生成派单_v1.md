## 必须覆盖的测试性质

测试集至少证明以下事实，且应包含能真实失败的负例：

- 新 model-routing 是独立 `03_mechanisms` 模块，而不是把 model catalog 复制进 workflow。
- mechanism 自身可回答：职责、加载方式、磁盘依赖、failure surfacing。
- routing contract 输入至少覆盖 task/role/risk/task_shape/required_capabilities/Human availability；输出包含 model+surface+parameter profile+basis+evidence+limitations+`authority: routing_only`。
- registered candidate 默认 available，Human unavailable override 能排除、restore 能恢复；不得存在自动 quota/cost availability scorer。
- catalog 将 model 与 product surface 分开，并且 current facts 有 source/ref、verified_at、invalidation condition/confidence。
- 参数必须 surface-specific；不得把 API-only reasoning 枚举冒充 Web/Desktop 参数。
- project observation 与 vendor catalog 分离；`diagnostic`/`anecdotal` evidence 不得形成 hard qualified/unqualified route。
- 当前 evidence-backed surface/model set 至少能表达 ChatGPT Plus Web、Codex Desktop、Claude Code Desktop、Gemini Web、Antigravity，并保留 entitlement/unknown 的不确定性边界。
- `开发入口与单窗口任务规范_v1.md` §7.1 不再长期内嵌 price table / volatile model catalog，而是保留稳定 routing preflight + canonical pointer。
- §8、§9、publisher authority、T3/protected-action 等非 routing 控制不得被削弱。
- registry / boot / execution-loader pointers 与 mechanism version 一致；缺文件、断 pointer、重复 key、缺 freshness/source 字段时 validator fail closed。
- 不出现 token/cost/quota 优化、自动 fallback 链、自动 entitlement crawler 作为 routing decision primitive。
