## 跨裁决组合与工程可验证边界

### Q41=C + Q44=B：自动接管，不等于无版本检查的抢占

- 新会话**自动覆盖旧会话所有权**是Human的Q41=C选择；Q44=B仅将接管生效点限定在GitHub权威更新成功并得到验证后，不转成手动审批选项。
- 旧聊天窗口可能仍然打开；GitHub无法强制其关闭。因此严格区分“物理窗口仍在”与“唯一有效持有者/写入资格”。有效接管之后，旧会话迟到的状态更新必须判失效而不是成功。
- Q13=A/Q21=B/Q34=B与此并行约束：不能谎称不合作旧窗口的本地活动已终止；版本冲突、未知副作用不得盲目重试或强行合并。
- 需要02/03实证GitHub CAS、临时网络断线、会话有效性读回的真实保证；若原子互斥技术不能达到产品要求，应明确证据缺口和Human裁决，而不能宣称已实现。

### Q42=A + Q45=B + Q46=A：全部内容复制、目标当前状态独立、复制后各自演化

- 一次复制时，目标岗位得到源角色长期记忆的**完整内容**（包括源当前状态、历史事件、经验、检查点、索引和未完成事项），保留来源岗位/提交/时间/血缘；复制结果不能只留下源路径链接。
- Q45=B约束了复制内容的效力：源CURRENT、源待办及其他源记忆**作为来源快照**可检索；目标岗位另建立自己正式有效CURRENT及任务绑定。源岗位的旧任务授权、Human批准**不能经复制自动变成目标岗位的新授权**。
- Q46=A约束后续关系：复制成功后双方可以独立发展新的经验和状态；后来的源更正也不会无声改写目标已有副本。是否单独查询原仓库是已有Q22=C的读取自由，不等于内存自动同步。
- Q24=A岗位身份规则与Q20=B同作用域多实例依旧有效；新岗位拥有自己的实例ID，不能冒充原岗位。
- Q47=B要求复制后可验收风险报告：源版本、复制清单、完整性、stale、事实/观点/正式知识区分、岗位适用性及独立审核污染风险，**不删除或自行过滤Human要求的全部内容**。
