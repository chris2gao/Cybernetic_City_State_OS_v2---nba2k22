## 1. 结果模型口径：19种基础逻辑对象不等于19份最终存储文件

Q48=B要求逻辑对象/必填/关系/值域，允许02/03再定物理文件布局。基础v0.9列出19种逻辑记录；新增v0.10/v0.11引入记忆专题的细化对象。候选映射如下：

| 新专题对象/记录 | 对应既有对象 | 建议规范性定位 | 防止的误解 |
|---|---|---|---|
| RoleMemoryRoot | RoleInstance + RoleCurrent + Checkpoint + MemoryIndex | 角色记忆根的**聚合视图/引用根**，不增设第二个独立角色身份 | role_id及CURRENT的权威来源不能有两个 |
| SummaryCard | RoleExperience / MemoryEvent / Checkpoint的来源引用 | **新增逻辑记录类型**，为任务/主题/岗位/里程碑/交接的派生概要 | 概要不改写源事件或替代经验原件 |
| MemoryIndexManifest | MemoryIndex | **MemoryIndex的清单/代际形式**，不是另一套独立权威索引 | 版本/覆盖/水位统一 |
| IndexEntry | MemoryIndex 的组成项 | **新增可定位的索引条目结构**，可物理内嵌或分片 | 命中须能回溯item与精确source |
| RetrievalReceipt/ContextAssemblyReceipt | SearchHit、RecoveryPackage及Q49公共操作回执 | **新增审计/结果回执结构**；SearchHit仍是单个检索命中值 | 请求级覆盖、排除量、预算与权限检查不可丢失 |

由此不得机械宣称“19 + 5 = 24张表”或“最终22个持久实体”：逻辑聚合视图、内部条目、持久事件与一次操作返回的DTO不是同一种计数。01b应给出统一的“对象ID—归属—是否耐久—与现有对象关系”矩阵；最终物理数由02/03决定。

## 2. v0.10 → v0.11字段继承核销：SummaryCard（RES-018）

| v0.10含义/字段 | v0.11对应字段 | 当前审查建议 |
|---|---|---|
| summary_id、summary_kind、role_id | 同名 | 保留；五类kind：task/topic/work_role/milestone/handoff |
| scope_refs、topic_tags | task_refs、topic_refs、role_id | **补明确scope归属**：项目/工作岗位/任务及topic标签不能被隐式丢弃；可用结构化scope字段统一 |
| title、purpose、concise_digest | title、digest | title/digest保留；purpose需保留用途语义或明确纳入kind+scope |
| confirmed_facts、decisions | confirmed_fact_refs、human_decision_refs | 引用必须指向原记录；可给短摘录，但不可只给无来源自由文本 |
| assumptions、experiences | model_inference_refs | **潜在遗漏**：须能辨别假设、模型推断及经验，并查询其适用性；建议类型化条目或显式refs |
| pending_work、blockers、next_actions | open_items | 建议open_items每项带kind（pending_work/blocker/next_action）、状态与来源 |
| source_item_refs、source_commit_sha | source_item_refs、source_commit_set | 多SHA可行，但每个source_ref必须单独绑定精确commit/路径或item_id，不能只保存不对应的SHA集合 |
| origin_range、event_watermark | event_watermark、coverage_scope | 建议coverage_scope显式包含source范围、时间/事件上下界、截至水位及覆盖对象 |
| generator_kind、generator_version | generated_by、generation_version | 必须仍能区分确定性抽取/模型提炼及版本，模型推断不自动变Human决定 |
| validity、stale_reason、supersedes_ref | validity_state、stale_reason?、supersedes_ref? | 保留明确状态及条件必填的失效理由/替代引用 |
| completeness、excluded_count、gaps | coverage_scope、excluded_count | **潜在遗漏**：补coverage_state、missing/unindexed/gap说明；excluded=0不能推导“完整” |
| summary_size、estimated_tokens | estimated_tokens | 用途不同：保存可测长度/字节及估算token；真实token计量需标明计数方法 |
| created_at、refreshed_at | 同名 | 保留 |

**建议统一不变量**：只要把事项标为Human确认或已核事实，就必须有可解析的逐项原始引用及来源版本。生成摘要可以先处于candidate/unverified；有冲突要显示contested或stale，不能自动升级为正式知识。

## 3. IndexManifest / IndexEntry（RES-019）

- v0.10的 schema_version、index_generation_version、source_watermark、indexed_scope、indexed_item_count、excluded_or_unindexed_count 等，不可因v0.11换成 index_version、scope、excluded_count 而失去信息。
- **建议规范分开三种版本**：记录格式版本 schema_version、构建方法版本 generator_version、索引内容代际 index_version；其具体编码留03。
- **建议规范分开四类数量**：已索引、被默认过滤、在应覆盖范围内尚未索引、来源缺失。仅有 excluded_count + missing_ref_count 不足以判定未知的总体范围。
- IndexEntry必须有精确 item_ref/source_ref、source commit或内容哈希、角色/任务/主题/实体/时间/证据状态及可选summary_ref、copy provenance；ref无法解析时标partial/unverified。
- **范围完整性**：within_scope_complete只意味着“经校验的声明范围内完整”，不等于全仓完整。若无法可靠枚举应覆盖的源集合，状态必须unknown/partial。
- **时间语义**：固定commit上的历史证据不会仅因master向前移动就自动成为伪证；当概要/索引声明依赖“最新有效状态”而该状态变更、被Human明确更正或有效性关系发生变化时，必须重检并传播stale。历史原件仍可追溯。
- **增量语义**：event_watermark须声明作用域、已覆盖事件集合和变更发现方法；一个SHA字符串不自动等于无遗漏的单调事件序列。技术获取方式保留EVQ-019给02实证。

## 4. ContextAssemblyReceipt（RES-020）

建议让以下逻辑结果在同一请求级回执中均可表达：

- 身份与授权：request_id、role_id、task_id、authority_ref、owner_verification、effective_current_ref。
- 实际加载：mandatory_context_refs、selected_summary_refs、selected_source_refs、loaded_items、来源版本、estimated_tokens（与实际测量值分开）。
- 覆盖与缺口：indexed_scope、coverage_state、excluded_count、unindexed/missing_refs、stale_refs、freshness、next_expand_options。
- 失败状态：READY/NEED_MORE_EVIDENCE/INDEX_PARTIAL/SUMMARY_STALE/SOURCE_MISSING/AUTHORITY_UNVERIFIED/OWNER_CONFLICT/CONTEXT_BUDGET_INSUFFICIENT/NO_MATCH_WITHIN_SCOPE等可映射为统一规范值域。
- **不变量**：任一mandatory_core（身份、有效Human权限、当前任务和必要OS规范）缺失或超预算，不能通过静默裁剪回报READY；NO_MATCH_WITHIN_SCOPE不能冒充全局不存在。
- **写权限不同于读取恢复**：Human手工转交的恢复包可能足以帮助模型判断，但不能仅凭内容自动获得正式owner写入资格，仍受Q41=C/Q44=B约束。
