## RES-017 · 五层持久记忆与摘要结果

| 层次 | 具体产品结果 | 权威/加载规则 |
|---|---|---|
| L0 · Boot/岗位入口 | OS正式规范/模型与权限路由引用、role_id、task_id、当前提交与读取范围 | 总是首先加载并验证，不得被模型摘要覆盖 |
| L1 · Role CURRENT | 简短有效状态：角色、当前目标、已确认结论、未完成工作、阻塞、最后有效检查点、主题索引入口、freshness | 角色接任时默认加载；不得堆积历史聊天 |
| L2 · 导航/概要 | 主题索引、任务索引、按时间/实体的目录，以及任务级/主题级/岗位级概要卡 | 先读索引或摘要，默认不读全部原文 |
| L3 · 源记录 | 追加式事件、决策、经验、handoff、关键产物、正式证据及其版本 | 按命中引用、疑问或审计要求精确展开 |
| L4 · 检索/审计材料 | 完整历史、归档、冲突/失败证据、详细外部来源 | 需要取证或历史分析时扩展，始终可追溯；非默认注入 |

**说明**：L0的OS规范原件、L1的正式CURRENT、L3的来源记录和L4的耐久审计各自具有既定权威属性；分层表示默认读取顺序，**不是把所有事实降级为一张索引的授权层级**。L2概要/索引是导航派生物，不能改写来源事实或替代Human决定。

## RES-018 · 概要卡（SummaryCard）逻辑字段全集候选

| 字段 | 要求 | 含义 |
|---|---|---|
| summary_id / summary_kind | 必填 | task、topic、work_role、milestone、handoff五类候选 |
| role_id / scope_refs / topic_tags | 必填 | 岗位主体及归属，防止跨项目串线 |
| title / purpose / concise_digest | 必填 | 检索导语与高密度概要，而非全文聊天转写 |
| confirmed_facts / decisions | 必填，允许空集合 | 分别列已核事实、Human确认；不能混成模型观点 |
| assumptions / experiences | 必填，允许空集合 | 明确未证假设、角色见解与经验适用条件 |
| pending_work / blockers / next_actions | 必填，允许空集合 | 当前任务或岗位后续需要处理的事项 |
| source_item_refs / source_commit_sha | 必填 | 至少能追到原记录、版本和证据；无来源不得称已证实 |
| origin_range / event_watermark | 必填 | 本摘要覆盖什么时间/事件区间、哪里开始未覆盖 |
| generator_kind / generator_version | 必填 | 确定性提取或模型生成、方法版本；声明提炼方式 |
| created_at / refreshed_at | 必填 | 创建与最近刷新时间 |
| validity / stale_reason / supersedes_ref | 必填（后两项条件必填） | current、stale、contested、superseded、unknown |
| completeness / excluded_count / gaps | 必填 | 哪些范围已索引、未检到、未覆盖；不能误报穷举 |
| summary_size / estimated_tokens | 逻辑必填、数值待测 | 作为上下文预算输入，不是事实可信度指标 |

**候选合成层次**：事件证据→任务/里程碑摘要→主题摘要→岗位概要。每一层保存来源清单与版本；上层概要不能只引用下层文本而失去追溯原始事件的路径。候选摘要若由AI提炼，应有“尚未核证”标记，不能自动发布为正式共识。

## 保存与更新触发

1. **确定性先行**：在任务启动、关键里程碑、已确认的外部结果、任务结束，保存真实事件和checkpoint；确认写入GitHub可读回后才发布CURRENT（Q16/Q23/Q31）。
2. **概要按需更新**：当相关事件新增、Human裁决改变、主题出现重要反证、摘要覆盖率/事件watermark落后、任务结束或接任时需要，生成或修订关联摘要；不要求每句聊天都调用模型。
3. **增量而非全量压缩**：新事件只影响相关任务/主题索引和上级概要；不因某一事件每次重算全部角色历史。更改来源SHA、反证、模板版本时标记旧摘要stale，必要时从原事件重算。
4. **先候选后正式有效**：自动或模型生成摘要可先staged。校验来源可解析、事实/观点分离、覆盖范围、冲突、无误导性Human批准后，发布索引版本和新的CURRENT指针；失败留旧有效版本并登记EVQ。
5. **全量复制不等于共享CURRENT**：按Q42/Q45/Q46完整复制源长期记忆及摘要/索引的有版本快照，目标创建自己的CURRENT；复制后源/目标索引分别演化，风险报告保留stale与审核污染标记。

## 不得违反的现有OS规范

- 现有context_management三平面与固定入口是本机制的上位导航基础，不能由概要直接代替其boot授权、哈希验证与正式handoff。
- 现有工作集契约拒绝全局静默排除、索引不权威、过滤后不能声称穷举；摘要/索引同样必须报告覆盖范围和排除量。
- GitHub Markdown/JSON权威存储；可按需使用本地瞬时排序/倒排缓存辅助检索，但缓存不是第二个权威记忆库，失效必须重建且不可覆写GitHub。
- Q22=C同仓库角色可读取全部内容，由模型自行选择查看哪些；**默认加载选择不是技术权限隔离**。不能据此保证Q10=B独立审核无污染，须公开残余风险。
