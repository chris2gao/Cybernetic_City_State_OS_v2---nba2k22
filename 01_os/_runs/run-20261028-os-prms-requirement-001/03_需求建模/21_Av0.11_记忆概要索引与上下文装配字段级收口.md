# OS-PRMS A-v0.11 · 记忆概要、索引与上下文装配字段级收口

状态：01b结果需求审查稿；非物理JSON/YAML格式、非已实现程序。依据Q1–Q51、RES-017–020与Human最新索引/概要/按需加载优先指令。所有`!`为逻辑必填（允许空数组须明示），`?`为有条件选填。

## 一、保存结构与来源链

### R17-1 · RoleMemoryRoot（记忆根）
`role_id!`、`work_slot_ref!`、`project_scope_ref!`、`template_version_ref!`、`published_current_ref!`、`latest_valid_checkpoint_ref!`、`index_manifest_ref!`、`source_commit_sha!`、`updated_at!`、`status!`。

- 同一项目同一模板可有不同role_id（Q20=B），身份随OS岗位（Q24=A），不随GPT/Codex/窗口。
- GitHub Markdown/JSON是唯一耐久权威；索引和摘要是有版本的派生信息，**不是**替代事实的权威来源。
- CURRENT应精简，保存本岗位已确认有效状态、工作任务/阻塞、版本/索引指针，不堆积所有历史事件。

### R18-1 · SummaryCard（五类可组合概要）
`summary_id!`、`summary_kind!`、`role_id!`、`task_refs!`、`topic_refs!`、`title!`、`digest!`、`confirmed_fact_refs!`、`human_decision_refs!`、`model_inference_refs!`、`open_items!`、`source_item_refs!`、`source_commit_set!`、`event_watermark!`、`coverage_scope!`、`excluded_count!`、`generated_by!`、`generation_version!`、`created_at!`、`refreshed_at!`、`validity_state!`、`stale_reason?`、`supersedes_ref?`、`estimated_tokens!`。

- `summary_kind`候选值：`task`、`topic`、`work_role`、`milestone`、`handoff`。
- `validity_state`：`candidate`、`current`、`stale`、`contested`、`superseded`、`unknown`。
- `coverage_scope`必须有明确范围和水位；`excluded_count`可为0但不可不报告。**未穷举的摘要不应声称完整覆盖**。
- 模型推论不能写作Human批准。每个概要至少能通过来源引用最终定位到原始事件/文件及其版本；不能只链接其他概要、遗失原文证据。

### R19-1 · MemoryIndexManifest / IndexEntry
Manifest：`index_id!`、`role_id!`、`index_version!`、`source_commit_sha!`、`scope!`、`event_watermark!`、`indexed_item_count!`、`excluded_count!`、`missing_ref_count!`、`generated_at!`、`status!`、`supersedes_ref?`。
Entry：`item_ref!`、`item_type!`、`role_id!`、`task_refs!`、`topic_refs!`、`entity_refs!`、`time_range!`、`validity_state!`、`evidence_refs!`、`source_sha!`、`summary_ref?`、`copy_provenance_ref?`。

- 索引维度：岗位、任务、主题、实体/产物、时间、证据状态、经验/决策、全量复制血缘；索引命中必须能回到**精确来源**。
- `status`：`candidate`、`complete`、`partial`、`stale`、`rebuilding`、`unverified`。失效/部分覆盖不是“无结果”。
- 历史扫描与默认检索必须各有明确scope；不会因工作集过滤而静默消失；支持显式加宽到全部历史。

### R20-1 · RetrievalReceipt / ContextAssemblyReceipt
`request_id!`、`role_id!`、`task_id!`、`query_or_intent!`、`authority_ref!`、`current_commit_sha!`、`selected_source_refs!`、`selected_summary_refs!`、`mandatory_context_refs!`、`loaded_items!`、`indexed_scope!`、`excluded_count!`、`missing_refs!`、`stale_refs!`、`estimated_tokens!`、`budget_ref!`、`coverage_state!`、`context_status!`、`next_expand_options!`、`created_at!`。

- `coverage_state`：`within_scope_complete`、`filtered`、`partial`、`unknown`；filtered/partial不能声称全局穷举。
- `context_status`：`ready`、`need_evidence`、`source_missing`、`summary_stale`、`index_partial`、`authority_unverified`、`owner_conflict`、`budget_insufficient`。
- `mandatory_context_refs`包含正式角色/任务身份与权限、OS强制规则、有效CURRENT；**预算不足只报阻断，不静默删除强制信息**。

## 二、跨对象关系与完整性

`RoleMemoryRoot → 1:1 有效CURRENT`；`RoleMemoryRoot → 1:N SummaryCard / MemoryIndexManifest / MemoryEvent`；`SummaryCard → N:M 原始事件/证据`；`IndexEntry → 1个精确source item和可选SummaryCard`；`ContextAssemblyReceipt → N:M 已加载原件/概要`，必须带每项SHA。

写入顺序的需求：原始事件/检查点**先保存并验证** → 相关摘要/索引形成候选并校验 → 发布有效CURRENT/索引入口 → 新会话只从已发布版本恢复（Q31=B）。任何失败保留上一有效CURRENT；候选摘要不是事实。

## 三、跨岗位全量复制与模型上下文分离

Q42=A的`copy_all`复制源角色**完整长期内容**，包括SUMMARY、INDEX与原始事件；目标CURRENT独立（Q45=B），复制后双方独立演化（Q46=A），风险报告保留过期/争议/审核污染标记（Q47=B）。**按需加载只决定本轮输入哪些信息，不得以省token为由减少应复制的持久记录。**
