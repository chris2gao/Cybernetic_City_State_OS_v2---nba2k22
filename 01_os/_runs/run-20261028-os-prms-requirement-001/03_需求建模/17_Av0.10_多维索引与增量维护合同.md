## RES-019 · MemoryIndexSet（可检索、可扩展、可核验）

OS每个工作岗位至少具备下列逻辑索引视图，GitHub Markdown/JSON记忆内容与版本为唯一持久权威；具体是否拆成多个物理文件由03设计B决定。

| 索引 | 主键/查询维度 | 使用示例 |
|---|---|---|
| 岗位身份目录 | role_id、project_id、work_slot、template_version | 选择正确OS架构师，而非误接其他窗口或岗位 |
| 当前任务目录 | task_id、stage、status、pending_decisions、dependency_refs | 接任进行中的开发规划，先定位任务CURRENT |
| 主题/机制目录 | topic_id、tags、mechanism、domain、status | 查OS上下文管理/REA、游戏数据机制相关经验 |
| 实体/产物目录 | entity_ref、file/path、repo、commit_sha、role_id | 根据一个PR/需求文档定位相关历史事件和证据 |
| 时间/里程碑目录 | occurred_at、season?、milestone、event_range、recorded_at | 查询某阶段或去年某轮审核经历；此处season不是游戏内人格绑定 |
| 证据有效性目录 | verified、stale、contested、missing、source_freshness | 找正式已证结论，或专门搜索过时/冲突记录 |
| 经验/决策目录 | experience_id、decision_ref、applicability、supersedes | 检索“同类问题过去怎么解决”及适用条件 |
| 跨岗位来源目录 | source_role_id、copy_manifest_id、source_commit_sha | 全量复制后还原源岗位和版本，并与目标CURRENT区分 |

索引应当**检索到准确定位符**：`record_ref`、`record_type`、`role_id`、`task_id`、`topic_ids`、`time_range`、`status`、`source_commit`、`evidence_refs`、`summary_ref`。绝不只生成无法追踪来源的一段自由文本。

## 逻辑IndexManifest字段

- **必填**：`index_id`、`role_id`、`schema_version`、`source_commit_sha`、`index_generation_version`、`generated_at`、`source_watermark`、`indexed_item_count`、`indexed_scope`、`excluded_or_unindexed_count`、`status`。
- **按需必填**：`missing_source_refs`、`stale_due_to_refs`、`rebuild_required`、`superseded_index_ref`、`copied_from_manifest_ref`。
- 结果项包含`item_ref`、`item_type`、`source_sha`、`time`、`topic_ids`、`summary_ref`、`validity_state`；确切编码留给03。
- 候选状态：`complete`、`partial`、`stale`、`rebuilding`、`unverified`。不得因为部分索引返回空结果就宣称仓库没有记录。

## 索引维护与失效传播

1. **源事件追加**：确定性提取新事件/任务元数据/已确认决定（含源SHA），写入staged事件；标记影响的任务、主题与角色相关索引分区。
2. **增量更新**：以watermark只处理新增/变化引用，维护对应posting/导航摘要；不得因新一次checkpoint无条件重扫所有历史。
3. **版本校验**：发布前验证每个命中记录存在、commit/sha一致、无重复ID冲突、关键来源可追到Human原件或工程回执。无从确认时索引`partial/unverified`而非`complete`。
4. **失效传导**：源内容/版本变更→对应索引条目stale→引用其摘要stale→CURRENT的summary pointers需提示可能不再有效；旧历史仍可追溯。
5. **正式发布**：先候选索引、来源校验，再经GitHub提交与读回验证发布新的索引指针。部分失败保留上一有效入口，登记缺口。
6. **恢复/重建**：丢失或过期索引可从GitHub权威事件/文件重建；重建前相关检索显式返回`index_stale`或`coverage_incomplete`，不得以旧缓存作为新事实。
7. **全量复制**：Q42=A要求复制源索引及对应记忆内容本体；Q45=B要求目标岗位重新建立自己的有效CURRENT与索引入口；Q46=A之后两边增量索引独立演化。

## 两种检索路径

- **准确定位优先**：任务ID、角色ID、文件/commit、Human决议ID、事件ID已知时先走精确索引，不必运行模型推测主题。
- **语义/主题检索按需**：自然语言任务描述→候选关键词/概念/实体→查主题目录及证据状态→需要时再做模型语义重排序。语义判断是辅助排序，**不是一个新的权威持久事实源**；不需要先选定向量数据库。
- **扩展与穷举**：默认可见性可以隐藏已终态累计面以省成本，但检索必须报告排除数量、索引覆盖范围和加宽路径；当用户询问“全部历史”或检索结果不足，提供显式full-scope扩展，不发生静默假阴性。

## 与已有OS机制的精确继承

现有`context_management/工作集与归档契约_v1.yml`已经约束：`global_silent_exclusion: prohibited`、`tool_must_report_excluded_counts: true`、`filtered_result_may_claim_exhaustive: false`、`index_is_not_authority: true`；本机制在角色记忆索引上继承这些不变量。不把新索引复制覆盖已有工作集索引，也不改动现有communication任务导航索引的所有权。

现有工作集测量明确把**默认启动加载量**、**全树枚举字节**、**无过滤检索噪声**分开报告。本索引的性能验收也必须分别测量三类开销，不以“压缩CURRENT”这一指标代替检索质量。
