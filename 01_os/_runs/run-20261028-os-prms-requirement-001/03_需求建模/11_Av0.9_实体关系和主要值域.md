# OS-PRMS A-v0.9 逻辑关系、值域和约束（草案）

上位裁决为A0 Q1–Q19与01b Q20–Q51，字段细则是候选结果模型，非实际GitHub Schema、非运行通过证据。

## 主要关系和基数

| 来源 | 基数 | 目标 | 约束 |
|---|---|---|---|
| RoleDefinition | 1:N | RoleInstance | 同项目同模板可创建多个实例(Q20=B) |
| RoleInstance | 1:N | RoleAssignment | 权限绑定任务，不能从旧任务自动继承 |
| RoleInstance | 1:0..1 | 有效SessionOwner | 自动接管(Q41=C)且读回确认后生效(Q44=B) |
| RoleInstance | 1:1 | 有效RoleCurrent | 角色长期身份跟OS工作岗位(Q24=A) |
| RoleInstance | 1:N | MemoryEvent、Checkpoint、Experience | 事件和经验与CURRENT分离(Q26=B) |
| RoleExperience | N:M | MemoryEvent | 观点可被反证，保留来源与原记录 |
| SharedKnowledge | N:M | RoleExperience、Evidence | 查看经验与正式发布知识不同(Q30=B) |
| FullCopyManifest | 1:N | CopiedMemoryItem | 真实全量内容复制(Q42=A)，不是只有链接 |
| FullCopyManifest | 1:1 | CopyRiskReport | 保留完整性、stale、审核风险(Q47=B) |
| FullCopyManifest | 1:2 | 源/目标RoleInstance | 目标新ID及独立CURRENT(Q45=B)，复制后独立演化(Q46=A) |
| ValidationCase | N:M | Human决定、RES、EVQ | 全部裁决可反向映射到测试(Q50=B) |

## 候选主要值域

- 角色生命周期：`exists`、`deleted`。历史不因删除活动入口而消失。
- 事件声明：`fact`、`human_decision`、`model_opinion`、`hypothesis`、`external_result`。
- 事件结果：`pending`、`succeeded`、`failed`、`unknown`、`corrected`。
- 经验有效性：`current`、`stale`、`contested`、`superseded`、`unknown`。
- 检查点触发：`task_start`、`milestone`、`confirmed_external_result`、`task_end`、`best_effort_interrupt`。
- 发布有效性：`staged`、`verified`、`published`、`invalid`；仅published可成为权威CURRENT。
- 会话所有权：`pending`、`verified`、`stale`、`conflict`、`unverified`；不承诺能物理关闭窗口。
- 全量复制：`pending`、`verified_complete`、`partial`、`failed`、`unknown`，缺失内容不能宣称完成。
- 验收：`not_run`、`passed`、`failed`、`blocked`、`evidence_missing`；本阶段不产生实测通过结论。

## 必须满足的不变量

1. 一角色实例最多只有一个GitHub权威已验证所有权版本；旧会话的迟到写入不得发布为CURRENT。GitHub CAS实际保证留EVQ。
2. CURRENT必须引用最后完整且已验证发布的检查点；候选记录部分写入不能提升为当前状态。
3. 历史和反证通过追加事件处理，原事件不可悄悄覆盖。
4. 全量复制后目标岗位有效CURRENT独立；源CURRENT及旧待办作为完整来源快照可查，不继承源任务授权。
5. 同仓库角色可读取全部记忆(Q22=C)，不能宣称技术性隔离保证独立审核(Q10=B)。
6. 规划阶段不声称已经有运行时服务；核心规划升级按Q35=C/Q36=B在03设计确认后进行，并遵守适用发布门。

待02/03核实的项目包括唯一ID格式、值域与OS既有Schema兼容性、GitHub多文件提交原子性、来源SHA/大数据复制成本。
