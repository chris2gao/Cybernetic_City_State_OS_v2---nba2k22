# OS-PRMS A-v0.11 · 概要/索引/按需加载操作与异常状态收口

**需求候选，不是已存在API或已执行测试。** 本文把RES-017–020的操作结果定义到可验收层级，并继承Q49=B成功/拒绝/冲突/未知/部分失败规则。

## 操作与结果

| 操作ID | 逻辑输入 | 成功时可观察输出 | 必须处理的失败及不变量 |
|---|---|---|---|
| OP-17 `record_durable_event` | event_id、role_id、task_id、source_SHA、事实类别、结果、idempotency_key | 追加事件与checkpoint引用、GitHub验证回执 | 重复键内容相同=已应用；冲突不覆写；不确定结果=unknown |
| OP-18 `refresh_summaries` | role_id、changed_source_refs、event_watermark、expected_summary_version | 仅受影响task/topic/milestone/role概要候选、来源清单、覆盖率、stale与更新回执 | 来源找不到→SOURCE_MISSING；AI推论不成为已证事实；发布失败留旧有效概要 |
| OP-19 `update_memory_index` | index_scope、changed_items、expected_index_version、source_commit | 精确索引条目、指向文件/事件的SHA、覆盖范围、excluded_count与新版本 | 缺项→INDEX_PARTIAL；依赖SHA变化→INDEX_STALE；结果为空须注明查询范围 |
| OP-20A `search_memory` | role/task/scope、query、filters、cursor、limit、include_history | 有序结果，每项包含summary、原件定位符、SHA、有效性、来源；含next_cursor与覆盖回执 | 被过滤/索引缺失不得宣称穷举；默认命中为空≠历史无数据 |
| OP-20B `expand_memory` | summary_id/source_ref、detail_level、expected_source_SHA | 下一级概要或具体原件/事实证据、来源与消耗 | 旧SHA→STALE；目标缺失→SOURCE_MISSING；无权限的**当前操作**不得被历史记忆授权 |
| OP-20C `build_context` | role、任务、运行面、预算、任务意图、已确认CURRENT版本 | 必备OS规则与权限、CURRENT、相关概要、证据引用、缺口与加载receipt | CONTEXT_BUDGET_INSUFFICIENT时不能静默省略必备规则；GitHub无法验证时不得伪称最新 |
| OP-20D `create_recovery_package` | role_id、task、最新有效CURRENT和checkpoint | 标准可交接恢复包、source commit、进度、未决、证据、stale与读取状态 | Human转交不自动拥有写权限；自动接管仍须Q41=C/Q44=B的GitHub验证 |

## 可观察的状态转换（只约束结果，不锁物理实现）

- 事件：`candidate → verified → durable`；冲突或未知按Q7/Q11登记证据，不篡改旧事实。
- 概要：`candidate → source_verified → published_current`；依赖变化→`stale`，产生新版本并以`supersedes`关联旧概要；失效记录不能直接返回为现行结论。
- 索引：`candidate → verified_complete → published`；缺源→`partial`、SHA差异→`stale`、重建中→`rebuilding`；重建不能覆盖原始事件。
- 上下文：`prepared → authority_verified → ready`；缺强制规则/所有权/来源→`blocked_or_unverified`；按需扩展是新读取，不自动改变长期事实。
- 所有状态只有在仓库可读回且满足Q31=B完整性门后才可声称“有效发布”；多文件GitHub事务是否可原子实现为02/03证据缺口。

## 三个用户可检视的输入输出例子

### 示例A · 新GPT接任OS架构师岗位

输入：`role_id=os_architect_A`、`task_id=prms_01b`、`intent=continue_requirements`、预算与源commit。输出：角色身份/当前任务/Human已确认裁决索引/未决事项/来源版本，按需加载与PRMS有关的TopicSummary；**不默认加入其他开发历史全文**。

### 示例B · Codex准备NBA2K22外挂工程任务

输入：`role_id=2k_external_dev_planner`、`intent=coach_settings_integration`（仅假设测试）；输出四个导航条目：OS工作机制总览、REA经验、游戏资料目录、现有设计；先短概要，随后展开有关训练/轮换/战术的原文及当前PR/commit。目录缺失须标明待补，不可杜撰索引已存在。

### 示例C · 历史概要过期

输入：`source_ref=decision_A`、`expected_SHA=old`，GitHub来源已更新。输出：`SUMMARY_STALE`+当前源版本+关联摘要列表+重新验证建议；不默认让模型重复旧观点，也不自动覆写已确认的历史决定。

## 需由Human审查的边界

- 对Q22=C，允许模型自主查看统一仓库，不把“默认不注入”误报为角色级技术读隔离；独立审核残余风险维持。
- 对Q42=A，记忆**保存和跨岗位全量复制**仍然复制原内容，本次按需加载策略不得缩减持久复制范围。
- 对Q43=B，预算阈值、检索相关性和召回标准02测量、03经Human确认；本文件不虚构token数量。
- 所有例子均为未来目标的可观察结果，不代表本次已经执行。
