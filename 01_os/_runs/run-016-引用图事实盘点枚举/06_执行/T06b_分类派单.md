## 必须完成

### 1. 六类分类，逐条落到 CSV 行

对 `path_references.csv` 的每一行给出分类：

| 类 | 含义 |
| :--- | :--- |
| `normative_definition` | 规定"必须如此"的定义 |
| `observed_instance` | 系统中真实存在的实例 |
| `explanatory_example` | 为说明规则而写的示例 |
| `template_placeholder` | 模板占位符 |
| `run_fixture` | 某次 run 的测试夹具 |
| `unresolved_hypothesis` | 尚未裁定 |

**输出为 CSV，逐行对应，不得聚合。**

### 2. 裁定那 1 条悬疑项

```
01_os/_dev/MECHANISM_2_信息挖掘方法论_v0.1.md
  引用自 01_os/01_workflow/02_信息收集与提炼/依据材料/人机对话沟通实现记录.md:46
```

判它属于历史记录（同 `claude与人类的开发对话日志.md` 那 8 条），还是真实断链。
**给出判据，不要只给结论。**

### 3. 覆盖 T06a 发现的新 ID 空间

`source_id`(75) / `evidence_id`(23) / `research_question_ids`(23) /
`original_source`(53) / `shared_origin`(23) / `location`(73)。

回答：这些 ID 的**唯一性范围**是什么——文件内、artifact 内、run 内、还是仓库全局？
`original_source` 与 `shared_origin` 的语义关系是什么？
**每条结论要指向 CSV 行或精确 path:line。**

### 4. confirmed 与 suspected 分开

一条失败只有在**同时**满足下列四项时才算 `confirmed`：

- 存在真实实例（不是示例、不是模板）
- 存在适用的规则
- 二者共享同一 scope
- 检索路径可复放

不满足即 `suspected`，并写明缺哪一项。

### 5. fixture readiness

对 T08 将要实现的 validator，标出哪些行可直接作为 valid / invalid fixture，
哪些不能，以及为什么。
