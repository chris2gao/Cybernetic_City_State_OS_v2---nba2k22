# check-jsonschema 准入验证矩阵

## 校准对象

`fixtures/run_manifest.schema.json` 是本轮专用的 JSON Schema 2020-12 机器契约，
缩小表示一个 OS run manifest。它包含：

- 六个必填字段；
- string、boolean、array、object；
- `const`、`enum`、`pattern`；
- `additionalProperties: false`；
- 嵌套 outputs 与 checks 对象。

它不替代 workflow 中的 Markdown schema，不验证跨文件引用、路径存在性、语义
真实性、证据质量或业务合理性。

## CLI cases

| ID | 输入/行为 | 期望 |
|---|---|---|
| P-YAML-COLD | 合法 YAML，新建 CLI 进程 | exit 0，`ok -- validation done` |
| P-JSON | 合法 JSON | exit 0 |
| P-METASCHEMA | 校准 schema 自检 | exit 0 |
| R-YAML-1..5 | 同一 YAML 连续五次 | 退出码和 stdout/stderr 完全一致 |
| N-MISSING-REQUIRED | 缺 `status` | exit 1，定位 required property |
| N-WRONG-TYPE | boolean 写成 string | exit 1，定位 `human_gate` |
| N-INVALID-ENUM | `status: done` | exit 1，定位 enum |
| N-EXTRA-PROPERTY | 顶层多余字段 | exit 1，定位 additional property |
| N-NESTED-ERROR | nested array 写成 string | exit 1，定位嵌套路径 |
| N-SCHEMA-SYNTAX | schema JSON 损坏 | exit 1，parse 诊断 |
| N-SCHEMA-METASCHEMA | schema keyword 类型非法 | exit 1，metaschema 诊断 |
| N-SCHEMA-MISSING | schema 文件不存在 | exit 1，明确 FileNotFoundError |
| N-INSTANCE-MISSING | instance 不存在 | exit 1，不得静默通过 |
| N-INSTANCE-SYNTAX | instance YAML 损坏 | exit 1，parse 诊断 |
| B-UNICODE-SPACE-PATH | instance 路径含中文和空格 | exit 0 |

“冷”仅指没有常驻工具进程、重新创建一个 CLI 进程；安装探测已经访问过 executable，
因此 OS 文件缓存是否完全冷不可观察。

## Wrapper cases

| ID | 行为 | 期望 |
|---|---|---|
| W-SUCCESS | PATH 解析工具、合法实例 | exit 0，转发 stdout |
| W-VALIDATION-FAILURE | 非法 enum | 保留底层 exit 1 与诊断 |
| W-EXPLICIT-EXECUTABLE | caller 显式传 executable | exit 0；wrapper 不硬编码 |
| W-WINDOWS-POWERSHELL | Windows PowerShell 5.1 调用 wrapper | exit 0 |
| W-MISSING-SCHEMA | 本地 schema 缺失 | wrapper exit 66，CLI 不启动 |
| W-MISSING-INSTANCE | 本地 instance 缺失 | wrapper exit 66，CLI 不启动 |
| W-REMOTE-SCHEMA-REJECTED | URL 作为 schema 参数 | exit 66；只接受本地文件 |
| W-TOOL-UNAVAILABLE | 子进程 PATH 移除工具目录 | exit 69；不回退模型判断 |

以上是候选提交原有的 27 项矩阵，修复任务必须原样保留并继续通过。

## 网络引用闭包与版本边界扩展

canonical v1 的 schema 输入面收紧为：

- schema 必须是本地 `.json` 文件并通过严格 UTF-8 JSON 解析；
- `$ref`、`$dynamicRef`、`$recursiveRef` 必须是 string，且只能是
  `#...` fragment-only 引用；
- `$id` 和 legacy `id` 不得是 HTTP(S) URI；
- 标准 `$schema` URI 继续允许；
- 相对路径、绝对路径及 HTTP(S) 外部引用均在 CLI 验证前以 exit 65 拒绝。

| ID | 输入/行为 | 期望 |
|---|---|---|
| CJV-FRAGMENT-REF | schema 内部 fragment 引用 | exit 0；证明 `$schema` URI 与本地 fragment 可用 |
| CJV-HTTPS-REF | HTTPS `$ref` | exit 65；validation sentinel 不出现 |
| CJV-HTTP-DYNAMIC-REF | HTTP `$dynamicRef` | exit 65；validation sentinel 不出现 |
| CJV-HTTPS-RECURSIVE-REF | HTTPS `$recursiveRef` | exit 65；validation sentinel 不出现 |
| CJV-RELATIVE-REF | 相对外部 `$ref` | exit 65；validation sentinel 不出现 |
| CJV-HTTPS-ID | HTTPS `$id` | exit 65；validation sentinel 不出现 |
| CJV-HTTP-LEGACY-ID | HTTP legacy `id` | exit 65；validation sentinel 不出现 |
| CJV-NONSTRING-REF | 非 string `$ref` | exit 65；validation sentinel 不出现 |
| CJV-YAML-SCHEMA | `.yaml` schema | exit 65；validation sentinel 不出现 |
| CJV-DAMAGED-JSON | 损坏的 JSON schema | exit 65；validation sentinel 不出现 |
| CJV-REAL-VERSION | 真实 executable 报告 0.37.4 | 版本门通过，随后执行 validation |
| CJV-FAKE-VERSION | executable 报告 9.9.9 | exit 78；validation sentinel 不出现 |
| CJV-CORRUPT-VERSION | `--version` 输出不可解析 | exit 78；validation sentinel 不出现 |
| CJV-PROBE-FAILURE | `--version` 本身失败 | exit 78；validation sentinel 不出现 |

另以 `M-VERSION-PROBE` 和 `M-SCHEMA-PREFLIGHT` 分别测量两个新增门禁；
wrapper 总耗时与底层 CLI 验证仍单独测量。所有拒绝案例都以独立 fake executable
sentinel 证明底层 validation 没有启动。

## 观测与准入

- 每例保存命令、参数、时间戳、退出码、stdout/stderr、UTF-8 字节数、耗时和
  诊断匹配结果。
- 进程峰值仅在 launched process 可读时记录；进程树峰值不可见则写
  `not_observable`。
- 没有进行网络抓包，网络行为仍写
  `not_observable_no_packet_capture`。本轮证明的是 canonical wrapper 的
  schema 引用面在启动 validation 前被机械闭合；直接调用上游 CLI 仍可能使用其
  remote-schema 能力，不得据此宣称上游包“零联网”。
- 全部 case、registry、boot、canonical path、结构 validator 和 pytest 回归通过
  后，状态才可写为 `verified_on_demand`。
