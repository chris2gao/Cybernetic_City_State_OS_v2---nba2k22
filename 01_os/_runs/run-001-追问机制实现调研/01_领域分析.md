# 步骤 1 · 领域分析

| 领域 | 为什么相关 |
| :--- | :--- |
| **AI 编程工具工程实践** | `spec-kit`、BMAD 等的 clarify 流程就在这里，且它们是**在真实使用中被打磨过的**，不是论文原型 |
| **需求工程（学术）** | 需求诱导的停止条件、本体驱动追问、评测基准（ReqElicitBench）都在这个领域 |
| **结构化数据交换 / schema 设计** | 产出形态要能被下游消费，这是 schema 设计问题，不是需求工程问题 |
| **类型系统与约束求解** | "schema 在约束下填满"要机械判定，本质是**约束满足**——这个领域有现成答案 |
| **对话系统 / 槽位填充** | 追问的经典形式是 slot filling，语音助手时代已经工程化过一轮，有踩过的坑 |

---

## 一处调整

原本想加"认知科学 / grounding 理论"。**这一轮不加。**

理由是步骤 0 定的目标：本次挖的是**第一版能不能实现**，不是**停止条件的最终判据**。
grounding 理论属于后者，而后者已经被明确列为"要自己造的"、且与阶段二的
停止条件问题合并研究。**这一轮挖它，产出不会改变"三段拼装可行/不可行"的判断。**

这是 EIG 判据在**开挖前**的一次应用——不只是用来决定何时停，也用来决定何时不开始。

## 第五个领域是新加的

**对话系统 / 槽位填充**在 T1 两份报告里都没出现——两份都聚焦"LLM 时代的需求诱导"，
而槽位填充在语音助手时代（Alexa/Siri/Rasa）已经被大规模工程化过。

那一代解决的正是"追问到什么时候算填完"，且是在**没有大模型可以偷懒**的约束下解决的。
这可能是本次最有价值的方向，也可能完全过时——**未知，这正是要挖的原因。**
