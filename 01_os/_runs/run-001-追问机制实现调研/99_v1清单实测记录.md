# v1 执行清单 · 实测记录

**跑到派单为止（步骤 0–3）的实测。** 这是本次运行的主要产物之一——
规格在跑之前只是纸面自洽。

---

## 一、结构问题：工作流实例没有位置

`01_workflow/` 现在装的是**阶段机制定义**（01–07）。
`WORKFLOW_MECHANISM_v0.1.md` 写的实例布局是 `01_workflow/<workflow-id>/`，
**两者会混在一起**——和之前设计稿占据实现目录是同一个错误。

**本次处置**：实例放 `01_os/_runs/<run-id>/`。

**待定**：`_runs/` 是否该进注册表、是否该保留、保留多久。
按"中间产物不注册不保留"的原则它该删；
但一次完整运行是**方法论的实测证据**，删了下次还得重跑。这两条冲突，需要裁决。

## 二、步骤 0 的第二问真的改变了行为

「什么信息会让我们相信它**不能**实现」——写完这一问后，
派单里多了一整类要求：**主动找剥离失败的记录、槽位填充踩过的坑、基准跑不起来的抱怨。**

不写这一问，派单会变成"请告诉我 clarify 怎么用"，**回来的全是成功案例**。

**这一条按原样保留，它是有效的。**

## 三、EIG 判据可以在开挖前用

原规格只把 EIG 当停止判据。实测发现它也能**决定某个领域要不要开始挖**：

"认知科学 / grounding 理论"本来在领域清单里，被我砍掉，理由是——
本轮目标是"第一版能不能实现"，而 grounding 属于"停止条件的最终判据"，
**挖它不会改变本轮的判断**。

→ 建议写进规格：**EIG 既用于何时停，也用于何时不开始。**

## 四、两轴分级救回了一类源

"踩坑讨论"可靠性 C、可信度 2，**合成一个分数会被筛掉**。
但它是**唯一系统性存在失败案例的地方**，而步骤 0 的第二问只能从这里得到答案。

官方文档与论文天然只报成功。**两轴分开的价值在这里第一次实测显现。**

## 五、模板缺一个字段：术语壁垒

约束求解领域与需求追问领域**几乎没有共同检索词**——
不是因为无关，是**两个领域的人不读对方的论文**。

这是一种检索限制，但不是"索引偏向"也不是"返回上限"，模板里没有它的位置。
它需要**人工搭桥**（手工提供跨领域检索词），不是搜索技巧能解决的。

→ 模板加字段：`术语壁垒: "<需人工搭桥的说明>"`

## 六、重合度算不了，只能将就

规格要求"同时报告新增与重合"。但**本次只有两路并行**，没有第三方能比对，
双方各自不知道对方找到了什么——**要求它们报重合，它们无从报起**。

本次将就做法：要求双方标注"哪些是显而易见的"，用显而易见项当重合的粗代理。

**这是错的，只是没有更好的办法。** 正确做法是双方都报完整清单，由合并方做交集——
也就是说，**重合度必须由第三方计算，不能要求被测方自报。**

→ 这条要改进规格：并行的要求不是"报重合"，而是"报完整清单"，重合由合并方算。
