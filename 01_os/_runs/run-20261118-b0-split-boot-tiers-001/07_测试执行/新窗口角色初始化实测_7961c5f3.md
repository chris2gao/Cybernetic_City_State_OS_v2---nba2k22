## 差异与缺口（供发起会话写进 run 记录时参考）

1. **skill 的加载源不是工作树。** 在 worktree 会话里，Claude Code 从主 checkout（`E:\workspace\...`）加载项目 skill，而 skill 正文中的相对路径（`../citystate-os/SKILL.md`）和命令都以"与本文件同级目录"或仓库根为基准。本次两边一致，所以没有影响。如果主 checkout 落后或超前于工作树，角色 skill 的正文和它指向的文件可能来自不同的提交。
2. **"实际加载"有两种方式。** 角色 skill 是通过 Skill 工具加载的；机制 skill 是由角色 skill 指示、直接读文件加载的。宿主层的 skill 调用记录里只会出现 `role-reviewer` 一项。
3. **超出要求的操作（AGENT_SELF_REPORT）：** 我额外做了基线 0b935671 的字节对比，只读，用来回应"启动读取量比原来少"这条完成标准。没有任何写入。
