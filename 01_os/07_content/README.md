# 07_content

The city-state supplies a workflow and the capacity to work. This is where that
capacity is pointed at something specific: information bases, source material, and the
results a workflow produces.

## Holds

- information bases the workflow draws on
- domain-specific material for whatever is being built
- generated results

## Does not hold

Workflow machinery. If it would still be needed after switching to an entirely
different subject, it belongs in `01_workflow/` or `03_mechanisms/`.

## The boundary that has already been paid for once

The first-generation system put a mathematics-teaching production pipeline inside
`06_Silicon_Index/`, a directory that was declared shared at the time because it then
held the bootstrap every instance started from. The justification was true of those
bootstrap documents and false of the twenty-one pipeline files sitting beside them. By
the time it was measured, roughly a third of the repository's tracked files were
teaching material living in a repository that describes itself as the common core.

That directory no longer holds a bootstrap and is not part of the active OS: startup
is `AGENT_WORKING_DISCIPLINE.md`, `AGENTS.md`, the current task and this OS entry, and
`06_Silicon_Index/` is legacy awaiting retirement. The lesson outlived the structure,
which is why it is written here in the past tense rather than deleted.

Content and capability separate cleanly at the start and never cleanly afterwards.
That is what this directory is for.

## Ownership

Content is domain property. When this system supports more than one domain, `07_content`
is the boundary along which they split — so its ownership declaration matters more than
most, and should be settled before anything substantial lands here.

Empty until the first domain content arrives.
