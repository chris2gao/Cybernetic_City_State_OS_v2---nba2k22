## Working command and behavior

`python cli.py refresh-world PID SAVE_DIRECTORY LOADED_FILENAME NEW_OUTPUT_DIRECTORY [--families FAMILY ...]` runs the default thirteen sources in dependency order: schedule/player context, organization, market, planning/training, settings, player contracts/base badges, player state, affiliations, skills, news/transactions, records, honor stats and league history/awards. An explicit subset supports selective follow-up after a partial batch. Output directories must be new. Nothing installs a scheduler or advances the game.

The controller checks the operator-declared save binding and current schema before starting. Before and after every source, it reopens the explicit PID read-only, checks process creation FILETIME, module/PE build, resolves current native roots and reads the game-season year. A process restart/PID reuse, build change, year change or binding change stops subsequent sources. The controller never reuses dynamic addresses from a prior process or source step. The operator filename declaration remains the save identity contract; process controls do not replace it.

Source adapters preserve their existing in-process LIVE_READ acquisition receipts and independently atomic SQLite units. Returned success strings are matched against committed units with the exact source, grade and native year. Annual skips are also matched to the existing same-save/game-year annual ledger; they retain their original observation time. A completed batch means the requested adapters completed or had a verified annual skip. It does not convert each partial Native source into complete coverage or create one global point-in-time snapshot.

`refresh-report.json` is an owner operational receipt with code hashes, source plan, individual units/counts, source outcomes and selective rerun families. Raw API/context files stay owner-only. A failure stops pending sources, preserves earlier committed units and exits2 through the CLI. Until a unit receipt is verified, the report retains `UNKNOWN_UNTIL_RECEIPT_VERIFIED`: an adapter can commit before a later reporting error, so the controller never claims a rollback it did not perform. Failure after a verified commit retains that receipt and marks the failed context check separately. There is no automatic retry, deletion or history rewrite.
