# Gemini REA 单字段 Loop · 主执行任务

**只执行本任务**；已有Gemini V2/V3集成工程分支的返工仍暂缓另行处理。优先从精确共享字段队列第一个 `TENDENCY_NATIVE_001` 开始，每轮只有一个 field_id 和一个具体问题。

本任务研究原生机制及必要的有界RE专用实验工具：字段身份、偏移及消费者、合法值域、GAME/3D/Calendar条件、和教练设置/球员倾向的实际交互假说。用既有REA文档、源代码及安全只读证据，**不能因为内存存在一个byte就判定它影响某行为**。

## 单字段循环
1. 读取一个队列字段和已有局部证据，记录本轮只验证什么。
2. REA静态定位/Native getter检查；只能以有来源的原始offset、dump、函数或文档SHA证明定位。
3. 当字段真实原生效果需要改值时，先为测试存档形成动作/权限/回滚申请；没有当前具体授权**不要对进程、存档或内存做写入、启动或提权**。
4. 允许的实验每轮只改变一个字段与一个目标值，原值和其他环境因素受控，且技术读回/消费证据和竞技效果分开记录。没有能力则标`UNKNOWN`。
5. 记录结果、反例、当前缺口、下次需要的单项改善；完成一轮后移动到队列下一字段，不被一个无法验证的字段拖住。
6. 首轮遍历全部种子字段，然后根据失败集收缩/证据等级按价值继续第二轮、第三轮，不以固定迭代次数停；连续使用同一方法仍无新证据的字段跳过，真正需要Human授权时停止对应动作并回传。

不要把V2的12个spec或V3未经核对的阈值作为真正Native能力。两次审核皆REWORK_REQUIRED。完整字段效果证明和已确认外部参考将由最终集中GPT独立核对，不自行认证。

本任务初次交付目标是逐字段的技术来源与真实UNKNOWN列表，并至少验证可重复的静态REA研究流程；未经实机授权，不能承诺实际写入达成率。所有记录在本Run，允许的研究代码限于独立`src/vae_rea_research`与`tests/vae_rea_research`；既有REA核心只读复用，不进行扩边写入。
