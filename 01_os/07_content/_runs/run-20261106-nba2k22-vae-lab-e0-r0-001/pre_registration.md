# W0 calibration and WP Shot Tendency screening

- W0 CONTROL has no interventions. W0-A and W0-B come from the same frozen original before either is advanced. Human controls loading, simulation and any capture authorization. The two paths require distinct disk save identities, WorldData DB identities and worldline identifiers. Verify common source SHA plus observable schedule, roster, settings, current field values and calendar. Preserve the source and all old WorldData.
- Freeze the scheduled Native game IDs before simulation. Use Calendar Sim only. Each manual run covers `[Today, Today + 7 days)` with the same start and stop convention. If the observed start is 2021-12-21, the historical proposal stops at Today 2021-12-28 and expects the 44 verified scheduled opportunities from the retained snapshot. Recompute if the actual start differs. Stop on drift, an unplanned game, mode conflict or missing source coverage. Capture authorization is separate.
- Compare exact paired games by Native ID and played date, score and canonical player box fingerprints from each run's verified full unit. The comparator rejects shared identities, mismatched starts, wrong mode, out-of-window results, and even matched pairs that both omit a predeclared game. Two matching outcomes mean matching on this pair only. If variability is detected, propose at least four independent W0 repetitions and report paired difference distributions. An assignment seed does not control the game's RNG.
- WP is an offline screening proposal. Restrict to one SHOT_TENDENCY target per team with three distinct teams. The deterministic seed is `E0-SHOT-TENDENCY-WP-V1-20261106`. Match on position and six-minute opportunity band, then choose among feasible triples by baseline shot and minutes gaps, breaking ties deterministically. Assign H/L/C by seeded hash order. H/L/C are baseline +5 / -5 / unchanged. No clipping and no cohort substitution after outcomes. Use the exact local assignment file for the historical proposal. Recompute and review on a verified W0 before any downstream authorization. WC/WI remain design-only.
- Primary metric is the predeclared ratio of sums `36 * sum(FGA) / sum(minutes)` over valid, positive-minute appearances in a seven-day window. For each assigned player compare its WP rate to its own matched W0 rate in paired games; report H minus L and the C change separately. Missing or zero minutes yield an unavailable rate, not a zero. Secondary metrics are FGA, same-unit team shot share, and teammate FGA spillover. Report missed opportunities, minutes changes and attrition by arm. No native touches count is inferred.
- Label both sides of every affected matchup and every teammate of a treated player. Report direct treated-opponent exposure and stratify or withhold unexposed contrasts as applicable. Use the game/team cluster and worldline repeat as units of dependence. The first H/L/C screen has one player per arm and no confirmatory p-value, power claim or causal promotion. After independent replication, predeclare paired cluster/worldline uncertainty intervals and BH FDR across secondary or multi-field families before looking at outcomes. Compare strata only when opportunity counts and replication support them.
- S4's historical setter receipt concerns a running memory field. This protocol does not establish save persistence, gameplay causality or authorization. Gate WP on verified W0 isolation, baseline/stability and Human review. An exact write batch and its authorization would be a separate task boundary.
