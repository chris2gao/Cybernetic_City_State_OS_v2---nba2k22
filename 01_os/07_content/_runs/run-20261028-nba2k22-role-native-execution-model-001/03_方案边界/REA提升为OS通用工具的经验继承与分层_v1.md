# REA 工具经验提升为 Cybernetic City-State OS 通用能力：规划记录 v1

**状态**：`PROPOSED_FOR_OS_TOOL_GOVERNANCE`，仅任务规划；当前未修改OS全局Skill/执行器/安全配置，没有授权新游戏实机操作。

## 为什么要提升

用户已经通过 NBA2K22 的原生教练参数Apply、直接原生交易Process和既有球探Goal修改，获得了“模型明确输入 → 游戏原生函数 → 游戏状态真实变化”的具体实机证明。REA对本任务的工程价值不再局限于只读内存取证，更包括从静态/动态证据恢复真实业务函数接口并有界调用。

## 通用层与项目专用层必须分离

### OS通用的REA研究/执行方法

- REA适配能力、二进制构建与版本指纹检查、静态可调用候选的证据记录。
- Frida/类似载体在恰当的进程权限下进行短时可恢复的有界观察；内存页可读性/对象身份证据与域假设检查区分。
- ABI、this指针、线程/GUI状态、函数生命周期、参数封装、函数指纹、调用前后读回。
- 明确交付`NOT_EXECUTED/EXECUTED_UNVERIFIED/EFFECT_VERIFIED/REJECTED/UNKNOWN`，不能用Fixture替代真实对象。
- 单次未知事务禁止盲目重放，保留实际执行与原始请求。正式执行遵守Human授权场景。
- 预算/超时控制，避免旧NBA2K22整包Ghidra分析重复长时间失败；优先局部证据和原生引用。

### 不允许误升格成OS全局默认值的项目绑定

- NBA2K22的RVA、POE枚举、STAFF布局、1668字节交易提案结构、球探目标槽、Windows游戏管理员进程及该EXE专有签名。
- 当前游戏世界线的业务权限、原生交易是否走FullCheck、是否跳过经营合法性、某个球队/球员UID等。
- 针对PC22当前构建的`NativeActionRegistry`、`read_catalog`和角色策略，不适用于别的游戏或一般系统。

## 建议的OS工具化交付层次

1. **REA工具适配说明**：如何发现工具、权限、REA调用API、文件或进程边界和错误/超时处理。
2. **Native研究标准证据合同**：函数定位、版本、结构、调用参数、证据成熟度与缺口，不嵌入NBA2K22字节。
3. **有限实验操作规范**：可读性/异常隔离、单调用/读回、状态未知不重试、人类准入与审计，不升级为自动修改许可。
4. **项目Profile**：例如NBA2K22单独提供Native ID/函数ABI/结构、角色能力与实际游戏业务协议。
5. **经验文档引用**：用户报告Codex已撰写下一任务可载入的REA开发经验交接；但现已按Human指定源`b7e0f51...`取得完整交接文档并在PR #18中逐字保存，blob`4cc0b2c487315cc26bd6f25419e0afea63f94ddc`。通用经验可从该文件提取；当前并未修改OS Core Skill或为其它项目安装工具。。

## 与本轮任务的关系

本轮先完成游戏功能范围与原生执行需求建模；后续Codex接到完整结果模型时加载REA经验文档，并按照现有工具Skill分层设计。不能因为REA已被证明可行，就先随意开启新游戏测试或直接修改全局OS工具注册。
