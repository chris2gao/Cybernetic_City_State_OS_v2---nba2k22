## 二、对后续物理 B 的六项重点审查——只提交“有证差集”

1. **真实字段全集与物理DDL**：以`schema.sql/field_dictionary.json`逐列差集为主。某字段有来源且现有typed列足够：复用；字段根本缺、单位/粒度/关系不兼容：生成最小Schema变更候选；仅未到场景：标`PENDING_SCENE`，不要预填值/偏移。
2. **常规赛与季后赛定稿**：比较S4/S6 Native期段语义、`season_finalizations`按season唯一和`*_season_totals_final_once`触发器；未证前不提前总体封季或自称已有软件故障。如需分期段闭合方案，先列出受影响真实字段/历史键/查询和迁移边界。
3. **身份与暂时性对象**：S7 prospect模板、draft结果与S8新PLAYER不得仅凭姓名/槽号合并；staff/pool/market是否可以聘任或签约必须靠实际Native状态证据。换季旧Unit不能伪成新鲜来源。
4. **来源和显示的分层**：原始Native值、已证UI显示值、有版本的转换候选、有效缓存标志、权限/隐藏数据严格分别存/输出；REA Overall代表了“值已实读但UI映射尚不全”的真实案例。没有授权就不复算游戏自带Overall或高级统计。
5. **单源原子历史与CRUD/Native I/O**：`capture_unit`确保同一个source的自洽，不把多个时间不同家族读数伪称同一瞬时状态。对Native新采的所有执行目标须`execution_id → fresh_capture_batch → typed事实 → expected/actual逐字段关系对账`，`already_refreshed`和沿用旧unit不可验收。
6. **容量与部署**：一档一库、历史追加和100赛季复用已批准；真实完成一整季的样本、每季20–40次采集、各来源池实际对象数/一次容量、索引热点与留存/备份成本需要量测；不把线性投影当真实百季PASS。

## 四、阶段02的候选判断与**不可省略的阶段门**

能停止的：在没有新游戏场景前，对未知Native日期/池/字段的无目标重复GitHub静态调查。继续猜测即使“找到更多摘要”，也不能替代真实来源证据。

不能停止的：正式阶段02证据包的剩余权威源分级、反证/边界记录/来源使用、对主要RQ与已批准RES的完整映射，以及高影响可行性条件的精确说明；要符合OS `02_信息收集与提炼/实现/证据包schema_v1.md`及独立性约束。阶段03原型候选可以先备，但正式03门不能从这份“候选”自动打开。

**建议进入Human阶段门讨论的触发条件**：当正式证据包/可行性判断具备足够条件，要决定按`partially_supported`带明确未来S2–S8实证保留进入03，还是因某个**具体阻断性架构问题**先做有界验证。提问要给真实具体承重分歧、证据等级、方案差异及推荐，不反复追问已批准A/ADR。现在不存在需要Human立即回答的原型语义选择。
