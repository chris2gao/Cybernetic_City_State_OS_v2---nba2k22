## 5. 缺口处理分类与优先级

| 代码 | 裁定规则 | 下游动作 |
|---|---|---|
| `REUSE_STRUCTURE` | v25现有表/Reader明确匹配所需业务逻辑，保留具体来源引用 | 仅做有边界的场景实证与必要查询核对 |
| `NEEDS_EVIDENCE` | 结构存在、历史记录有限；游戏值域/身份/最终性或场景时机未证 | RQ-02证据任务，尚不派开发 |
| `CONFIRMED_DELTA` | 发现具体目标容器/字段缺失且已有可靠反证排除v25能力 | 进入03设计B的明确增量事项；未达到本分类门槛前不填 |
| `NOT_YET_GENERATED` | 有真实游戏场景证明该数据此时未生成 | 记时机与依据，下一窗口验证；不能把场景名当证据 |
| `NONCORE_EXCEPTION_PENDING` | Human明确指定可延期的非核心容器 | 逐个记录批准引用；无明确批准不标PASS |
| `BLOCKED_PERMISSION` | 只有真实Windows/Native/写入才可取得的证据且本次未授权 | 保留证据空缺与授权请求；不启动执行 |
