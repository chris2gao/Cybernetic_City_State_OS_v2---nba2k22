**来源**：2026-10-30 Human 直接要求VAE原型必须包含：(1) GM、教练、球员可对NBA2K22原生系统完成真实操作；(2) 每类操作有可解释、有来源、可验证、能持续更新的机制方法论和设置联动知识；(3) 真实采集、分析及按角色分发的决策信息服务。Human明确允许规划Gemini通过REA探索原生机制；权限仍按OS动作门禁确认。

**重要变更**：旧候选 `c2d9caae388bac3ae5e586c69ee0bd2116ba473b` 是离线/模拟执行流水线，21个自报通过的fixture单测不证明任何游戏原生修改、三角色原生执行、完整采集或竞赛效果；**不得将其作为新目标的完整验收候选**。保留旧 completion_pointer 作为前一基线/迭代记录，不删除或改写历史证据。

## 必须交付的三层原型

### 1. 真正的原生操作能力（不是只会给出提案）
GM：预算与工资帽/奢侈税/合同逐年计算；名单和人员管理；交易；签约/续约/裁员；选秀和选秀权。
教练：教练/球队攻防体系、ACE/POE/Playbook/Freelance；轮换/时间/角色；团队及个人训练。
球员：属性成长、潜力与训练机制；倾向/PlayTypes；徽章种类/等级/触发成长；个人训练和导师机制。

必须区分**原生引擎自然成长**、**允许角色通过游戏内机制干预**、**仅世界维护者能直接修改的属性/徽章**。角色拥有“理解”和“提出调整建议”，不等于有权限任意写能力值。每项动作均需`Action → Preconditions → Authority → Native/UI Path → Before → Execution → Readback → History/Failure`，详见矩阵。

### 2. 可持续学习的原生机制方法论
建立字段级`Mechanism Knowledge Registry`和`Interaction Graph`，至少记录：用途/受影响行为、取值域及生效时机、关联设置和冲突、证据等级、预期主指标/副作用、可证伪假设、当前游戏验证状态。任何REA探索/静态Getter发现均不得把相关性说成已证因果。对每次真实修改按已批准的`Trial`冻结原值、假设、比较群与测量窗口，收集赛后或后续训练/经济结果，产生 CONFIRMED/REFUTED/INCONCLUSIVE/NO_CHANGE；结果连同失败追加到知识库，更新方法版本。未知项保持UNKNOWN。

### 3. 面向三独立角色的信息闭环
基于既有D2 Reader/D3采集与原生Getter，制作可复用`Capture → Validate → Historical Ledger → Deterministic Analysis → Role Information Views`。GM只拿与经营/工资/合同/交易/选秀有关的获准数据集；教练拿球队/对手/轮换/体能/训练/比赛数据；球员拿自身成长/倾向/徽章/训练及权限允许的数据。输入需save、season、object ID、capture time、freshness、来源与权限，UNKNOWN不得填0，不覆盖历史事件；决策与效果验证依靠同口径数据。

## 单一Loop、统一审核、不碎片化
Gemini继续当前同一任务和任务分支，按`识别未证操作或机制 → REA/Reader可授权探索 → 更新Action×Method×Data矩阵 → 实现适配/方法论 → 局部验证 → 追加实证与缺口 → 下一轮`迭代。无固定迭代轮数；受支持的局部代码改进不反复询问Human。对新验收要求建立覆盖矩阵；原离线结果作为第一轮基础，不计为实机操作PASS。

**作用于已有任务的正式修订**：本新增材料与矩阵优先于旧任务包中“只需离线首个E1纵向原型即可交付完成候选”的表述；不授权扩大代码写路径和游戏写入权限。需要改旧Reader/REA或通过有副作用的Native入口测试时，形成一次清晰的路径/动作/存档/回滚授权需求，不自行扩权。

**集中审查**：所有能力族、机制方法论、数据服务三个维度共同达到可审核状态后，只生成**一个冻结的集成候选和一个正式独立GPT审核任务**。若权限或不可达到的未知阻挡，提供有界`PARTIAL/BLOCKED`与实测边界，不宣布产品原型完成。

## 现阶段可继续事项
在不触碰受保护动作前可集中完成：原有REA能力清点与接口适配、原生动作清单、静态/已有真实证据读回、训练与成长相关机制表、机读方法论及关系图、三个角色的确定性数据视图、失败/缺失验证、离线测试和安全批准申请准备。

**须停下取得实际授权**：启动或提权游戏/进程附加、未授权内存/Native写入、存档变更/重新加载、真人比赛推进、增加允许路径、关键新语义改变；同一类别有界测试可打包一次Human确认。不要把“允许REA探索机制”误读为所有写操作已获批。

**交接要求**：恢复当前任务最新状态，检查当前分支干净并同步远端后应用本修订。新任务不另立，不自行覆盖旧completion_pointer历史；本轮真正完成后更新其阶段身份并发布新指针。执行者的实际模型须保留来源。
