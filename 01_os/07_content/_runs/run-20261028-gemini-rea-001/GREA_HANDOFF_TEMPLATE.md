## G. Codex审阅工单（不可跳过）

- 审阅基线（PR19最新实际HEAD，而非Gemini旧猜测）：
- 是否重演静态原始字节/ABI：
- 是否有同名函数误识别、UI字符串/Native回调张冠李戴：
- 是否能在默认无game transport下安全离线运行：
- 是否修改/污染现有Registry/正式源或权限：
- 是否真正实现单个目标业务效果而没有额外副作用：
- 是否影响现有多角色批次/资源锁/未知不重放纪律：
- 需要的最小实机验证场景（仅列出，不自动执行）：
- 审阅结论：`ACCEPT_SELECTED_PATCHES` / `REQUEST_REPAIR` / `RESEARCH_ONLY` / `REJECT`。
- Codex在正式工程接收时才修改其项目索引和生产状态；Gemini不得自行把实验标记成正式完成。

**验收策略**：Gemini即使遇到Native缺口，只要提交有限范围、明确排除、可复现来源，仍可能有价值；只有有足够ABI/对象/业务效果的候选才值得Codex移植。未证则不合并。
