# W03-00 Delivery Handoff: Wave-02 Evidence Credibility Audit & Commit Pipeline

## 1. 核心目标
响应 Codex 接收基线与 Wave-03 总体要求，对 Wave-02 中取得的 18 项个人防守位段假说、Playbook 68 槽分区假说及 Gameplan/Playbook 真实提交刷新链进行严格自纠与反证复核，区分“硬性二进制证据”与“业务推断”，并恢复游戏原版真实提交流水线。

## 2. 证据自纠与降级核定
1. **18 项个人防守位段 (W02-B)**:
   - **硬性二进制事实**:
     - Word 1（偏移 `+0x4`）默认值为 `0x00280000`（指令 `0x1465285: mov dword ptr [rax+4], 0x280000`）。
     - Word 2（偏移 `+0x8`）低 11 位有效，其余高位被清零（指令 `0x146527e: and dword ptr [rax+8], 0xfffff800`）。
     - 复制为整条 12 字节更新（指令 `0x14652c0`：一条 8 字节 `mov` + 一条 4 字节 `mov`）。
   - **自纠修正与推断降级**:
     - 游戏中不存在针对单个字段的微型 Setter（如单独修改 `on_ball_pressure` 2 位的独立函数）。
     - 18 个字段的具体名称与位排序（如 bits 0..2 为 on_ball_pressure）属于结合 UI 菜单顺序的“工程编解码约定”，而非经过独立单字段反汇编验证的符号。
     - 12 字节更新由 2 条硬件指令完成，在多线程环境下非硬件单条原子写入。

2. **Playbook 68 槽 (W02-C)**:
   - **硬性二进制事实**:
     - 战术书数据结构大小为 360 字节（`0x168`），战术槽从偏移 `+0x58` 开始。
     - 原版战术上限为 68 槽（`0x44`），由 `0x7aa584: cmp eax, 0x44` 严格限定。
     - 战术书已分配数量由 `0x149ae80` 统一获取（调用 `0x141017910` 获取管理器并读取偏移 `+0x7fc`）。
   - **自纠修正与推断降级**:
     - 战术循环仅检查整体上限 68，并未在汇编层出现 4 个分区的硬编码边界。30/20/10/8 的四分区是游戏战术界面 UI 与规则设计上的槽位划分逻辑。

3. **Gameplan 原版提交流水线全链证实**:
   - 之前 GREA-01 将 `0x131f110` 误认为唯一提交点，W02-A 降级其为默认计划刷新。
   - 本次回查完整追踪了原版 UI 提交流水线（位于函数 `0x7a7840` 内）：
     - `0x7a7aab: mov word ptr [rbx], 1`：在内存中的 Gameplan 对象首字写入 1，标识自定义/激活状态。
     - `0x7a7ab0: mov dword ptr [r15 + 4], 1`：设置 UI Dirty 脏标志。
     - 随后检查活动比赛状态（`call 0x1414c2070`），若正在比赛或后台模拟，将 880 字节战术数据打包复制到栈中，并调用 `0x1414af790`。
     - `0x1414af790` 将任务分发给后台作业调度器（调用 `0x1414c1060`，事件哈希 `0xf7ba8674`）。
   - **关键结论**: 纯内存数据写入立即生效于 Gameplan 结构，而 `0x1414af790` 是向比赛运行引擎分发后台异步同步通知。
