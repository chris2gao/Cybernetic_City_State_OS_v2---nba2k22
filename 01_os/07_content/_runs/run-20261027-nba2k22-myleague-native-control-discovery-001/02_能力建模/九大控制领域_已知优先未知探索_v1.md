### 角色与权限分工

- **GM 模型**：选交易球员/签权、签约球员及条款、选秀人选和签位、**选球探考察目标**；Codex不做GM估值、配薪搜索、自动选新秀或自动球探优先级排名。
- **Coach 模型**：指定防守、进攻、Playbook、战术槽位、轮换、球队与个人训练参数；Codex只把参数送到对应Native业务函数。
- **Player模型或获授权管理角色**：提供玩家属性、倾向、徽章、训练等业务目标；对哪些原版可以直接更新/哪些必须经过自然成长需要保留真实性标识。
- **NBA2K22原生服务**：已有校验可照常调用；拒绝就返回`REJECTED_BY_GAME`，**不要因为失败由Codex自行更换GM资产或战术决定**。

## 二、球探功能的最小接口原型（本轮不执行）

### A. 查看本届选秀候选名单和现有资料

```text
gm.scouting.list_prospects(draft_year_or_current_class)
 -> [{prospect_id, name, position, currently_visible_fields, scouting_progress_if_available}]
gm.scouting.get_prospect_report(prospect_id, team_id)
 -> {known_fields, unknown_or_unscouted_fields, reported_on_if_available, evidence_source}
```

这里的字段名是**外部统一接口目标**，不宣称PC22原生已有同名字段或函数。把候选人列表可见、球探报告已解锁、底层隐藏真实球员值三个概念分开。

### B. 安排球探按GM决定的球员进行考察

```text
gm.scouting.assign_targets(team_id, [prospect_id_1, prospect_id_2, ...])
 -> original_game_assignment_plan_or_native_call_candidate
gm.scouting.get_assignment_status(team_id)
 -> pending / scheduled / completed / unavailable / unknown
```

需要Codex寻找原版考察任务的`Assign/Confirm/Update`及数据关联。如果2K22实际机制要求等待赛季日期推进后报告逐步解锁，那么控制系统只能**按原生周期执行任务并随后读取报告**，不应把“安排球探”包装成“瞬间获得全部候选真实潜力”。

本届选秀名单可能由下载/自定义Draft Class更改，因此`prospect_id`需与当次League存档和届次关联，不应仅依靠姓名。

### C. 从次世代资料借鉴，但不偷换PC22函数真实性

PC22 MyLEAGUE`Scouting > Prospect Scouting`页面已在NBA2K22公开资料中描述；历史MyLEAGUE用户与开发人员讨论说明球探任务可能通过定期弹出的分配界面而非页面直接单击完成。此为**找入口的线索**，不是当前PC22 Native 调用证据。Codex本轮可只读静态查相关Scout/Prospect/Draft Class对象、日期事件、任务分派/报告更新函数，下一轮再测试。

## 三、交付原则与防止浪费算力

1. **已经真实打通的先接接口**：教练防守Apply、1对1球员交易；不重试、补返回收据或Save/Reload。
2. **已发现原生函数的先补调用合同**：例如训练/选秀静态候选，但不把未证ABI猜成实测能力。
3. **未知领域继续探索**：球员4战术类型、教练战术替换和手册、员工属性、球队配置、球探分派与报告等，不因只在界面看到就直接标Native已恢复。
4. **读与写均需能力目录**：第8类是读取全集，不能只列Writer；球探第9类既有读取又有主动管理行为，不能被数据读取或选秀大会吞并。
5. **本轮没有任何新测试**：不启动真实进程、不Hook、不做新原生调用、也不跑新模拟/Fixture测试；只发现机制、实现调用接口与静态规格，留待下一独立测试任务。
6. **不要创造不存在的“必须集齐某数字才算完成”**：9类为Human确认的大领域，46个当前细分行为只作为第一版目录；Codex发现更多时可有证据地增加，先完成确知能力的接口再逐项补未知。
