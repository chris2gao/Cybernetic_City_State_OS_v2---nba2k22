# NBA2K22 REA · 阶段03 B0-v3 双轨成果模型审查与执行路由准则

**状态**：候选，不等于Human对完整结果B的精确版本批准。**Human新约束**：`03_Human机制主体边界裁决_AI与AI优先_20261027.md`及`03_Human最终目标补充_机制知识与双执行路径_20261027.md`。**候选B主文件**：`NBA2K22_REA_03_B0_结果模型_v3_AI机制知识与双后端候选.yml`。原始A0与A两个已批准Blob保持不变；本版是后继Human新指令的目标细化。

## 1. 我们要得到的不是一个反编译报告，而是一套“理解+执行”共用的真值约束

```text
REA: 游戏原生AI逻辑、字段布局、函数引用、数据转换与真实行为
  ├── 机制知识层：可验证的规则解释 + 字段语义 + 角色知识卡
  │       ├── GM AI：游戏交易规则、AI谈判/评估/执行、工资合同选秀权等
  │       ├── Coach AI：战术/POE/训练的游戏原生含义、适用时机与实际后果
  │       └── Player AI：自然徽章成长、能力/倾向/训练与游戏状态联系
  └── 行为语义层：带AI身份、条件和权限的类型化决策指令
          ├── 具备真实AI原生调用条件并可授权验证 → NATIVE_FUNCTION
          ├── 原生调用不适用，但字段/依赖/缓存/后果与写后读回经验证
          │      → VALIDATED_MEMORY_WRITE
          └── 两种都未具备必要证据 → NO_SAFE_PATH（不写、不误报成功）
                            ↓
               统一新鲜Game读回 + 关联状态对账 + 来源/失败记录
```

**核心规定**：AI外部人格形成`DomainActionIntent`而不是输入RVA/Frida内存地址；执行适配层对两种后端使用**相同游戏行为语义**、业务前置/后置条件、状态一致性与权限门。逆向得出的原生字段即便不能直接调用函数，也能帮助AI合理决策并帮助工程Owner正确映射内存Writer。

## 2. 每张机制知识卡应回答“是什么、为什么、怎样影响游戏”

| 必需字段 | 内容要求 | 禁止偷换 |
|---|---|---|
| `AI_actor/mode/build` | 当前为哪类AI球员/AI教练/AI GM、哪个PC22离线MyLEAGUE存档/构建、场景适用 | 不能以Human控制玩家或次世代MyNBA逻辑冒充 |
| `GameRule` | 原版在什么条件下如何处理，具体来源与可观察证据，未证部分标UNKNOWN | 攻略假说不能当Native确定公式 |
| `FieldMeaning` | 字段原生身份/所属、单位/值域、UI解释、在引擎里何时被消费、作用条件 | 内存值改变不等于行为实际生效 |
| `DecisionReason` | AI为什么可以选择该战术/训练/交易，在哪种状态不适用，何时需Human或必须禁止 | 不把人格推理结论混成底层游戏真值 |
| `ActionSemantics` | 类型化命令、输入、预期业务变化、受影响对象、不变量和可选执行路径 | AI不能直接拼Native地址或绕开业务条件 |
| `EvidenceAndGaps` | 函数/来源/观察指纹、证明级别、最新有效时点、反例与未知项 | 同一Codex Run多文件不充独立实机证据 |
| `RoleVisibility` | 某知识是否批准GM、Coach、Player查看与使用 | 隐藏Native原始字段不能默认泄露 |

## 3. 同一个Action的执行资格矩阵

| Native原生AI函数 | 实时写入语义与一致性 | 结果 |
|---|---|---|
| **已证可安全调用** | 任意 | 优先`NATIVE_FUNCTION`，仍须具体动作授权与结果读回 |
| 尚未找到、不可安全调用或不适用 | **完整已证可安全写入** | 使用`VALIDATED_MEMORY_WRITE`；注明为何不采用原生函数 |
| 已找到地址但ABI/this/线程/AI调用者不明 | **完整已证可安全写入** | 不进行危险Native调用；可采用获授权内存方式，同时继续研究Native候选 |
| 仅找到旧DEV07写法或Field名称，没有真实语义/刷新联动 | 未验证 | `NO_SAFE_PATH`，即使看似能改变某个数字也不得宣称游戏行为完成 |
| Native与Memory均未证安全或完整性 | 未证 | `NO_SAFE_PATH`，可继续输出机制研究知识、资料假说及待测试列表 |

`HYBRID`仅在真实源证明存在可安全拆分的动作时保留为**未来方案**，不能以“外部修补字段”绕过游戏原生交易的校验与原子性。

## 4. 三机制示范（目标知识/合同，非声称已发现原生真值）

- **M1 AI球员徽章自然成长**：目标知识要区分AI球员成长与人类MyCAREER玩家徽章解锁；探索阈值是否存在和实际游戏条件；没有天然徽章提升证明时不授权`grant_badge`等自动行为。即使没有安全徽章函数，仍可给AI角色解释训练、导师关系与成长规则，但数字阈值需证据。
- **M2 AI教练战术**：目标知识要说明某战术参数对AI比赛决策的含义、合法值域、设置来源与消费时点。通过函数证明AI coach setter可安全调用时优先`NATIVE_FUNCTION`；否则在存储字段、刷新/消费、后台联动和fresh readback均证明后，可继续经授权实时内存写入；不能因旧UI存值报告就宣称“游戏AI正在使用它”。
- **M3 AI GM对AI GM交易**：目标知识要说明AI AI之间的评估/合法性/合同工资/选秀权与资产联动，不研究人工交易确认编辑窗口。证明原生AI-AI事务函数满足提交一致性则Native优先；找不到安全执行入口时，旧外部GM交易路线继续保持Human批准状态，**实时内存兜底也必须单独证明交易全域一致性**，而不是简单切换单个球员的球队指针。

## 5. 与原有批准任务范围的严格相容性

- 当前P0研究`Q3=A`：**三类代表性研究有真实且有边界的发现即可申请结束**。长期目标是将同样Knowledge+Action模型逐步扩展到全游戏重要AI机制；本轮不突然要求全部机制百科、生产API、完整内存执行器。
- `RES-REA-01`沉淀可给AI角色使用的知识；`RES-REA-02/03/04`三份代表机制知识档案；`RES-REA-05`安全Native PoC与内存兜底可行性，不强制实写；`RES-REA-06`双路径动作语义与架构方案；`RES-REA-07`保留机读证据与角色可见权限。依旧**7项A结果、8项SC验收映射**。
- 技术发现的证据成熟度、执行后端资格、角色权限、真实动作Human批准、结果验证是不同字段；不得用`PoC未执行`的实验凭据证明原生调用成功，也不得用“AI希望这样行动”代替游戏本体Mechanism规则。
- 如果未来需要启用外部AI控制的球队，却发现游戏Save内部仍是`HUMAN_CONTROLLED`，这是**必须单独研究和批准**的控制权分发问题，当前不自动改档案标志或模拟玩家UI。
- 本文与B0-v3只能用于规划，真实REA attach/游戏运行/Native调用、实时内存写入、旧交易执行器更新、master合并都没有得到新授权。
