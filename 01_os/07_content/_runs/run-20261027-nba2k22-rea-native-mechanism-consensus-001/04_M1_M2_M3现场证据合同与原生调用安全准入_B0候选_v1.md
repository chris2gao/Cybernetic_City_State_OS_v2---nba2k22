# NBA2K22 REA｜M1–M3有界现场研究合同与 Native PoC 安全准入 B0候选

**性质**：Stage02 原型/开发规划文档，`DESIGN_ONLY_NOT_DISPATCHED`。对应Human已批准 `A-v1-RC01`、Q4=A/Q5=A/Q6=B、三个代表机制和1–2个**有条件**调用PoC。实际Windows、Frida注入、游戏操作、函数调用仍由Codex在未来获明确许可的独立任务负责，当前无授权。

## 0. 共同研究单元与冻结输入

一个研究单元只能针对`ONE_MECHANISM + ONE_GAME_MODE + ONE_GAME_BUILD + ONE_SPECIFIC_SCENE`，固定游戏EXE/SHA、REA/provider/脚本SHA、save/season/游戏阶段、对象Native ID、允许的只读区域/运行成本、证据目录、新旧值、对应攻略`SRC-ID`及其平台版本。

共同输出 `SourceFact → NativeType/Instance → FunctionConsumer → ActualGameTransition → IndependentCheck`，每步标已证/被否定/未知，并引用源文件与source hash。不同时间的证据不能拼成同一个游戏瞬时状态。

### M1｜一个MyLEAGUE徽章的自然升级/导师路径（Q4=A）

| 步骤 | Codex应在真实新任务中验证 | 反证/失败分支 |
|---|---|---|
| 选样 | 在确实可访问的MyLEAGUE游戏存档中，选择存在UI徽章/导师进度的一名球员和一枚徽章；留第二枚轻量对照，记录为何比其它徽章更可观测 | 该徽章仅MyPLAYER/CAREER UI出现则不得移植 |
| 字段 | 读旧REA `FRANCHISE_MENTOR::BADGE`的`Progression`、`DateLastChecked`等**定义**，探索当前真正实例的同ID关联、日期和等级 | metadata中有`Progression`字段不能证明该字段此时是活值或表示自然升级进度 |
| 函数 | 定位对该实例字段写/读的候选consumer与更新事件；区分成长、训练、导师安排、比赛徽章触发、比赛效果常量的不同路径 | `BADGE_TUNING`中`ShotChanceBonus`不等于升级需要的能力阈值 |
| 阈值/状态 | 有原生cmp/分支或合法真实前后观测时才记录`attribute_id, operand_type, threshold, tier, AND/OR, update_time`；反向尝试低值/未触发等负例，或报告无法取得边界原因 | 不填无原生证据的固定数值；允许游戏该升级本来不按能力值门槛触发，需相应反证支持 |
| 产出 | 一条深度Mechanism Card；第二枚只比较来源与可见等级；证据等级精确到L1/L2/L3；明确缺少哪段、时间预算和后继 | 没有自然变化就`BOUNDED_UNKNOWN`，不是“游戏没有此机制” |

**先前研究的潜在错误**：导师指南中的“1.8倍/40%/60%”等说明不能被当作当前PC22Native真相。实际规则不允许由玩家偏好或GM教育目的倒推出内部阈值。Human没有授权直接修改徽章来模拟自然升级。

### M2｜一条教练进攻**或**防守设置的实际消费路径（Q5=A、Q6=B）

| 层 | 要找的对象 | 可能复用的来源/注意 |
|---|---|---|
| UI `V0` | MyLEAGUE → Coaching → Coach Gameplan，某一项在当前save有合法UI值 | 旧`39_COACHING_TACTICS`和`40_COACHING_EXECUTION_RUNBOOK`中的默认POE等实测记录是候选；必须绑定到当前gamebuild/角色 |
| Native stored `V1` | 真实所属Team/Coach/默认方案/指定对手/临场3种作用域、合法枚举与动态对象身份 | 已知旧V2存值/部分UI/读回，不能因此宣称原生setter定位 |
| Consumer `V2` | 该Native字段由哪个游戏代码分支读、在比赛准备、暂停或3D模拟哪个时点生效；截取局部callsite/执行线程 | xref只说明静态引用；比赛场景证据未提供则停在`CONSUMER_STATIC_ONLY` |
| Applied `V3` | 在同模式可靠对照中能否观察到具体应用状态或3D比赛引擎消费，无混淆AI覆盖与方案重载 | 值在菜单保存 ≠ 战术效果实际被采用；无应用实例时不打L3 |
| PoC候选 `V4` | 有可安全重入的游戏内部单一设置更新函数，不是Frida Memory.write或旧CLI；完整ABI/this/线程/游戏状态及副作用 | **没有独立Human具体调用授权就没有`V4`执行**；只做条件可行性评价 |

第二个进攻/防守参数只作`LIGHT_CONTRAST`，不把本P0升级成全部ACE、POE、Freelance、战术手册逆向。工程上可独立编组`LIVE_UI/REALTIME_FIELD/FUNCTION_CALLS/APPLIED_STATE`四份证据，避免来源时点混乱。

### M3｜游戏原生交易验证/commit与跨对象状态一致性

**研究核心分叉**：在Native交易菜单中执行`proposal`可能调用UI包装函数、合法性检查`validator`、评估/人工决定函数、真实提交`commit`和下游事件队列。不能用一个字符串`trade`+单个RVA代替真实流程。

1. **静态/只读**：由已有`R05B`的交易菜单候选、Roster Native/profile、`37_APPROVED_TRADE_EXECUTOR`等提出并核实局部函数/对象路径；观察游戏对非法和合法提议的校验分支但默认**不提交真实交易**。
2. **事务结构**：明确交易资产、双方名单席位、合同逐年薪资/选项、球队财政、选秀权归属、受约束条款、Game事件/新闻或历史记录，逐项区分`MUST_UPDATE/CONDITIONAL/UNKNOWN`和哪个函数负责。
3. **Native复用评估**：判定外部GM是否只能触发UI控制器，还是能安全驱动Game业务事务；函数是否需要游戏线程、当前GM/Save对象、动画回调、特殊市场时段和合法参数。
4. **输出**：`VALIDATOR_IDENTIFIED`、`COMMIT_IDENTIFIED`各自证据等级；完整性差集与`FEASIBLE/INFEASIBLE/BOUNDED_UNKNOWN`，若不安全则保留既有外挂执行方案，不能把局部写入视为交易完成。
5. **PoC顺序**：Q6=B规定先教练，交易只在高价值前置全部有证、另获Human精确授权的情况下作为第二个候选。无可安全调用目标是可以报告的研究结果，PoC仍`NOT_EXECUTED`。

## 1. Native函数调用安全准入门（真正行为前置，不是工具层自检）

| Gate | 必有证据 | 不满足的结果 |
|---|---|---|
| **G0 源锚点** | 固定EXE、模块SHA、candidate function RVA、REA/provider、原始指令或数据绑定 | 只能L0/UNKNOWN |
| **G1 语义与Mode** | 正确PC22离线MyLEAGUE真实对象/值，来源不是MyCAREER/跨世代假说或模组 | 禁止将其他模式函数解释为目标 |
| **G2 调用上下文** | ABI、参数/返回、this/vtable、线程、对象生死期、UI/Game manager当前实例、调用触发时机 | `NOT_SAFE_TO_CALL` |
| **G3 副作用** | 对应业务完整受影响对象/索引/缓存/事件集合、失败响应、部分更新与恢复/终止路径可控 | `TRANSACTION_INCOMPLETE`，禁止调用 |
| **G4 当前授权** | Human明确指定`save_id/exe_sha/scene/function/object/exact_action/允许改动字段/风险和恢复`；不是A-v1批准自动附带 | `NOT_AUTHORIZED_NOT_EXECUTED` |
| **G5 隔离执行** | 仅在已批准隔离档、固定执行时窗，有界动作/监控/现场状态防漂移/错误即时停止 | 中止并保留全部失败 |
| **G6 真结果** | 调用后**全新Native采集**，比较预期字段+关联不变量+实际UI/Gameplay状态（适用时）、源/时间绑定一致；不能仅凭调用返回值 | `EXECUTED_BUT_UNVERIFIED`不算PoC PASS |
| **G7 审核与后继** | 保存原始证据/中止记录/边界/异常、独立审核；提出现有GM外部路径变更前另请求Human架构裁决 | 不标Production Ready |

**不是自动回滚承诺**：非安全可逆交易不执行；已经触发未知副作用不得靠过期旧PID/旧快照盲回写。任何机制实验的安全边界必须由Codex在实际Game场景提出，经Human明确批准。

## 2. 任务预算、证伪与终止（供之后Codex任务书收敛）

每个候选目标事先声明`max_time / max_events / max_bytes / max_probes / max_failed_attempts / max_game_state_changes`和严格`stop_conditions`。本设计不虚构已经批准的固定秒数或合法变更额度。旧材料报告整EXE Ghidra原路线四次失败；**禁止无新定位/新方法仅扩大timeout重试**。

**高价值停止节点**：
- 发现是CAREER专属、旧模组或本世代MyLEAGUE从未实证可达 → 暂停该候选，保留证据；
- 找到目标字段但无人能定位消费函数 → 停L1/BOUNDED_UNKNOWN；
- 找到调用链但无法证明执行上下文 → 停L2/BOUNDED_UNKNOWN；
- 函数可执行但未获具体授权 → `NOT_EXECUTED`；阶段02/03可继续设计，不能偷跑实验；
- 工具超时、游戏进程异常、对象变化、清理失败 → 即时中止，原Evidence留存；
- 阐明交易commit不能单独安全重入 → 给`INFEASIBLE_FOR_EXTERNAL_DIRECT_CALL`并保留外挂路径。

## 3. 既有源码和真实执行必须分开评审

`M1:M2:M3`要有**独立完整的Source+Native+Function+Scene/Diff状态报告**。每张证明卡需包含原始`Evidence ID`、gamebuild/模式、可观测字段/状态、所需对照、证明了什么和未证明什么、失败预算结果与后继可操作任务。单个`evidence_id`不因为出现在两个项目二手文档中就算两条独立来源。

**工程开发Owner与任务界限**：本Run GPT可以维护B0契约；Codex新任务要等OS后续阶段规划门、Human另批执行范围。Human可以在对应游戏阶段配合提供场景，但当前只读规划不请求实时游戏操作。
