## 二、建议“机制地图”分层（01b再固定最终交付字段）

| 能力级别 | 实验依据 | 外挂系统可以据此做什么 |
|---|---|---|
| **L0 资料假说** | 原有NBA2K攻略/经验，明确出处与适用游戏版本 | 只能生成待证规则问题 |
| **L1 数据布局已证** | 独立对象、字段/枚举/常量/表格及真实样本/静态代码证据 | 设计Reader和数据库字段映射；不能断言触发逻辑 |
| **L2 机制静态路径已证** | 可复核函数入口、反编译/指令、xref/caller/callee、状态分支、必需前置条件 | 重建规则解释/条件假设；不能声称场景生效 |
| **L3 场景行为一致性已证** | 实际触发前后UI/Native源对象/条件对照，与已发现调用路径相互佐证 | 认为对应游戏机制的局部事实得到场景验证 |
| **L4 原生调用可行性已证** | 已证明签名、this/线程、调用链依赖、副作用/一致性、失败边界，**经另行Human授权的隔离测试档代表调用与全新读回** | 只能在已证条件与获授权范围内提出具体接口选项 |
| **L5 长期可调用实现与验收** | Codex真实集成、跨场景稳定、负例、独立验证和保护发布 | 是后续工程项目的结果，**不是本轮探索任务自动要求** |

不以“找到了某个函数地址”跳到L4，不以某个游戏内存值变化证明交易交易完整性。尤其对交易/合同：须考察工资帽、选秀权、球队名单、工作人员、新闻、赛程等联动和事务一致性，若调用只能完成局部改变则仍可能不优于现有路线。
