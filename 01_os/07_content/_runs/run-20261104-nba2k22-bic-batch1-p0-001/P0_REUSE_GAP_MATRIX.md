## Proposed reviewable increments

DEV01 first consumes the existing cards and scoped queries, with value/provenance/status/applicability and explicit save/batch/as-of/mode checks. Its real input selection precedes benchmark and negative-case acceptance. DEV02 then consumes those identities and badge observations while retaining UNKNOWN for unproved predicates. DEV03 consumes the same fact interface for comparable groups, synthetic arithmetic validation and a 3D observation protocol. Schema changes, Reader expansion and live operations require their own stated scope.

## Discrepancies to retain

Old R04 native badge-ID UNKNOWN labels describe that research artifact. The later WorldData profile supplies static Native field definitions and a decoder. Neither source should overwrite the other's historical scope. Player-card and badge queries select latest fields independently, so a card needs per-field age rather than a blanket fresh-batch claim. The historical 307-pass report is a fixed report, not a fresh BIC regression result.
