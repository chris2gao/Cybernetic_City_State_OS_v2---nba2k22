# REA calendar automation boundary

## Verified date operation

`rea_read_today.js` is a one-shot REA Frida script. Discover the current NBA2K22 PID and verify the installed executable against the candidate build SHA256 before attaching. Use `instrument_with_frida` with mode `attach`, device `local`, that PID, source_kind `file`, and this script's absolute path. A short observation window is sufficient. Require one `REA_NATIVE_TODAY` message with the bound PID and clean teardown. The output is game civil time. No native getter or simulation is invoked.

The script checks Win64 PE and timestamp, the existing GameMode getter code bytes and vtable binding, then double-reads the date and identity. The file-backed entry was exercised with REA on PID 10216 after the single-day trial: `0x2b7d0000` → 2021-12-29 00:00. Source SHA256 `f7b31fc51291a2ca83fadb6b698b5c3bea6040d2ee6289ff580491259f20bb30`. REA observation `ev_40c2604cbe0a1a2a6c63202cea6af50cfdd434f2516804228da53f2de80c4e9f` reported no cleanup error. This read does not attest the loaded save slot or session epoch. Bind those independently in the caller.

## Simulation entry research

[The 2021-12-28 live receipt](https://github.com/chris2gao/Cybernetic_City_State_OS_v2---nba2k22/issues/37#issuecomment-6702489511) anchors the true runtime callsite `0x12690dc`. REA disassembled it inside the command dispatcher at `0x1268320`. This path prepares the stack-local context with `0x12613e0`, passes the context from `[rbp-0x68]` to `0x11be250`, and invokes cleanup `0x1261260` after return. The dispatcher has several command IDs routed to the same switch arm, including 17, 18, 19, 20, 31, 32, 34 and 35. Some use typed payload objects resolved via virtual query, others derive their date from an engine object. The exact command ID for the live interaction was not captured. Retaining the old RDX from the trace would bypass object lifetime and cleanup.

REA independently enumerated the NBA2K22 visible window on the same still-running PID. Its thread was **3836**, whereas both simulation entries and their returns were observed on **3128**. The existing `research/rea_native_control/runtime/gui_once.js` schedules on the visible window's thread. Its selector cannot be used as proof of correct simulation thread affinity.

**External execution remains disabled.** The next evidence needed is the command identity and payload at dispatcher entry, the caller that submits it, and the engine path that consumes it on the simulation thread. A successful replay must use the engine's own construction, submission, lifetime and completion contract, with the save, session, current and target date and frozen game IDs checked again. The live UI case shows selected 2021-12-28 maps to a 2021-12-29 00:00 native boundary. It does not establish all target encodings, successful return paths or event semantics. Keep date/readback, exact final set, Box verification and non-replay checks in the controller.

`rea_trace_calendar_dispatch.js` provides that next capture surface using REA on the fixed process. It reports the candidate command ID, payload vtable provenance, caller stack, thread and matching wrapper arguments/return without publishing raw object pointers. REA arm-and-cleanup smoke `ev_2afe2377d609afb27a05e221afb264c56668029033914d8085e84e981ecc4a94` returned `REA_DISPATCH_TRACE_ARMED` and no cleanup error (source SHA256 `433f5478478934c7d9d1c6000400eda2372e2e0e96b163c585c7815c38a78c59`). This smoke exercises attachment only. A later authorized trigger with this observer active is required to establish command identity.
