# Human只读身份守卫纠正与新实验

Human明确要求：“请将STAFF池范围和对齐检查从只读探索的硬性阻断条件改为待验证的身份假设。保留实际内存可读性检查、有限范围读取和异常隔离。重新调查第一次失败的教练指针，寻找真实对象结构，而不是直接结束实验。严格身份认证仍用于写入和原生函数调用，不要影响已授权的只读探索范围。”

执行变更：配套只读builder移除STAFF池检查的硬阻断，输出hypothesis；新identity probe恢复最初PHI/IND缩写筛选的目录顺序，包含非核心球队。对null、池外、未对齐指针分别报告映射、有限字段投影、反向team link和可能RTTI；逐字段可读性检测和异常隔离，不因pool假说失败终止其他观察。

预算：一个新的1000ms REA窗口，最多32个缩写匹配对象，65536显式读取字节，单次字段最大1024字节，不hook、不调用函数、不写业务内存。根和目录复核，异常明确输出。输出只含RVA/逻辑身份/可读性/投影，不输出绝对地址。

第一次失败未保存原指针值，无法倒填“同一旧绝对地址已确认”。此次重建同一选择条件并识别当前第一个会被旧检查拒绝的记录；保持该证据局限。只读候选信息不自动成为写入/Native调用的严格身份资格。
