# 01 · 需求共识与需求结果建模

**NBA2K22 仓库活动机制：`方法论_v0.4.md`。**

阶段01分两步，必须连续执行：
1. **01a 需求共识建模**：双方统一目标、成功方向、范围、约束、术语。Human 确认此层仅代表 A0 共识；
2. **01b 需求结果建模**：提前、具体列明任务最终交付结果的对象、字段/功能、关系、行为、历史、输出与完成标准；经 Human 明确确认完整 A，才算完成需求阶段。

即**不是等到 03 结果建模才知道任务最后具体产生什么**。01b 预先确定最终结果目标与已知内容；02 核实事实、补足未知；03 依据证据提出可实施的工程 B（数据库物理表数、全部字段和设计理由等）。

活动方法：`方法论_v0.4.md`，通用结构：`实现/需求结果模型模板_v1.yml`。原 `方法论_v0.2.md`、`实现/需求建模schema_v1.md` 八槽继续兼容。Human 共识确认不代替完整 A 确认；A 变更需要新的精确版本确认。

默认每轮2–4个同层低依赖问题，关键术语冲突时退回单问题。尚未查明的字段不能编造，必须给出可逐项查验的缺口和判满方法。

**机器边界：** v1 七阶段 runner 尚不检查双层语义充分性；本仓先激活语义规范与 Boot/Registry 入口，Core 仓库后续独立审核及机器兼容升级。
