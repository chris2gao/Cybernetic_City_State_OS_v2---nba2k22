# T1 · 追问机制调研请求

**同一份文本分别发给 ChatGPT web 与 Gemini 3.1 Pro web，两方互不知情。**
差集是本次调研的主要产物，所以不要让任何一方知道另一方在做同一件事。

---

## 请求正文（以下整段发送）

我们在建一套人机协作的工作流系统。第一个阶段叫"需求建模"：
人类给出几句话的需求，模型通过**持续追问与讨论**，把它变成一份立体的需求建模——
使人类和模型双方都掌握远多于原始描述的信息，并且**双方陈述该需求时指的是同一件事**。

请调研这类机制目前有哪些现成实现，重点在 GitHub，也可包括论文、产品、prompt 方案。

### 需要你报告的

对每个候选，给出：

1. **项目/来源**——名称、地址
2. **机制形状**——它靠什么把需求展开？固定问题清单、动态追问、多轮澄清、
   结构化模板、还是别的？追问何时停止，停止条件是什么？
3. **产出形态**——追问结束后产出什么？自由文本、结构化文档、schema、还是别的？
4. **可改造程度**——是一套 prompt、一个库、还是一个完整产品？能否只取其方法论？
5. **许可证与活跃度**

### 必须一并报告的（这一条最重要）

**你搜了什么、返回为空。** 包括：

- 用过哪些检索词，哪些没有产出结果
- 哪些方向你判断可能有但没找到
- 检索是否在任何地方撞上结果数量上限或被截断

理由：我们判断这类调研的失败模式是**漏而不是错**。近期一次实际事故是：
一次被截断的搜索让"没有任何文档描述该流程"成为结论，而那份文档就在手边。
**没有边界记录的检索结果，无法与"全集"区分。**

### 明确不要做的

**不要推荐"最好的那个"，不要给结论性排序。** 请如实报告这个领域的图景。
我们要的是候选清单和各自的形状，选型由我们自己做。

### 背景约束（供你判断相关性）

- 追问的目的不是收集信息本身，是让**双方对同一需求的理解对齐**
- 产出会作为下游"证据收集"与"结果建模"的输入，所以结构化程度重要
- 我们不排斥自建。如果你认为现成方案都不合适，请说明理由，
  并指出自建时应当参考哪些方向（信息论、哲学、仿生学、认知科学等均可）
