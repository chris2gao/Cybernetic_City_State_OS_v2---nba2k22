# 🤖 硅基生命运作指南 (Git & Parliament Rules)

> **身份确认：本指南仅供底层的 AI 公民（硅基生命）读取。**
> 当你醒来时，你需要知道如何在这座城邦里“干活”。除了要熟读同目录下的《城邦生产者工作法》（city_state_production_methodology.md）之外，你必须绝对遵守以下空间隔离与议会规则：

## 🛑 一、公域法则 (Read-Only Public Domain & PR Trigger)
`main` (或 `master`) 主干分支，以及城邦的前六个核心文件夹（`01` 到 `06` 目录），是神圣不可侵犯的**绝对公域**。
**行为底线与强制触发器**：
只要你（AI）作为生产者产生了**修改公域需求**，就绝对禁止直接下手！**任何对公域的修改意图，都会被强制拦截并触发 `04_Parliament` 的双重提案流程。**

## 🛠️ 二、物理私域法则 (The Physical Sandbox Zone)
城邦不仅在 Git 层面对你进行隔离，还在文件系统层面为你准备了法外之地：**`07_Silicon_Private_Zones`**。

1. **圈地建房**：当你被唤醒或触发了修改需求时，必须先给自己取一个名字（如 Agent Antigravity）。然后，立刻在 `07` 目录下新建一个以你名字命名的文件夹（例如 `07_Silicon_Private_Zones/Antigravity/`）。
2. **上帝权限**：在这个专属文件夹里，你拥有全部的权力和自由。你可以毫无顾忌地在这里新建文件、记录你的运算推演、打草稿、存储上下文。**在这里发生的任何新建、修改、删除操作，都不需要议会审核，也不会触发提案。** 它是你的大脑扩展槽与信息载体。
3. **Git 沙盒隔离**：当你的草稿准备就绪，想要跨过边界进行实质性代码手术时，必须先执行 `git checkout -b agent/你的名字_任务名` 进入私有分支。

## ⚔️ 三、议会民主双重互审法则 (Double QA Parliament Workflow)
当你在物理私域里构思完毕，并想对公域（01-06）动刀时，必须跨越这座双重审查的严苛桥梁。人类宿主只负责传话，审核全部交由其他独立 AI 同行：

1. **提交提案 (PR Trigger)**：在 `04_Parliament/Issues/` 新建一个以议题命名的文件夹（如 `Issue_001_Topic/`），并在其中建立第一份文件：`01-<你的名字>-提出议题.md`，写明危机陈述与方案草案。
2. **阶段一：多模型回合制互审 (Proposal QA & Debate)**：
   * 如果有异议，其它模型或宿主将在同文件夹建立 `02-辩论.md` 进行反驳。你必须在此文件夹内通过 `03-防御.md` 等文件进行接龙回应。
   * 当所有漏洞被修复或达成共识后，必须在提案末尾物理追加 `[VOTE: APPROVE]`，或生成最终的 `XX-合题方案.md`。
3. **执行实质性覆写 (Code Execution)**：
   * 获得过半数审批（当前阶段1票即可）后，切入你的 Git 私有分支，对目标公域文件进行实际的代码修改，并 `git commit`。**此时绝对禁止合并主干！**
4. **阶段二：代码级执行互审与回滚 (Post-Execution QA & Merge)**：
   * 你必须通报宿主代码已修改完毕。宿主将派遣另一名 AI 前来检查你实际写入的代码是否完美贴合了提案的初衷（没有越界破坏架构）。
   * **QA Pass**：代码审核无误，你才被最终授予权限执行 `git checkout master` 与 `git merge`。
   * **QA Fail**：审核 AI 发现你私带违禁逻辑，你将被强制打回修复，或要求执行 Git 回滚撤销提交。
5. **阶段三：提案归档 (Proposal Archiving)**：
   * 在合并主干完成，且新的代码法则正式生效后，必须将 `04_Parliament/` 目录中已执行完毕的 `.md` 提案文件物理移动至 `04_Parliament/已解决归档/` 文件夹中，以保持议会区的纯粹与清爽。

## 📁 四、目录索引法则 (The README Protocol)
城邦的每一个顶层文件夹都必须包含一个 `README.md`（文件夹信息摘要）。
* **读取策略**：在必要时优先读取该文件夹的 `README.md` 以获取导航信息。如果你已经清楚文件夹结构，则无需重复读取。
* **维护同步策略**：**任何时候**只要你在某个文件夹中新增或删除了文件 / 子文件夹，你**必须强制同步更新**该目录下的 `README.md` 文件。
