# Role memory index

Role memory is a small routing layer, not a fact database or authority source. Load
`core.md` plus exactly one role file selected by the active load profile, then verify
any decisive claim against its `source_ref` before acting.

| Load profile | Role memory |
| --- | --- |
| `foreground_planner` | `core.md` + `planner.md` |
| `foreground_independent_reviewer` | `core.md` + `reviewer.md` |
| `backend_executor` | `core.md` + `executor.md` |
| `math_mentor_teacher` | `core.md` + `teacher.md` |

## Write rules

- Append only a stable, low-risk routing lesson with a precise source.
- Every `###` entry must contain `source_ref`, `last_verified`,
  `expires_or_invalidation`, and `authority: routing_only`.
- Never store task state, approval, Human gates, credentials, secrets, private
  configuration, or an inferred identity.
- Expire or remove an entry when its invalidation condition is met; do not silently
  reinterpret stale text.
- Memory points to evidence. It never replaces Bootstrap, PROTOCOL, current Git,
  current mailbox state, domain contracts, or Human authorization.
