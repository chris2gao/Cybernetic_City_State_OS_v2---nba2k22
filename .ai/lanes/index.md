# Cooperative communication lanes

This directory defines a C0/C1 cooperative convenience layer. It prevents accidental
shared-file overwrites and reduces repeated context. It is not a trusted runtime,
identity system, scheduler, CAS protocol, authorization source, or replacement for
the communication gate.

## Instance layout

```text
.ai/lanes/<lane_instance_id>/
├── meta.yml
├── seq
└── events/
    ├── NNN.lane-envelope.yml
    └── NNN.yml
```

`lane_instance_id` is a self-declared local UUID-like identifier. `meta.yml`, `seq`,
and temporary files are local runtime bookkeeping and are ignored. Durable event and
envelope artifacts may be tracked on `ai/review/latest` so canonical STATE can cite
them immutably.

`meta.yml` conforms to `lane_meta.schema.json` and records `environment_class`, descriptive `protocol_role`,
`load_profile_id`, `lane_instance_id`, `opened_at`, and `lane_protocol_epoch`. The
epoch must equal the bound value in `lane_epoch.yml`. The envelope repeats that epoch
and records `base_review_head`, the review head observed before writing; it never
self-references the commit containing its event.

An event carries the role-appropriate seven-field signal or handoff and keeps that
pointer byte shape unchanged. Its `required_refs` includes the independent envelope
artifact. Because an immutable Git ref cannot refer to the commit that contains
itself, publish the envelope first, then publish `NNN.yml` referring to that envelope
commit. There is no dual write to legacy `.ai/OUTBOX.md`.

Each instance appends only to its own directory. Files are first written to a temporary
name and atomically renamed. `seq` increases monotonically. `reduce-lanes.ps1` rejects
an envelope whose lane ID differs from its directory, duplicate backend claims for one
task, duplicate event IDs, and a task listed as both legacy and lane delivery.

## Canonical reduction

Only the foreground role invokes `reduce-lanes.ps1` to write `.ai/STATE.yml`. The
reducer takes the maximum numbered event per lane, sorts by lane ID and sequence,
ignores events whose `lane_protocol_epoch` differs from the bound current epoch, and
records immutable event and envelope refs plus SHA-256 digests in `lane_inputs`.
Lane tests validate routing and traceability. The communication gate, policy,
validator, canonical event, seven-field pointer, and STATE transition semantics are
unchanged.

After the protocol release bound in `.ai/lanes/lane_epoch.yml`, backend receipts use
lanes. Cutover is forbidden unless no backend task is in flight, every old backend
session has completed or stopped, and every environment reloads the protocol before
its next durable write. Legacy shared OUTBOX is read-only compatibility input. The
same event must not be written to both channels, and the same task in mixed mode fails
closed. Source/master neutral mailbox rules remain unchanged.

## Local transport and publication helper

`lane-local.ps1` provides Windows-native `post`, `read`, and `gc` commands under
`%LOCALAPPDATA%/CityState/local_lanes/`. Local metadata declares `transport: local`;
omitting `transport` retains the historical Git default. Local messages are explicitly
non-authoritative and are limited to C0 coordination or C1 shadow copies. They never
enter canonical `lane_inputs`; `reduce-lanes.ps1 -Transport local|both` records only
`local_lane_traces` with `non_authoritative: true`.

`publish-review.ps1` copies an approved staging tree into a temporary review worktree,
checks immutable refs, stages explicit paths, commits, and performs a normal non-force
push to `ai/review/*`. A failed push is rebuilt once from the newly fetched review head.
Successful publication consumes staging; dry runs and failures preserve it. Logs remain
under `%LOCALAPPDATA%/CityState/logs/`.
