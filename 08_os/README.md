# 08_os — the city-state operating system

Scaffold created 2026-07-27. This is the second-generation structure: the old system
grew by accretion and had to be reconstructed by reachability analysis because nothing
recorded what loaded what. This one records first and grows second.

## The seven areas

| Directory | Holds | Does not hold |
| :--- | :--- | :--- |
| `01_workflow/` | Workflow stages and the execution information for each | General mechanisms; content |
| `02_boot/` | Environment information and startup mechanisms — context management, global state | Per-mechanism logic |
| `03_mechanisms/` | General reusable mechanisms, each a self-contained capability — the communication protocol is one | Workflow-specific steps |
| `04_skills_and_tools/` | External skills and tools that extend model capability | Mechanisms the system itself runs on |
| `05_registry/` | A structured record of what every file is for, and what loads it | Anything generated by a task |
| `06_execution/` | Per-area loaders that initialise or reload a mechanism, workflow part, environment, skill or tool | Definitions; those live in their own area |
| `07_content/` | Domain content built with this workflow — information bases and generated results | Workflow machinery |

## Two rules this structure exists to enforce

**The registry is updated with the development, not after it.** Every file added under
`08_os` gets a registry entry in the same change. A registry that lags is a registry
that lies, and the previous system demonstrated exactly what that costs: two
mechanism files were deleted by a correct reachability computation because nothing
recorded that an external tool loaded them, and both were found by accident.

**Intermediate files produced by task execution are not registered and are deleted.**
The registry describes the system, not the traffic through it. If a file is scratch,
it does not get an entry; it gets removed.

## Status

Every directory here currently holds only its purpose statement. That is deliberate and
temporary. An empty directory that claims a role it does not yet fill is the same
failure this structure is built to avoid, so each one states plainly what it is for and
what it does not yet contain.

Migration from the first-generation system is selective: where the old repository
already implements a mechanism, it is assessed and ported, not copied wholesale.

## Ownership

`08_os/` is not yet declared in `CORE_MANIFEST.yml` under either `core_owned_paths` or
`domain_owned_paths`. Seven such undeclared paths were already found in the previous
system, two of them in the receipt-required bootstrap set. This one should be declared
before it accumulates content.
