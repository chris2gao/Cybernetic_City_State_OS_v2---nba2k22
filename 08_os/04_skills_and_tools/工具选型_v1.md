## 2. 三个必须先记住的坑

### ~~mutmut 在本机装不上~~ —— 这一节的结论已被推翻，保留作教训

- 不兼容 **Python 3.14**：依赖的 Pony ORM 序列化失败（`itertools.count` pickle error）
- AST 变异引擎**跳过所有带装饰器的函数与类**——`@app.post`、`@typechecked` 全部被忽略

**本机实测 Python 3.14.6。** 第一条直接判死。
第二条更麻烦：**即便降到 3.12，装饰器密集的代码会静默返回"捕获率为零"**，
而这种失败**不报错**——看起来像测试写得好。

**原结论**：暂缓。

**2026-08-01 更正**：错的是作用域。**我实测的是 Windows 那一个解释器，
结论却下到了整台机器**——而本机 WSL2 可用，run-013 在隔离 venv 中把 3.6.0 跑通并接入。

装饰器那一条**仍然成立且仍然重要**：它不报错，直接回报「捕获率为零」，
看起来像测试写得好。所以上面那句「先跑一段已知有缺陷的代码验证它确实能抓到」
是对的，run-013 的 calibration 正是这么做的。

**留下的规则**：一个环境探测的结论，作用域不得大于被探测的那个环境。

### check-jsonschema 的 `anyOf` 会被 MCP 客户端拦截

主流编辑器的 MCP 客户端验证引擎对 `anyOf`（即 `Union[str, dict]`）有实现缺陷，
**合法输入会在客户端就被拦下，请求根本不下发到服务端**。

**结论**：暴露给 agent 的接口参数用宽泛类型，细粒度值校验下沉到 Python 内部。
**这条约束要写进我们自己的 schema 设计**——三张 schema 里凡是"或"关系的槽位都受影响。

### promptfoo 是 Node 生态

评测纯 Python skill 或需隔离的系统级脚本时，跨进程 stdout/stderr 捕获**偶发截断**。
需要在评估器里严格约定自定义执行脚本的接口规范。

## 3. 挂载形态：不要全量挂 MCP

**MCP 的工具定义会全量注入上下文**：所有工具 schema 在会话初期一次性载入，
数十个工具就是数万 token，**工具数破二十后 agent 的选择准确率断崖下跌**。

| 形态 | 装什么 | 为什么 |
| :--- | :--- | :--- |
| **Agent Skill** | zwicky、EMR-ACH、PyArg、Z3、recapture、set 覆盖、校验错误转追问 | 渐进式披露：平时只占约 100 token 的名称+描述，命中才读全文；纯离线数学，无常驻服务 |
| **MCP server** | `promptfoo`（原生自带）、`cargo-ovft` | 重运行时，跨进程隔离 |
| **内联** | 操作 2、14 | 几十行，外部化是净损失 |

这条与我们已有的 token 纪律同向：**上限设在调用发生之前**。

后备：`mcp-skill-server` 可把任何带 `--help` 的 CLI 零改造转成 MCP。**不预先引入。**

## 4. 登记规矩

每条工具真正启用时，本表对应行的「实测」列必须填：

```
实测: 已装 | 未装 | 前提不成立
版本: <命令实测输出，不是文档写的>
验证命令: <一行，任何人可复跑>
```
