# 环境能力 receipt v1 正例与负例

## 正例

`08_os/_runs/run-020-环境能力发现最小版/08_结论/环境能力receipt_实测_v1.yml` 是本次真实测量正例。
它覆盖六个必需类别，每个 observation 都携带测量来源；不可观测事实使用
`status: not_observable` 和原因，不用 registry 历史值代填。

## 四个必拒负例

验证 harness 从正例的内存副本生成以下临时实例，并在 run 的 `_runtime/` 中完成验证后删除：

1. 删除必填顶层 `toolchain`；
2. 在允许的字符串 value 中注入由 drive-root 与用户目录语义片段运行时拼成的个人绝对路径；
3. 把一个不可观测项的 status 改成 schema 不接受的未知状态；
4. 删除一个 observation 的 `measurement_source`。

负例 2 不在脚本、fixture、日志或 receipt 中持久化字面绝对路径。wrapper 的完整拒绝输出只在
`_runtime/` 存活，耐久结果仅保存退出码、输出摘要哈希和行数；这样既真实测试拒绝能力，也不让
测试证据触发个人路径推送门。

## `.yml` 与 wrapper 的边界

任务包固定 schema 输出名为 `.yml`，而已登记 wrapper 的 policy gate 只接受 `.json` 后缀。
canonical `.yml` 因而保存严格 JSON（同时是合法 YAML）；harness 复制其原始字节到临时 `.json`，
先比较 SHA-256 完全一致，再调用 wrapper。临时副本和四个负例均在测试结束前删除。

## 通过标准

- 正例 wrapper exit `0`；
- 四个负例 wrapper exit `1`，不能用 wrapper/policy/tool failure 代替 schema 拒绝；
- `status: observed` 的 observation 顶层 `value` 不得为 null；嵌套 safe value 仍允许 null，
  因而实测 receipt 的 `rollout_token_budget: null` 继续合法；
- 独立 Python checker 不复用 schema 正则，而按 drive-root、UNC、POSIX 用户/系统根目录、
  home 缩写和环境变量展开等路径形态推导；
- checker 把双拒绝记为 `agreed_reject`、仅 checker 拒绝记为 `checker_only`、双放行记为
  `pass`。`checker_only` 是 schema 盲区信号，本轮记录但不扩张 schema；
- 最终 personal-path changed-mode、`git diff --check` 和 allowlist scope 全部通过。

第 1 轮修正另验证：A2 顶层 null 被双拒绝、五类既有 schema 路径形态保持双拒绝、状态机与
深层嵌套回归继续生效、N1 八类形态稳定产生 `checker_only`，且原始 receipt 与嵌套 null 正例通过。
