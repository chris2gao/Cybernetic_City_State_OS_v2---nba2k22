# 文件隔离与产物生命周期 v1

| 类别 | Canonical 路径 | 跟踪 | 注册 | 生命周期 |
|---|---|---:|---:|---|
| 阶段方法/实现 | `01_workflow/<stage>/` | 是 | 是 | protected/versioned |
| 全局机制 | `03_mechanisms/<mechanism>/` | 是 | 是 | protected/versioned |
| boot | `02_boot/<name>/` | 是 | 是 | protected/versioned |
| loader/validator | `06_execution/<area>/<name>/` | 是 | 是 | protected/versioned |
| 开发设计 | `_dev/` | 是 | active 时是 | 以 supersedes 保留历史 |
| 公开运行产物 | `_runs/<run-id>/` | 耐久时是 | 否 | 按运行策略保留 |
| 角色私有/scratch | 宿主运行时或 `_runs/<run-id>/_runtime/` | 否 | 否 | 完成后删除 |
| handoff/outbox | run 的明确公开路径 | 仅正式发布 | 否 | 耐久时保留 |

公开运行目录只在有内容时建立 `01`–`07` 阶段目录；不建空目录。经审核提升的通用定义进入
`03_mechanisms/`，原 run 证据仍留在 `_runs/`。

## task × role 区域

每个任务角色区逻辑上分为 `entry`、`inbox`、`private`、`outbox`、`artifacts`、`audit`。
工作区优先位于仓库外；必须位于仓库内时，只能使用 `_runs/<run-id>/_runtime/`，且由
`.gitignore` 排除。private/scratch 不得成为 durable handoff 的隐式来源。

## 发布与失效

- 发布接口必须列出精确路径 allowlist；禁止 `git add --all`、`git add .`、根目录全量归档。
- private sentinel 必须证明不会进入提交、包或上传。
- handoff 与入口记录依赖哈希；stale 与 checkpoint 是不同概念。
- 删除私有过程前，先把耐久事实、正式失败与审计引用写入公开产物。
- 失败状态保留；最终成功不能覆写先前发生的副作用和清理残余。

## 当前残余风险

1. 最小入口在真实完整 OS 任务中的语义完整度、补充次数和 token 收益尚未验证。
2. Web 受限交接候选实现的运营成本尚未验证。
3. run-007 披露的两个早期合成临时目录仍需新的宿主权限或 Human 清理决定。
