## 3. 新 ID/字段空间的作用域

### 3.1 `source_id`

**定义唯一性：evidence-index artifact version 内。**

`source_catalog` 在一个 evidence-index artifact 内定义 source symbols；
同一 artifact 的 `source_refs` 可以多次引用同一 `source_id`。被取代草案与最终 artifact
可以复用同一 symbol，而不构成仓库全局重复。

依据：

- `08_os/03_mechanisms/context_management/依据材料/evidence/07c_证据索引草案_v1.yml:8-31`
- `08_os/03_mechanisms/context_management/依据材料/evidence/07c_证据索引草案_v1.yml:34-47`
- `08_os/03_mechanisms/context_management/依据材料/evidence/07_证据索引与可行性判断_v1.yml:11-16`
  （最终 artifact 明确 supersede 草案）

结论：不是 repository-global ID；T07 应要求“每个 evidence-index artifact version 的
source catalog 定义不重复，引用必须解析到该 artifact 的 catalog”。

### 3.2 `evidence_id`

**定义唯一性：evidence-index artifact version 内。**

它是 `证据条目` 的主键。草案与最终 artifact 可以保留相同 evidence identity，
因为二者有明确版本/supersedes 关系；不能把跨版本同名直接判为重复失败。

依据：

- `08_os/03_mechanisms/context_management/依据材料/evidence/07c_证据索引草案_v1.yml:33-35`
- `08_os/03_mechanisms/context_management/依据材料/evidence/07_证据索引与可行性判断_v1.yml:132-145`

T07 应按 artifact version 建 symbol table，不建立仓库全局唯一索引。

### 3.3 `research_question_ids`

**定义唯一性：研究问题定义 artifact 内；解析作用域：同一 workflow/mechanism
research instance。**

`RQ-01` 至 `RQ-07` 定义在挖掘目标 artifact，随后被证据 index 和 closure 跨文件引用。
因此它不是 evidence file 内自足的 ID，也不是仓库全局 ID。

依据：

- `08_os/03_mechanisms/context_management/依据材料/evidence/00_挖掘目标与领域_v1.yml:20-67`
- `08_os/03_mechanisms/context_management/依据材料/evidence/07c_证据索引草案_v1.yml:34-35`
- `08_os/03_mechanisms/context_management/依据材料/evidence/07_证据索引与可行性判断_v1.yml:84-131`

T07 应要求 evidence artifact 显式绑定其 research-question definition artifact/version，
再在该 workflow/mechanism instance 内解析。

### 3.4 `original_source`

**不是 ID，也没有唯一性范围。**

它是每个 `source_ref` 上的布尔属性，回答“该引用是否直接指向原始/一手来源”。
同一 evidence item 中可以出现多个相同布尔值。

依据：
`08_os/03_mechanisms/context_management/依据材料/evidence/07c_证据索引草案_v1.yml:39-45`

### 3.5 `shared_origin`

**不是 ID，也没有唯一性范围。**

它是 evidence item 的依赖说明，描述多个 source refs 是否共享首发论文、官方文档体系、
框架资料或其他共同来源，用于解释 `independent_source_count`。

依据：
`08_os/03_mechanisms/context_management/依据材料/evidence/07c_证据索引草案_v1.yml:46-49`

### 3.6 `location`

**不是 ID；作用域是单个 `source_ref`。**

它是 source 内部定位器，只有与相邻 `source_id` 联合才有意义。允许重复，也不要求仓库
全局唯一。

依据：
`08_os/03_mechanisms/context_management/依据材料/evidence/07c_证据索引草案_v1.yml:38-45`

### 3.7 `original_source` 与 `shared_origin` 的关系

二者互补但不互相替代：

- `original_source`：逐个 source reference 的一手/非一手标记。
- `shared_origin`：整个 evidence item 上，多路 source references 之间是否具有共同来源的说明。

多个 `original_source: false` 的综合报告可能回溯不同首发研究，也可能共享同一首发研究；
因此独立来源数不能由布尔值相加，必须结合 `shared_origin` 与 source locator 计算。

## 6. 必须带入 T07 的合同要求

1. **引用定界**：真实文件名含空格，禁止按空白切词。合同应规定反引号、引号、
   结构化字段或等价的无歧义定界。
2. **anchor**：路径可能携带 `#anchor`；合同需分别定义 file target 与 anchor target，
   并决定 anchor membership 是否进入引用有效性判定。
3. **context class**：validator 必须知道 occurrence 是 normative、observed、example、
   template、fixture 或 unresolved；“目标当前不存在”不能脱离 occurrence class 判失败。
4. **versioned symbol table**：`source_id`、`evidence_id` 按 artifact version 解析；
   `research_question_ids` 按绑定的 research instance 解析。
5. **非 ID 字段**：不得对 `original_source`、`shared_origin`、`location`
   施加唯一性检查。
6. **confirmed failure 四门**：instance、rule、scope、replay path 缺一不可。
