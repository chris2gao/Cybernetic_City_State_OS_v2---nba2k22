T06b 的分类判断已通过独立审核，六类计数、失败计数、fixture readiness 全部逐项复现，

它只解决一件事：`path_reference_classification.csv` 只有 `input_row` 行号，
没有 `from` / `line` / `target`。连接键指向 `cca682a` 的 blob，而 `cca682a`

且该路径在 `c0492cd` 不存在。一旦并入 master，这张表在 master 内无法解释：
钉住 blob sha 是好习惯，但钉向未合并分支的 sha，耐久性只等于那条分支的寿命。

顺带补 T06b 缺的机器可读发布回执（见 §4）。散文里写了确实绑定并读回，只是没落成字段。

## 2. 要做的改动

### 2.1 分类表补三列

原地重写 `path_reference_classification.csv`，列序固定为：

```
input_row,from,line,target,classification,failure_status,fixture_readiness
```

`from` / `line` / `target` 取自 `t06a_csv_blob` 的同一位置数据行（`input_row` 是去掉
表头后的 1-based 行号）。后三列**逐字保留** `t06b_csv_blob` 的原值。

**输出必须是 RFC4180 引号包裹的 CSV。** 这不是风格偏好：第 278 行的 `target` 实际值是

```
.githooks/install.ps1,
```

结尾带逗号（源文是 YAML 折叠块里的散文标点，属已判定的 `extractor_regression`）。
不加引号会让该行列数错位。T06a 输入本身就是全字段引号包裹的，照此输出即可。

同理，含空格的 8 行（`evidence/chatgpt`、`evidence/gemini` 截断）保持原值不动——
它们是被判定的抽取器缺陷记录，不是待修复的路径。**不要顺手把它们补全成真实文件名**，
那会改变 T06a 的枚举事实。

### 2.2 结论文档记一句 schema 变更

在 `分类结论_v1.md` §0 补一句：分类表已反规范化为七列自足表，`input_row` 仍是对
`t06a_csv_blob` 的 1-based 行号，新增三列为该 blob 同位置的原样拷贝，不构成新枚举事实。

### 2.3 run.yml 补发布回执

`validation:` 下把非 local_git 传输的回执补全（`c0492cd` 的规范第 10 节要求）：

```yaml
  publication_transport: github_api_connector
  hook_guard: not_applicable_transport
  replacement_gate: passed | failed
  expected_remote_head: <本次发布前实测>
  resulting_remote_head: <本次发布后远端读回>
  compare_and_swap: passed | failed
  fast_forward_verified: true | false | not_applicable
  force_used: false
```

`resulting_remote_head` 必须是发布后从远端读回的值，不是本地 HEAD，也不是
`expected_remote_head` 的复制；两者相等要由读回证明。
不得在本传输上写 `hook_guard: passed`。

同时把 `outputs` 与 `validation.rows_classified` 之外的计数保持原值——本单不改计数。

改动前先复现，改动后复测，两次都留可回放命令与实际结果：

   三列与 `t06b_csv_blob` 逐行逐字相等。这是本单最重要的一条——加列不得改判。
3. **连接正确**：新表每行的 `from` / `line` / `target` 与 `t06a_csv_blob` 同位置数据行
   逐字相等。
4. **计数不变**：`normative_definition` 277、`observed_instance` 86、
   `explanatory_example` 10、`template_placeholder` 0、`run_fixture` 18、
   `unresolved_hypothesis` 0，合计 391；`failure_status` 全为 `not_a_failure`；
   `fixture_readiness` 为 `valid_reference_or_policy` 349 / `not_ready` 29 /
   `extractor_regression` 9 / `negative_sentinel` 2 / `executable_probe` 2。
5. **引号回归**：用标准 CSV 解析器读回新表，第 278 行必须解析成 7 个字段，且

6. **自足性**：仅用新表 + master 树，不访问 run-016，能对任意抽查行还原
