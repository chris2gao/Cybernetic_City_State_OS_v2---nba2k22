# 环境与安装回执

## 结论

mutmut `3.6.0` 已在 WSL2 Ubuntu 的 Linux 文件系统工作区和专用 virtualenv 中
完成真实性验证。安装未修改 Windows Python、WSL system Python 或全局 PATH，
未执行系统级安装，也未使用 `sudo` 或任何凭据。

## 工作区与安装

- WSL 用户：`gk`
- 工作区类别：`/home/**` 下的 WSL Linux filesystem
- Python：`3.14.4`
- virtualenv：`/home/gk/.venvs/core-mutmut-3.6.0`
- isolation：`include-system-site-packages = false`
- 安装：virtualenv 内 `pip install mutmut==3.6.0`

非交互 SSH clone 未在限时内完成，随后按任务授权使用普通本地 clone fallback，
再把 `origin` 恢复为 GitHub SSH URL。该 fallback 不改变 source commit，也未从
Windows 挂载目录运行 mutation。

`mutmut --version` 在没有配置的 repository root 会先加载配置并失败；在声明
`[mutmut]` 配置的 mutation project 中返回精确的
`mutmut, version 3.6.0`。因此 wrapper 的版本门在 project 临时副本内执行。

## 真实性与隔离

机器可复核字段、命令退出码、输出摘要、virtualenv 文件/字节数、`fork` 回执、
origin/master 起止值和 process residue 在 `environment_receipt.json`。该 JSON
属于机器态运行回执；canonical 文档和 registry 不依赖其中的用户绝对路径。
