# Human 确认说明

独立审核通过后，请 Human 对完整候选 A 核对以下五点：

1. `目标` 是否准确表达希望达成的结果；
2. 14 条 `成功判据` 是否代表“通讯机制做成了”，尤其是 §3.2 的 R1–R11；
3. `边界` 是否排除了不希望 P1 或阶段一处理的内容；
4. 目标关键词与 23 个 `术语` 的含义是否一致；
5. 9 条 `假设` 与 8 条 `未解歧义` 是否诚实，没有把待研究的技术选择写成已确认事实。

五项高影响未解歧义是：兼容观察期阈值、全部 core 窗口的可执行枚举、无本地 hook 的传输
等价证明、action-bound Human authorization 的可信注入，以及真实 rollback 的在途状态和恢复
标准。它们按 `阻塞范围` 阻塞后续阶段，不阻止 Human 确认“双方所指同一需求”。

候选确认模板位于 `../01_需求建模/Human确认_v1.yml`。执行方和审核方不得填写
`human_decision`；Human 只能对模板已绑定的 version `1` 与 SHA-256 作出确认或要求修订。
