## 机制 2 分析结论

### 有效的承重结构

1. **挖掘目标指向可行性，而不是泛化了解。**
2. **必须同时写支持条件与推翻条件。** 本次推翻条件直接生成了本机隔离成本、交接补充成本、Web 仓库成本和失效传播复杂度等研究问题。
3. **先做领域与信源分析，再进入内容检索。** A 的关联领域可以直接作为输入，但需要 EIG 预筛选。
4. **内部证据、外部发现、定向核实和第三方综合应分开。**
5. **发现用 agent 检索，收敛用 NotebookLM。**
6. **边界记录是必要产物。** 单次“没有找到”不能被写成“不存在”。
7. **EIG 是最终停止判据。** 覆盖率低不自动意味着继续搜。

### 测试前已存在的确定缺陷

1. `实现/README.md` 声称实现为空，但目录已有执行清单和信源模板，状态已过期。
2. `执行清单_v1.md` 仍使用朴素 Lincoln-Petersen 公式，与方法论中的 Chapman 修正冲突。
3. 清单仍要求并行双方“报告重合”，但互不知情的两方无法知道真实交集；重合应由第三方或合并方计算。
4. “信源可靠性”和“信息可信度”虽在方法论中分开，模板却把一般可信度写在平台条目，层级错误。
5. 阶段二没有标准 `evidence/` 耐久产物 schema，机制 3 无法确定性消费。
6. “中间过程不保留”与“阶段状态由耐久产物推导”缺少边界，可能误删阶段完成所需证据。

## 本次测试新发现

### 1. 问题类型必须逐问题声明

同一个 A 同时包含：

- 定向核实：无关上下文是否影响表现、GitHub 权限粒度、当前角色是否可用；
- 开放发现：有哪些上下文机制、隔离机制、版本与失效模式。

因此不能把整轮研究统一标为“开放发现”或“定向核实”。捕获-再捕获只能用于其中的开放发现问题。

### 2. A 的关联领域不能机械照抄

A 列出十个关联领域。本轮通过 EIG 暂不单独深挖通用认知科学、零信任安全和跨平台兼容，因为它们不会改变第一版可行性判断或已被 A 排除。

领域分析应以 A 为起点，不是把 A 的列表复制进派单。

### 3. 内部材料是正式证据，不是背景资料

`系统机制总结.md` 提供了第一代真实运行的懒加载、角色 Profile、fast path、role memory、checkpoint 和失败反例。

这些证据必须与外部研究一样形成证据条目，并标明时间、适用性和不能继承的部分；不能只在模型头脑中作为“参考”。

### 4. 模型上下文与系统执行依赖必须分离

第一代盘点显示 validator、Schema、tests 和 fixtures 可能不被模型读取，但仍是运行机制。

第二代的上下文入口不应承载所有控制逻辑；版本检查、权限检查和产物校验应由确定性系统执行，避免把控制面重新注入模型上下文。

### 5. 首条外部路线只支持“暂时可行”

ChatGPT 路线已经找到：

- 无关/过长上下文的性能风险；
- 独立子代理上下文与压缩交接；
- session、thread、checkpoint 和外部 memory；
- handoff 输入过滤；
- worktree 工作目录分离；
- GitHub 仓库级权限；
- checkpoint retention 风险。

但它不能单独结束阶段二。仍需独立 Gemini 路线、NotebookLM 第三方匹配和本机运行试验。
