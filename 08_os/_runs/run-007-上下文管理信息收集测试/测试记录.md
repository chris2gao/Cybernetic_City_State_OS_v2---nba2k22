## 机制 2 分析结论

### 有效的承重结构

1. **挖掘目标指向可行性，而不是泛化了解。**
2. **必须同时写支持条件与推翻条件。** 本次推翻条件直接生成了本机隔离成本、交接补充成本、Web 仓库成本和失效传播复杂度等研究问题。
3. **先做领域与信源分析，再进入内容检索。** A 的关联领域可以直接作为输入，但需要 EIG 预筛选。
4. **内部证据、外部发现、定向核实和第三方综合应分开。**
5. **发现用两路独立 Deep Research，收敛用 NotebookLM。** NotebookLM 必须等待两份正式完整报告都返回。
6. **边界记录是必要产物。** 单次“没有找到”不能被写成“不存在”。
7. **EIG 是最终停止判据。** 覆盖率低不自动意味着继续搜。

### 测试前已存在的确定缺陷

1. `实现/README.md` 声称实现为空，但目录已有执行清单和信源模板，状态已过期。
2. `执行清单_v1.md` 仍使用朴素 Lincoln-Petersen 公式，与方法论中的 Chapman 修正冲突。
3. 清单仍要求并行双方“报告重合”，但互不知情的两方无法知道真实交集；重合应由第三方或合并方计算。
4. “信源可靠性”和“信息可信度”虽在方法论中分开，模板却把一般可信度写在平台条目，层级错误。
5. 阶段二没有标准 `evidence/` 耐久产物 schema，机制 3 无法确定性消费。
6. “中间过程不保留”与“阶段状态由耐久产物推导”缺少边界，可能误删阶段完成所需证据。

## 本次测试新发现

### 1. 问题类型必须逐问题声明

同一个 A 同时包含：

- 定向核实：无关上下文是否影响表现、GitHub 权限粒度、当前角色是否可用；
- 开放发现：有哪些上下文机制、隔离机制、版本与失效模式。

因此不能把整轮研究统一标为“开放发现”或“定向核实”。捕获-再捕获只能用于其中的开放发现问题。

### 2. A 的关联领域不能机械照抄

A 列出十个关联领域。本轮通过 EIG 暂不单独深挖通用认知科学、零信任安全和跨平台兼容，因为它们不会改变第一版可行性判断或已被 A 排除。

领域分析应以 A 为起点，不是把 A 的列表复制进派单。

### 3. 内部材料是正式证据，不是背景资料

`系统机制总结.md` 提供了第一代真实运行的懒加载、角色 Profile、fast path、role memory、checkpoint 和失败反例。

这些证据必须与外部研究一样形成证据条目，并标明时间、适用性和不能继承的部分；不能只在模型头脑中作为“参考”。

### 4. 模型上下文与系统执行依赖必须分离

第一代盘点显示 validator、Schema、tests 和 fixtures 可能不被模型读取，但仍是运行机制。

第二代的上下文入口不应承载所有控制逻辑；版本检查、权限检查和产物校验应由确定性系统执行，避免把控制面重新注入模型上下文。

### 5. 普通 Web 检索不能冒充 Deep Research 路线

`02_ChatGPT外部检索_v1.md` 是当前 ChatGPT 会话通过普通 Web 检索形成的预跑材料。它有助于确认问题、信源和派单形状，但不具备本机制要求的独立 Deep Research 完整性，也不能与 Gemini Deep Research 做正式覆盖率测量。

正式流程是：

```text
ChatGPT Deep Research ─┐
                       ├─ 两份完整报告均返回 ─► NotebookLM 第三方匹配 ─► 合并方判断
Gemini Deep Research ──┘
```

本次已按该流程获得两份正式报告并完成 NotebookLM 匹配。

### 6. 外部派单必须指定精确文件落点

原派单只给出“输出文件建议”，没有明确：

- 仓库内完整输出目录；
- 精确回存文件名；
- NotebookLM 不支持 YAML 时应使用什么兼容格式；
- 每个待上传文件的完整仓库路径。

人类因此需要自行决定回存位置，并手工建立 Markdown 镜像。虽然本次处置正确，但说明派单接口不完整。

已裁决：所有外部研究派单必须包含 `output_directory`、`output_filename`、`output_format`、`canonical_or_mirror`、完整 `upload_inputs`、`upload_output_path` 与 `start_when`。不得要求人类推断路径。

### 7. 工具格式兼容镜像需要明确身份

NotebookLM 可上传 Markdown，但不能直接使用本次 YAML 输入。因此建立：

```text
00_挖掘目标与领域_v1.md
01_内部证据_v1.md
```

两者内容与对应 YAML 完全相同。

镜像不是新证据，也不是新的 canonical。以后必须记录它是 `derived_mirror`，并用内容 hash 或 Git blob SHA 检查同步。

### 8. NotebookLM 匹配没有完全满足原文定位要求

`06_NotebookLM_第三方匹配_v1.md` 已完成共同结论、分歧、单一路线项、三类清单匹配和内部证据对照。

但派单要求它逐条给出两份报告的精确原文位置；当前输出主要给出结论和列表，没有提供足够的段落或行级定位。

因此该文件当前只能作为：

```yaml
status: candidate_mapping
can_support_merge: true
can_replace_source_verification: false
```

合并方必须回到两份原始报告复核关键重合、候选同义项和来源独立性。

### 9. 两份正式报告的初步质量边界

- ChatGPT 报告包含完整机制清单、原子 evidence register、反证与检索边界，结构较接近证据包要求。
- Gemini 报告提供了 Landlock、受限网关、部署密钥风险、双轨内存等独特发现，但部分论断使用绝对措辞，且信源层级混有二手材料；这些内容需要在最终证据索引中降级或回查一手来源。
- 两份报告使用了部分相同原始证据，报告数量不能直接当作独立来源数量。
- NotebookLM 的“名称不同但可能同一机制”必须由合并方裁定，不能直接计入重合数。
