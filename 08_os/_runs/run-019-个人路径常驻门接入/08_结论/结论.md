# 结论

候选实现把个人路径校验接入 `.githooks/pre-push`，按每个 ref 的精确
`remote_sha..local_sha` 提交范围扫描；新分支使用远端 master/main 与本地头的 merge-base，
无法确定时 fail closed，不退化为全仓扫描。validator 新增 `--head`，因此读取的是实际要推送
的提交 blob，不会用当前工作树替代另一个 ref 的内容。

在当前 `patterns.json` 口径下，tracked 扫描得到 16 hits：`.ai/` 12、`08_os/` 4。
新增 `/mnt/<drive>/` 族识别出
`08_os/_runs/run-014-cosmic-ray安装对照验证/07_测试执行/validate_wrapper.py`
中的一处 mounted workspace 路径；run-014 是禁改对照基线，本任务只报告、未清理。

hook 决策表由 9 例增至 14 例，证明推送范围命中会拒绝、范围外历史命中不会误伤干净推送，
并证明 Python/validator/config 错误均 fail closed。validator 单测由 8 例增至 12 例，覆盖
Linux case-insensitive、两种 WSL mounted 尾部和精确提交 blob 扫描。

本守卫不是 access boundary：`git push --no-verify` 会完全跳过它；
`activation_travels_with_merge: false`，每个 clone 仍需配置 `core.hooksPath`；它只覆盖
`local_git`，API/connector 传输报告 `hook_guard: passed` 属于假回执。

当前状态是 `candidate_pending_human_publish_gate`。master 尚未推送；发布前须再次核对远端
head、提交范围、diff、mailbox 中立性，并在 Human 确认后才执行 fast-forward push，随后从
远端新 HEAD 读回四个 source mailbox 文件。
