# 双路线重合、差异与矛盾 v1

## 范围与身份

Human 已确认以下两个上传文件就是两条独立 Deep Research 路线的最终输出，文件名差异不影响身份：

- `01_ChatGPT_外部检索_v1.md`：ChatGPT 路线最终输出，结构偏摘要和综合判断；
- `02_Gemini_外部检索_v1.md`：Gemini 路线最终输出，包含较完整的 RQ、来源表与检索路径；
- 两个 Antigravity 模型家族的补充通讯理解实验；
- 对会改变 B 或测试结构的关键主张所做的一手来源核实。

两条路线均已返回。由于 ChatGPT 路线的来源表和检索路径没有像 Gemini 路线一样在仓库文本中完整展开，本轮只做语义重合、候选来源重合和冲突识别，不伪造精确来源交集或捕获—再捕获覆盖率。

## 两路共同支持的承重结论

1. **短消息与长产物分离可行。** 两路均把轻量消息索引与外置长文档视为可复用的工程模式。Microsoft Claim-Check 官方文档确认：大型 payload 可存入外部数据存储，消息中仅传引用 token，接收方按需取回。
2. **减少无关上下文具有价值。** 两路均认为全历史递归注入会增加成本并降低聚焦度；`Lost in the Middle` 的同行评议研究支持长上下文位置敏感和利用不稳健。
3. **直接引用闭包可能不完整。** 两路均指出发送方遗漏隐含依赖、历史决策或被替代文件时，按需加载可能变成静默上下文缺失。
4. **Human 中转是治理边界，不是可靠投递系统。** Human 可以控制披露、路由和越权授权，但不能保证消息不丢失、不重复、不乱序或一定被正确理解。
5. **按任务隔离通讯空间、区分 runtime 与 durable 有工程依据。** 两路均支持固定结构与任务结束后的有界清理，但普通 Git 删除不等于从历史、镜像或备份中抹除。
6. **不存在被证据证明的跨模型唯一最优文本格式。** YAML、JSON、Markdown 各有解析、可读性、推理和 token 成本权衡。
7. **语法正确不等于语义正确。** Antigravity Opus 实验出现“自然语言解释合理但精确字段恢复错误”，支持语法验证和语义逐字段验证分离。

## 路线差异

### ChatGPT 路线更强调

- 精确路径不等于精确内容身份；
- 幂等、重复转发和因果顺序风险；
- 普通删除不移除 Git 历史、fork、cache 或备份；
- 协议、schema、模型和 tokenizer 版本变化可能影响复现；
- Human routing 应视为 governance gate，而非 reliability mechanism；
- I-PASS 结构化交接研究是相邻类比，不能把效应量外推到 AI 通讯。

其中只有已经回到一手来源核实的内容进入承重证据；其余作为设计和测试候选线索。

### Gemini 路线更强调

- Two-Step Structuring：复杂推理与最终结构化通讯边界分离；
- Explicit State Machine Handoff；
- Context expansion / 索要更多引用；
- stale pointer、serialization failure、timeout cascade 等失败模式；
- TOON、JSON、YAML、Markdown 的 token 与解析差异；
- 自动握手、超时、重试、监控和垃圾回收建议。

其中不少建议属于自动多智能体或消息队列环境，与 A 已确定的 Human 手动中转、无自动轮询、低并发边界不一致，不能直接写入 B。

## 报告内部需要降权或拒绝的内容

1. Gemini 报告中的“约 35% 协调性崩溃”“降低约 70%”“Markdown 5%–15% 重试率”“TOON 节省 30%–60%”等数字，未由报告中可确认的一手实证来源稳定支撑；不得进入正式验收阈值。
2. 将行业博客或教程标为“独立首发来源”的条目需降权；它们可用于发现术语和失败模式，不能单独支撑承重架构裁决。
3. “必须保存 Chain-of-Thought 草稿”不成立。结构化格式税证据只支持不要让复杂推理全过程受严格输出格式束缚，不授权存储或传递模型私有推理过程。
4. “必须增加自动 watcher、自动完整性握手、超时重试状态机”与 A 的 Human 监督边界冲突；v1 仅允许模型在缺失引用时产生新的 `blocked` 消息或向 Human 请求补充。
5. ChatGPT 路线提出 receiver acknowledgment、actual recipient 记录和每条引用的版本验证；这些属于外部可靠性建议，但 A 已明确不建立投递/已读状态机、不记录 actual recipient、普通消息不强制 digest。B 只能在受保护动作或内容精确性实际承重时使用已有 Git head/blob 证据。

## 对 A v2 的影响

### A 无需重开

外部证据没有推翻以下已确认需求：

- Human 手动选择实际接收模型；
- 一个 task 一个通讯空间；
- 消息是轻量索引，长内容外置；
- 默认只读直接引用，不递归扫描；
- 消息不授予权限，越权行为依赖独立 Human 授权；
- 不建立投递、已读、理解、接受状态机；
- 本地与 GitHub 使用同一逻辑结构；
- runtime/durable 固定分区，由 Human 触发清理。

### B 必须吸收的限制

- 接收方发现直接引用不足时必须 fail-closed，并通过新消息请求补充，不得猜测；
- 对受保护动作，授权引用属于必读路径集合，测试必须单独断言；
- GitHub 上对内容版本敏感的引用应使用已有 branch/head/blob 身份，不额外发明消息 digest 体系；
- 清理只能声明删除固定 runtime 当前内容，不能宣称从 Git 历史或外部副本彻底擦除；
- 极简结构只约束最终通讯边界，不约束模型内部推理或要求额外保存推理草稿；
- Claude Code Desktop 与 Codex Desktop 的宿主兼容性仍需未来额度恢复后补测，但不阻断 v1。

## NotebookLM 决策

本轮不使用 NotebookLM：

- 两条路线的承重结论、冲突和来源质量差异已经可以直接识别；
- 关键项已经回到一手来源复核；
- ChatGPT 路线的来源复现限制不会因 NotebookLM 而消失；
- 新增上传、等待、下载和结果复核不会改变 B 或测试结构，EIG 低。

NotebookLM 不是阶段二完成的必经步骤，后续只有在语料规模显著扩大且机械匹配成为主要成本时才值得使用。

## 停止判断

- 内部补充实验：已饱和，不再追加同宿主模型。
- 定向核实：承重主张已有一手来源支持或明确边界。
- 开放发现：两条最终路线输出均已返回；由于结构不对称，不计算伪精确覆盖率。
- 理论饱和：两路共同结论与独立实验已覆盖 B 的核心对象、权限、引用、载体、生命周期和测试风险。
- EIG：继续追索更多来源或引入 NotebookLM 不会改变当前可行性判断、B 的承重结构或验收标准。

**结论：停止信息收集，进入阶段三结果建模。**
