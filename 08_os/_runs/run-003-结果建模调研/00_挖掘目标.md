# run-003 · 挖掘目标

**需求 A**：机制 3 第一版——由 A 与证据推出结果建模 B，且 B 的每条主张写明依赖哪条证据。

---

## 什么样的信息会让我们相信它可以实现

1. 存在**可操作的**"从证据推出结论"的流程，而不只是"让强模型想一想"
2. ACH 有实际可用的操作步骤（矩阵怎么建、不一致性怎么打分、怎么淘汰）
3. 有办法让"每条主张挂证据"成为**结构约束**而非文档纪律——
   即漏挂能被机械发现
4. 存在把 A 与证据映射到 B 的既有做法（不限于软件领域）

## 什么样的信息会让我们相信它不能实现

1. ACH 的实操要求人类分析员的判断，**无法交给模型**——
   那它就只是个思维框架，不是机制
2. "主张—证据"的挂接**只能靠自觉**，没有可校验的形式
3. 现有做法都假定**候选方案已经存在**（只做评估），
   而我们需要的是**生成** B——两者差距无法弥合
4. 证据到结论的推导本质上需要领域知识，**通用机制不存在**

第 3 条是我最担心的：**ACH 是评估框架不是生成框架。**
它回答"这几个假设哪个对"，不回答"假设从哪来"。
如果调研证实这个缺口无法填，机制 3 的形状要重想。

---

## 停止判据

EIG：能否判定"由证据推出 B 且可机械校验挂接"这件事可行/不可行。
能判定就停。

## 本轮捕获单位

**可实现性结论**（例："ACH 可自动化"、"主张-证据挂接可用 X 形式校验"），
不是文献数。
