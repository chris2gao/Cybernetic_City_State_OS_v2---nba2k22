# 改动前基线复现

本节记录执行方在创建任何 run-024 文件之前完成的只读复现；它不是改动后的自证。

1. 远端 `master` 与派单 base 均为 `a66ee671e47f3a90f3a108eb7531c7c84b0f9d37`；原 Codex
   worktree 停在旧 detached HEAD 且有 allowlist 外未跟踪内容，因此从精确 base 建立隔离分支。
2. `git log --all -- 08_os/_runs/run-024-通讯机制信息收集` 无输出，证明当时所有本地 refs 中
   run-id 未占用。
3. `A_通讯机制需求建模_v1.yml` 的 SHA-256 实测为
   `cfff1e32928db0c8aeb860260b8ed9c34e32994ab1b137e015dcafe5eac0f4a7`，与 Human 确认绑定一致。
4. `git ls-tree` 实测 `.ai/TASKS/` 有 5 个 tracked 文件；`.ai/TASKS/index.md` 只列出 4 个，
   漏掉 `context-stage2-local-partition-001.md`。因此“5 个已登记文件”必须拆成“5 个 tracked、
   4 个 indexed”，不能把 tracked 当 indexed。
5. `.ai/token_profile/` 只有聚合器、C0 chat 工具及测试；仓库内未找到可供 3–5 组匹配比较的
   `token_profile_run.v1` 记录。旧 handoff brief 也明确记载 category-level token metrics 为 null。
6. 旧实际 dispatch `e8ac5ba:.ai/SIGNAL_CHATGPT_v03-local-transport-and-role-memory-0001.yml`
   使用非 40 位 `source_head` 占位符、额外 `note`，且其 `brief_ref` 在该提交指向无关历史简报；
   后续 immutable lane completion event 才改用精确 source head 与独立 Human Brief。

这些事实构成本任务的基线问题：任务类型枚举不可复算、索引状态被混称、Token 成本没有匹配基线，
以及旧 pointer 工作记录存在 head/brief 绑定漂移。
