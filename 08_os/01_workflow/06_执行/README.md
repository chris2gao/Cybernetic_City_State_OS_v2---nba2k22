# 06 · 执行

按步骤实现，逐步验证。

## 核心机制

**判断 / 执行分离。**

> **判断交给模型，具体开发与执行交给确定性的 skill 和工具。**

数值计算、调用外部工具产生确定性结果——这类事不由模型自己做。

**这是"确定性"问题的真答案，比任何流程约束都有效。**
流程约束是要求模型不要出错；判断/执行分离是让模型不必在那些地方正确。

## 输入 / 输出

- 输入：步骤拆分、冻结的测试
- 输出：实现

## 上下文约束

执行实例（角色 e）拿到的是：**实现方案，以及只读的测试**。
它**看不到测试是如何推导出来的**。

篡改测试因此不是一条规矩，是**结构上的不可能**——会从削弱测试中获益的那个实例，
根本没有拿到能改写测试的上下文。

**但要记住这是加载纪律，不是访问边界。** 有 shell 的实例能读加载范围外的文件。
要让它成为真边界，用每角色一个工作树——本仓库已有 32 个已注册工作树，
机制现成，问题只是用不用。

## 分区盖不住的

**对测试过拟合。** 不碰测试，也能只满足测试的字面而非意图。
这不是篡改，是测试作为不完备规格的固有性质。

对策在阶段七：**审核核的是实现对 B 与证据，不只是套件绿不绿。**

## 待定
