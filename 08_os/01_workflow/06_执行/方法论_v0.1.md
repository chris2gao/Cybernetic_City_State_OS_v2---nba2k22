# 执行 · 方法论 v0.1

按步骤实现，逐步验证。

**本机制未做独立调研**，理由见文末。

---

## 一、核心原则：判断给模型，执行给确定性工具

> 数值计算、格式转换、结构校验、调用外部服务——**这类事不由模型自己做。**

**这是"确定性"问题的真答案，比任何流程约束都有效。**

流程约束是要求模型不要出错；判断/执行分离是**让模型不必在那些地方正确**。
前者对抗概率，后者移除概率。

## 二、谁执行

**沿用现有后端执行角色**（Codex / Antigravity），不新造。
活动裁决与理由见 `../../_dev/决定_谁执行_v0.2.md`。

`06_execution/` 的加载器因此是**加载一个外部代理**，不是驱动内部角色。

## 三、执行者拿到什么

**只给它做这一步需要的东西：**

| 给 | 不给 |
| :--- | :--- |
| 当前步骤的描述 | 证据集 |
| 该步骤对应的测试（**只读**） | B 的推导过程 |
| 上一步的产物 | 凭证选择记录 |
| 允许改动的路径 | 其他步骤的实现 |

**理由**：会从削弱测试中获益的那一方，不应拿到能改写测试的上下文。

### 但这是加载纪律，不是访问边界

有 shell 的执行者**能读没给它的文件**。收窄派单消除的是**污染和动机，不是能力**。

每角色 worktree/clone 只能改善 `workspace_partition`，不能把加载纪律变成真边界。
需要技术拒绝时，必须使用经允许/拒绝正负例验证的 ACL、容器、受限 tool root 或网关。
现有 DACL 证据仅覆盖受测正常读取路径，不能支持强隔离结论。

## 四、分区盖不住的：对测试过拟合

执行者可以**一个测试都不碰**，却只满足测试的字面而非意图。

这不是篡改，是**测试作为不完备规格的固有性质**，任何上下文边界都防不住。

对策在阶段七：**审核核的是实现对 B 与证据，不只是套件绿不绿。**

## 五、工具需求

按第一节的原则，本链条中已识别的确定性工作：

| 来自 | 工作 |
| :--- | :--- |
| 机制 1 | schema 校验、缺失槽位判定 |
| 机制 3 | 交叉一致性剔除、ACH 矩阵、挂接校验、敏感性测试 |
| 机制 4 | 测试溯源校验、变异测试（v2）、SMT 可满足性（v2） |
| 机制 5 | 采样结果的测试过滤 |

**这些工具本身需要被测试**——验证器有 bug 会安静地放行错误输入，
而这类失效没有任何东西会报警。

具体配置属 `04_skills_and_tools/`。

## 六、v1 不做的

- 不把工作树分区误称为访问隔离
- 不做工具的自动装配，手工配置
- 不做执行过程的实时监控

## 为什么没做独立调研

判断/执行分离来自人类的工程经验判断；执行角色已裁决；
上下文收窄的内容由机制 4 的测试冻结要求直接推出。

按 EIG：**再调研一轮改不了这些。**

**但有两处是真未知**：经技术拒绝验证的强隔离实现及其成本、
以及"过拟合测试"除了靠阶段七审核之外有没有更早的拦法。
后者若有更好答案，值得单独调研——**它现在的对策是事后发现，不是事前阻止**。
