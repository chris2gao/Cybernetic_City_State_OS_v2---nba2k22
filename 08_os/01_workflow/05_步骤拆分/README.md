# 05 · 步骤拆分

以 问题、信息、答案、测试 为依据，把问题拆成各个可实现的部分，
每部分可配对应的测试内容。

## 核心机制

**拆分 + 循环停止条件。**

停止条件不是新造的——**它就是阶段四的测试程序**。这是整条链闭合的地方：
信息越准 → 测试越准 → 实现越好，是真的因果，不是修辞。

## 输入 / 输出

- 输入：A、证据、B、测试程序
- 输出：有序步骤，每步可配测试

## 循环的正确形式

**不是"改了再试"，是多次运行、由测试筛出正确的那一次。**

用**采样加过滤**换确定性，而不是指望单次正确。这是模型的实际用法。

## 三个出口，不是两个

| 出口 | 何时 | 动作 |
| :--- | :--- | :--- |
| 通过 | 测试通过 | 下一步骤 |
| 重试 | 像实现缺陷，预算尚有余（三次） | 重跑同一步骤 |
| **失效** | 三次耗尽，或失败表明证据有误 | 向上退回并追加判定 |

**第三个出口让循环诚实。** 一个怎么都过不了的步骤，是关于产出它的那个模型的证据——
最常见是 **B 声称了证据并不支持的东西**，而这正是阶段三的证据依赖标注要暴露的。

三次耗尽后**人类介入**。

## 必须防的失败模式

**通过削弱检查来终止。** 重试压力下，让测试通过最省力的方式是改测试。
**一个除了成功没有别的出口的循环，会找到那个出口。**

所以：测试冻结，且第三个出口必须存在。**这不是警告，是这个循环必须被建造来对抗的东西。**

## 最小运行状态

`实现/最小运行schema_v1.yml` 与统一 runner 已实现步骤到冻结测试的绑定、1–3 次重试预算、
无环依赖和 `pass / retry / invalidate_upstream` 三出口。上游失效目标必须落在阶段一至四，
不能通过削弱测试或无限重试伪造完成。

步骤内容和拆分质量仍由模型判断；runner 只验证控制边界与可停止性。
