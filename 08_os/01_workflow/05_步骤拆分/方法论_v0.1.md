# 步骤拆分 · 方法论 v0.1

以 A、证据、B、测试为依据，把问题拆成可实现的步骤，逐步执行并验证。

**本机制未做独立调研**，理由见文末。

---

## 一、拆分规则：每一步必须至少被一条测试验证

测试在阶段四已冻结。**步骤的边界由测试决定，不由实现的方便决定。**

一个步骤若**没有任何一条测试能验证它**，只有两种可能：

- 它太小，没有可观察的变化 → 并入相邻步骤
- 它的范围划错了，跨越了测试的边界 → 重新划

这条规则把"怎么拆"从审美问题变成可判定问题。**拆完自检：每一步指向哪条测试。**

## 二、顺序：依赖序，不是难易序

先做被依赖的。**不要因为某步"容易"就提前**——早做的容易步骤如果依赖后面的结果，
会在后面被推翻，而它已经通过的测试会给出虚假的进度感。

## 三、循环：多次运行，测试筛选

**不是"改了再试"，是多次运行、由测试筛出正确的那一次。**

用**采样加过滤**换确定性，而不是指望单次正确。这是模型的实际用法：
单次输出的方差是固有的，而过滤器（冻结的测试）是确定的。

## 四、三个出口

| 出口 | 何时 | 动作 |
| :--- | :--- | :--- |
| 通过 | 该步骤的测试全过 | 进入下一步 |
| 重试 | 像实现缺陷，预算未耗尽（**三次**） | 重跑同一步骤 |
| **失效** | 三次耗尽，或失败表明上游有误 | 向上追加判定并退回 |

**三次耗尽后人类介入。**

### 第三个出口是让循环诚实的那个

一个怎么都过不了的步骤，是**关于产出它的那个模型的证据**——
最常见的情况是 **B 声称了证据并不支持的东西**，
而这正是 B 的 schema 要求"每条主张写明依赖哪条证据"所要暴露的。

失效判定要指向具体上游产物：`steps/`、`tests/`、`result/`、`evidence/` 之一。

## 五、必须防的失败模式

**通过削弱检查来终止。**

重试压力下，让测试通过最省力的方式是改测试。
**一个除了成功没有别的出口的循环，会找到那个出口。**

两条防线：

1. **测试在循环开始后冻结**——循环内改测试不是修复，是重新定义什么叫成功
2. **第三个出口必须存在**——没有"向上失效"这条路，压力只能往测试上泄

这不是警告，**是这个循环必须被建造来对抗的东西**。

## 六、v1 不做的

- 不做自动拆分——拆分由模型提议、人类确认
- 不做步骤间的并行调度，一律串行
- 采样次数固定为 3，不做自适应

## 为什么没做独立调研

前四轮调研已经把本机制的形状定死：循环三出口来自机制 1 的设计讨论，
测试冻结与"可失败"来自机制 4，失效向上退回来自 B 的证据溯源结构。

按 EIG 判据：**再调研一轮，改变不了这些已被约束确定的部分。**

**但有一处是真未知**：什么样的步骤边界最好——
"每步至少一条测试"是我推导出的规则，**不是调研出来的**。
若实测发现它导致步骤过粗或过细，这一条要重做，届时值得单独调研。
