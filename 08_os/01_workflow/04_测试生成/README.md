# 04 · 测试生成

依据 问题、信息、答案 三者之间的映射，生成有效的测试方法。

## 定义性规则

**测试由证据推导，不由 B 推导。**

从 B 生成的测试检验的是 B 的自洽性；当同一套推理产出 B 和它的测试时，
**测试因构造而通过，什么也证明不了**。

证据是第三方——A 没写它，B 也没写它——**所以基于外部事实的测试能够诚实地失败。**

同一批证据因此干两件事：证明 B 可行，供给测试必须展示的内容。

## 核心机制

**映射 → 测试的生成机制。** 需要强模型。

## 输入 / 输出

- 输入：证据集、A、B
- 输出：测试程序，**每条测试可溯至一条证据**

## 关键性质

**开发之前就能验证结果建模是否可行。** 不考虑作弊的前提下，测试通过即 B 成立。

这些测试随后成为**开发的边界与验证依据**——避免出现没有依据的实现。

## 已有材料（T2 调研中已收集，留给本阶段）

| 框架 | 用途 |
| :--- | :--- |
| **Daubert 判据** | 可测试性、同行评审、已知错误率、操作标准、普遍接受度——**测试本身的可采性** |
| R. v. Mohan / Kelly-Frye | 其他法域版本：相关性、必要性、执行者资质、程序遵守 |
| **FactScore** | 原子级事实精确度，可作为证据支撑度的度量 |

Daubert 在这里的用法要注意：它原本判的是**证据能否被法庭采信**，
借到这里是判**一条测试是否够格作为验收依据**。**这是类比，不是直接适用**，
使用时要说明借的是哪一条。

## 一条硬约束（来自执行循环）

**测试在循环开始后冻结。** 循环内改测试不是修复，是重新定义什么叫成功。
所以本阶段的产出必须在进入阶段五前定稿。
