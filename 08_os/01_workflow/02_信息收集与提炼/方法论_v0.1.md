# 机制 2 · 信息挖掘与收集方法论 v0.1

**核心思路：不在互联网上搜，在选定的优质信源上挖。**

先分析问题关联哪些领域，再找出这些领域的优质信源，然后在这些源上挖掘。
覆盖更全、效率更高，而且**信源清单是可复用资产**。

本文是操作规格。证据出处见文末，理由与实测见 `T1_MERGE_追问机制选型.md` 与本文第七节。

---

## 一、四步

```
1 领域分析  →  关联领域清单
2 信源枚举  →  信源清单（分级，可复用）
3 源内挖掘  →  证据条目
4 交叉验证  →  已验证证据集 + 可行性判断
```

### 第零步 · 明确挖掘目标

**挖的不是"关于这个问题的信息"，是"能建立可行性的信息"。**

两者搜到的东西完全不同。前者得到一堆背景资料，读完对问题更熟悉但判断不了任何事；
后者得到的是**能支撑或推翻"A 可以被实现"的依据**。

所以开挖之前先写一句：

> 什么样的信息，会让我们相信 A 可以实现？
> 什么样的信息，会让我们相信它不能？

**第二问必须写。** 只想着找支持证据，就是假说驱动检索退化成确认偏误的那一刻。

这一步同时决定了后面所有搜索的方向，也决定了停止判据里 EIG 的算法——
**"再挖一轮能否改变可行性判断"，得先有可行性判断这个对象。**

### 第一步 · 领域分析

针对需求建模 A，列出它关联的领域。不止一个，通常四到六个。

例：一个"追问机制"的需求，关联到——需求工程（学术）、AI 编程产品（业界）、
情报分析（方法论）、认知科学（理论）、开源社区实现（工程）。

**产出**：关联领域清单，每个领域一句话说明为什么它相关。

### 第二步 · 信源枚举与分级

对每个领域，找出该领域的**优质信源平台**，而不是直接开始搜内容。

信源类型至少覆盖：

| 类型 | 例 |
| :--- | :--- |
| 学术 | 论文库、会议、预印本 |
| 权威 / 标准 | 标准组织、政府机构、行业协会 |
| 业界 | 厂商文档、产品文档、工程博客 |
| 工程 / 代码 | GitHub 及同类平台 |
| 民间活跃 | 论坛、社区、个人实践者 |

**分级两个轴，不要合成一个分数**（NATO Admiralty System 的做法）：

- **信源可靠性**——这个平台本身的质量
- **信息可信度**——具体某条信息的可信程度

一个可靠平台上也会有低可信信息，反之亦然。合成一个分数会把这两件事搅在一起。

**每个信源必须记录它自己的检索限制**：索引偏向、返回数量上限、付费墙、时间覆盖范围。

这一条不是流水账。**源优先会让人以为"我检索了权威信源"因此更完整**，
而层内漏检一点没少。不记检索限制，这份多出来的信心就是没挣来的。

**产出**：信源清单——领域、平台、两轴分级、检索限制。**这是可复用资产，独立版本化。**

#### 基础信息库：一类特殊信源

有些领域存在**常设的、已策展的知识库**——物理等专业领域的知识体系，
公司或国家的历史信息库，行业的标准语料。

**判断要不要引入，是第二步的一部分，不另设阶段。** 但它与普通信源有三点不同：

| | 普通信源 | 基础信息库 |
| :--- | :--- | :--- |
| 关系 | 搜索 | **查询** |
| 可靠性分级 | 需评估 | **继承**，已策展 |
| 选择性 | 为本问题检索 | **不是为本问题组织的**，需自己找角度 |

**引入前必须做时效性检查，且越是组织性的越要做。**

物理知识库稳定，公司或国家的历史库不稳定——它会包含**已被推翻的决定、已过期的结构、
曾经为真的断言**。本项目今天实测的全部事故都是这个形状：
一份没有东西检查的声明与现实脱节。基础信息库因为"权威""已策展"而更容易被直接采信，
**它的过期条目比普通信源的过期条目更危险**。

所以：引入基础信息库时，同时记录它的**最后更新时间**与**已知的过期区域**。
拿不到这两项就降级使用，不要当作确定事实。

### 第三步 · 源内挖掘

在选定信源上做挖掘。分四段（自动化事实核查的标准管线）：

```
声明检测  →  证据检索  →  真实性判定  →  理由生成
```

**大模型挖掘为主**。但——

> **若某个信源重要而大模型访问不了，人工挖掘。**

这一条是硬要求。**信源的可访问性不得默默定义证据集的边界。**
模型够不着的东西不会消失，它只是不出现在结果里——而这与"不存在"在报告上长得一模一样。
访问不了就明确记为"重要但需人工"，不要让它无声脱落。

**优先首发原始信源**，避开二手报道偏见（CAAFC 的做法）。
证据按时间排序，便于后续动态纠错。

### 第四步 · 交叉验证

**双源规则**：有争议或关键的断言，必须有**至少两个独立且不结盟**的信源支持。

"不结盟"是关键限定——两个都转引同一原始报道的源不算两个源。
**主动剥离循环报道**：追溯每条证据到首发处，重复的首发处只算一次。

## 一之二、工具路由

**哪一段用哪个工具，是方法论的一部分，不是使用技巧。** 选错工具的代价是拿到看起来
合理但性质不对的产出——比如让源锚定工具去发现新领域，它只会说"材料里没有"。

| 任务性质 | 工具 | 为什么 |
| :--- | :--- | :--- |
| **不知道有什么**，要摸清一个领域 | Deep Research（ChatGPT / Gemini） | agent 式检索，能规划、迭代、跨源综合 |
| **语料已在手**，要找矛盾、单一来源、缺口 | NotebookLM | 源锚定，**源里没有就拒答**，不会补一段听起来合理的推论 |
| **目标明确**，单点事实、快速核实 | 直接用大模型搜索 | 一问一答，不值得开 deep research |
| **模型访问不了的重要源** | 人工 | 见第三步的硬要求 |

**两条实测出来的路由规则：**

**发现用 Deep Research，收敛用 NotebookLM。** 反过来用会浪费两者——
让 NotebookLM 去发现新领域，它受限于你给的源；让 Deep Research 去找矛盾，
它会综合出一个读起来通顺、抹平了分歧的答案。

**NotebookLM 是双模的，但两模要先后用不要混用。** 它的 Discover Sources 能自行搜索
填充语料，但那是**填充**，回答仍只基于语料。先受控语料问边界、再放开搜索做第二次抽样，
这样第二轮天然成为第一轮的独立抽样，可直接算重合度。混着用会失去"这个结论来自哪里"。

工具的具体提问结构与配额限制见 `DEEP_RESEARCH_使用经验.md`。

## 二、停止判定

用三个判据，**按信源覆盖率算，不按文献数算**。

| 判据 | 怎么用 | 阈值 |
| :--- | :--- | :--- |
| **捕获-再捕获** | 两路独立挖掘，比对重合 | 覆盖率达 95% |
| **理论饱和** | 连续 N 份新材料不再产生新类别 | 新类别归零 |
| **预期信息增益** | 再挖一轮能否改变结论或验收标准的结构 | 不能则停 |

**捕获单位必须先声明。** 同一批数据按文献算与按框架算，估计值可差 5 倍——
文献数几乎无界且无意义，**框架数或信源数才是决策相关的单位**。

**三个判据冲突时以 EIG 为准。** 覆盖率低不等于该继续挖：
如果再挖一轮不会改变设计，那就是该停。

## 三、并行是测量，不是保险

**同一挖掘任务派给两方，互不知情**——这不是为了保险，是为了**测量覆盖率**。

实测两次，两次都发现：**单次挖掘必然分层，而且从单次内部看不出来。**
T1 分成学术与产品两层，T2 分成分析方法论与取证/新闻两层。

因此并行是机制的默认形态，不是可选项。且必须要求双方：

1. **报告各自的检索路径**——分层一旦发生要能被看见
2. **同时报告"新增了什么"和"重合了什么"**——只问新增就拿不到重合数，
   而重合数是所有覆盖率估计的必需输入

第 2 条是本项目实测的设计缺陷：第一次并行只问了新增，导致无法计算覆盖率，
需要补问一次才拿到。

## 四、贯穿全程的记录要求

- **搜了什么、返回为空**——包括在何处撞上结果上限
- **每个信源的检索限制**
- **重要但访问不了的信源**——标记为待人工
- **每条证据的首发出处**——供剥离循环报道

前三条的共同目的：**让证据集的边界可见**。完备性无法从证据集内部证明
（明希豪森三难困境），能做的只有让不完整**可被看见**——
这是"能被注意到的缺口"与"不能被注意到的缺口"之间的区别。

---

## 五、产出

1. **证据集**——已验证，带出处与时间序
2. **可行性判断**——证据是否支持构建出满足 A 的东西；**可以是否定的**
3. **信源清单**——本次建立或增补的，作为长期资产沉淀
4. **边界记录**——第四节四项

产出 3 是这套方法论相对于"直接搜索"的核心增益：**一次建立，长期复用。**

---

## 六、生命周期

任务结束后判断：下沉到基础信息库，还是删除。
**中间过程文件不注册、不保留**——注册表描述系统，不描述流经系统的东西。

## 七、本规格的证据出处

| 内容 | 来源 |
| :--- | :--- |
| 先声明检索范围再检索 | PRISMA-S |
| 信源可靠性与信息可信度两轴分级 | NATO Admiralty System / AJP-2.1 |
| 四阶段挖掘管线 | 自动化事实核查（AFC）标准框架 |
| 双源、不结盟 | Two-Source Rule（水门事件起源） |
| 首发原始信源、时间序 | CAAFC |
| 可审计 / 可重复 / 可重现 | ISO/IEC 27037 |
| 捕获-再捕获 | Lincoln-Petersen |
| 理论饱和 | Glaser & Strauss, 1967 |
| 完备性不可自证 | 明希豪森三难困境（Hans Albert）；Popper 论基本陈述的武断性 |
| 必然分层、并行即测量 | 本项目 T1、T2 两次实测 |

**未采信的**：ACH（竞争性假设分析）与 Daubert 判据是两批材料的最大交集，
但它们解决的是**假设评估**与**证据可采性**，不是挖掘方法论，
留待结果建模（机制 3）与测试生成（机制 4）阶段使用。
