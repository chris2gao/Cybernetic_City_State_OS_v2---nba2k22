# 实现

本阶段机制的实现文件。规格在上一级 `方法论_v0.1.md`，这里放能实际执行和校验的东西。

## 当前文件

- `执行清单_v1.md`：第一版手工执行流程，当前内容版本 v1.2；
- `信源清单模板.md`：长期信源资产格式；
- `证据包schema_v1.md`：workflow 实例 `evidence/` 耐久产物格式与完成条件；
- `外部工具中转与Codex委派_v1.md`：NotebookLM 人工中转和 Codex 结构化委派契约；
- `运行验证补充_v1.md`：首个真实 workflow 与本机试验形成的强制运行规则。

## 该放什么

- 领域分析与信源枚举的可执行流程；
- 信源清单格式与以后提取的长期资产；
- 挖掘任务模板与工具调用；
- 外部 Web 工具的人类中转契约；
- 确定性本地工作的 Codex 委派契约；
- 交叉验证与循环报道剥离的具体做法；
- 停止判定的计算——重合度、Chapman 覆盖率、EIG；
- 证据包完整性 validator（尚未实现）。

## 不该放什么

- 规格与理由——在上一级；
- 某一次任务挖到的证据——放在对应 workflow 实例的 `evidence/`；
- 不承担状态、溯源或方法论证据的普通临时文件。

## 第一版要求

**接得上，不是好看。** 允许慢、允许手工触发、允许只覆盖主路径。

第一版至少要能：

1. 给一个已确认的 A，形成研究问题、问题类型和领域清单；
2. 读取内部指定证据；
3. 执行至少两条独立外部检索路线；
4. 通过 GitHub 任务包把 NotebookLM 纳入人工中转闭环；
5. 把适合的确定性本地工作形成可交给 Codex 的任务包；
6. 形成结构化证据条目、边界记录和可行性判断；
7. 让机制 3 不重读聊天即可开始 B 建模。
