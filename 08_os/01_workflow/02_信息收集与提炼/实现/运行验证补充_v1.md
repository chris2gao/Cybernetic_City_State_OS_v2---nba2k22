# 信息收集与提炼 · 运行验证补充 v1

本文件补充 `执行清单_v1.2.md` 与 `证据包schema_v1.md`。它记录 `context-management-mechanism` 在真实阶段二 workflow 和本机运行试验中暴露的强制规则。

## 1. 发现路线独立不等于证据来源独立

- 两路 Deep Research 可以互盲运行，但若共同引用同一论文、官方文档或公告，只算一个首发来源。
- 覆盖测量的重合单位由合并方裁定；发现模型不得自报真正交集。
- 最终证据条目的 `independent_source_count` 按首发来源计算，不按报告数、网页数或模型数计算。

## 2. 第三方语料工具只生成候选映射

- NotebookLM 等源锚定工具适合找共同项、分歧、单一路线项和候选同义项。
- 未提供精确原文位置时，其输出不得直接作为最终 source proof。
- 关键同义、冲突和独立性必须由合并方回到原始报告或首发来源复核。

## 3. 工作区组织与访问边界分开

```text
workspace_partition != enforced_access_boundary
```

- clone、worktree 和目录布局可以减少默认加载和 Git 状态混合。
- 同一不受限 shell 能读取兄弟目录时，纯工作区方案的访问边界验收必须判为 `failed`。
- ACL、容器、受限工具 root 或网关只能按实际正负例声明能力；不得从理论存在推成当前环境已可用。
- 边界测试必须包含授权读取、越界读取、权限恢复和清理结果。

## 4. 发布边界使用显式 allowlist

- 目录名 `private` 不提供任何 Git 发布保护。
- 角色 handoff 或结果发布必须显式列出允许暂存、打包或发送的路径。
- 禁止角色发布 helper 默认使用 `git add --all`、仓库根目录全量打包或等价宽泛发布。
- 验收必须在私有区放置 sentinel，并验证它不进入提交、handoff 或上传包。

## 5. 固定入口和 handoff 必须可验证

每个角色入口至少绑定：

- `task_id`、`role`、当前步骤与状态；
- 待办、阻塞和获准引用；
- 每个依赖的精确版本或内容哈希；
- 输出路径和 stale 检查路径。

恢复测试必须使用新进程或等价清空旧会话状态的运行方式。只声明“可以恢复”不算证据。

## 6. 失效传播属于确定性控制面

- handoff 和入口声明上游依赖；validator 比较精确版本或内容指纹。
- 上游变化后旧入口必须产生 `stale` 并停止继续工作。
- validator 不负责语义决定从哪个阶段重跑；该决定由规划角色承担。
- checkpoint 存在不等于依赖失效传播已经实现。

## 7. 失败和清理不得被最终成功覆盖

- 每个实验记录 `passed | failed | blocked`，不能只写叙述性结论。
- 预期负例可以使某个候选方案失败，同时仍形成高价值证据。
- 早期失败运行、修复原因、残留路径和清理阻塞必须保留。
- 最终成功运行只能证明修正版结果，不能抹除先前已发生的副作用。

## 8. 体积代理不等于模型质量

- 文件数、字节、字符和 token 可以证明默认输入体积变化。
- 不得由体积缩减直接宣称正确率提高、语义无遗漏或补充轮次下降。
- 真实任务测试必须同时记录任务结果、遗漏、补充申请、token 成本和恢复成功率。

## 9. EIG 决定是否转向运行或停止

- 覆盖率低不自动要求继续检索；覆盖率高也不证明完整。
- 当继续发现不再改变 B 的主要结构或验收标准时，停止宽泛研究。
- 当前最高不确定性若是操作成本、权限或恢复行为，应转成运行试验。
- 需要创建远程仓库、权限、密钥或其他保护资源的试验，必须单独取得具体授权；未授权时可作为显式未决项进入 B，不得伪造试验结果。

## 10. 阶段状态由耐久产物推导

阶段二只有在以下对象均可从磁盘读取时才能标为完成：

- 最终结构化证据条目；
- 可行性判断；
- 边界与信源使用记录；
- 停止理由；
- 机制 3 可直接消费的约束与未决项。

聊天总结、旧 run 记录或任务完成声明不能覆盖更新后的物理产物状态。草案仍写 `pending` 时，必须生成最终 canonical 或明确 superseded 关系后再关闭阶段。
