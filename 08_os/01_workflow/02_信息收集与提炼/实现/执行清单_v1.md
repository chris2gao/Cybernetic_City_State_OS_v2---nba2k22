# 信息收集与提炼 · 执行清单 v1

**第一版。允许慢、允许手工触发、只覆盖主路径。要求是接得上。**

规格见上一级 `方法论_v0.1.md`。本文是照着做的清单。

---

## 步骤 0 · 写下挖掘目标

开挖前先写两句，**两句都要写**：

```
什么样的信息，会让我们相信 A 可以实现？
什么样的信息，会让我们相信它不能？
```

第二句不写，就是确认偏误开始的地方。

## 步骤 1 · 领域分析

列出 A 关联的领域，通常 4–6 个，每个一句话说明为什么相关。

```
领域 | 为什么相关
```

## 步骤 2 · 信源枚举与分级

对每个领域，找**信源平台**，不是找内容。五类至少各想一遍：
学术 / 权威标准 / 业界 / 工程代码 / 民间活跃。

填 `信源清单模板.md`。**两轴分级不要合成一个分数。**

**基础信息库**（专业知识体系、组织历史库）在这一步判断要不要引入。
引入的记两项：**最后更新时间**、**已知过期区域**。拿不到就降级使用。

## 步骤 3 · 源内挖掘

按工具路由派活：

| 情况 | 派给 |
| :--- | :--- |
| 不知道有什么，摸清领域 | Deep Research × **2**，互不知情 |
| 语料在手，找矛盾/单一来源/缺口 | NotebookLM |
| 目标明确，单点核实 | 直接问大模型 |
| 模型访问不了但重要 | **人工，且明确记为待人工，不要让它无声脱落** |

**派单正文里必须带上步骤 1 的领域清单。**

不带，就等于让检索方**自己重新发现领域**——而那正是分层的来源，
也是这套方法论第一步存在的理由。领域分析留在自己手里，方法论的第一步就白做了。

同时要写明：**这五个是我们认为相关的，请覆盖但不要局限于此；
若认为某个其实不相关，请说明**——后者也是有用信息。

*（此条为 run-003 实测补入：派单写好后才发现领域清单只在 run 记录里，没进正文。）*

派 Deep Research 时，请求里必须含（见 `工具使用_DeepResearch与NotebookLM.md` 七要素）：

- 是**问题**不是主题
- 时间范围
- 信源优先级
- **报告搜了什么、返回为空、哪里被截断**
- **不要推荐"最好的那个"**
- **区分读到的与推断的**
- 并行时：**同时报告新增与重合**

## 步骤 4 · 交叉验证

- 关键断言要**两个独立且不结盟**的信源
- 追溯每条到**首发出处**，重复首发只算一次（剥离循环报道）
- 证据按时间排序

## 步骤 5 · 停止判定

先**声明捕获单位**（框架数或信源数，**不要用文献数**），再算：

```
N̂ = (n₁ × n₂) / m          覆盖率 = distinct / N̂
```

三判据取一，冲突时**以 EIG 为准**：

> 再挖一轮，即使拿到最理想的结果，能否改变可行性判断或验收标准的结构？
> 不能，就停。**覆盖率低不等于该继续挖。**

## 产出检查

- [ ] 证据集：已验证、带出处与时间序
- [ ] 可行性判断：**可以是否定的**
- [ ] 信源清单：已存档，可复用
- [ ] 边界记录：返回为空、检索限制、待人工的源、首发出处

## 收尾

本次证据判断：下沉到基础信息库，还是删除。
**中间过程文件不注册、不保留。**
