# 结果建模 · 方法论 v0.1

由 A 与证据推出 **B**——需求实现后是什么样，且**每条主张写明依赖哪条证据**。

**承重关系：B 实现即 A 满足。**

设计依据全部来自 run-003 调研，出处见文末。

---

## 零、B 有两半

**这一节是 v0.1 之后的补充，来自人类的一处关键澄清。**

| | 是什么 | 锚在哪 | 供给谁 |
| :--- | :--- | :--- | :--- |
| **结果形态** | 需求实现后是什么样 | A 的成功判据 | 判定"B 实现即 A 满足" |
| **实现方法** | 具体怎么做到 | 证据 | 阶段四（测什么）、阶段五（拆什么） |

**"根据信息依据构建实现可行性和具体的实现方法"——这个过程产出的正是后半。**

只留结果形态，**阶段五无东西可拆**；
只留实现方法，**没人能说清做完的是不是当初要的那个**。

实现方法必须带 `类型`（脚本 / prompt / skill / 配置 / 文档 / 流程），
**因为类型决定阶段四怎么测**。

## 一、三段管道，不是一个方法

调研的核心结论：**不存在单一方法包揽全程。**

```
生成候选  →  评估淘汰  →  存储校验
形态分析      ACH          结构约束
```

三段各解决一个问题，且**各自的自动化边界不同**——这是本机制的形状。

## 二、生成候选（形态分析）

**为什么需要这一段**：ACH 是**评估**框架，它回答"这几个假设哪个对"，
**不回答"假设从哪来"**。这是 run-003 开挖前就担心、调研后被证实的缺口。

**通用形态分析（GMA）** 的步骤：

1. 从 A 与证据中提取**离散参数**——问题有哪几个可变维度，每维有哪些取值
2. 构建 morphospace（多维矩阵）
3. **交叉一致性评估**——逐对检查取值组合是否互斥或矛盾，剔除无效组合
4. 剩下的组合就是候选 B 集合

**第 3 步是确定性工作**，逐对比较、无需判断——**交给工具，不交给模型**。
参数提取（第 1 步）需要判断，留给模型。

工程设计侧的等价做法（**公理化设计**的矩阵解耦、Pahl-Beitz 系统化分解）
逻辑相同：**用约束矩阵机械地生成并过滤候选结构**。v1 用 GMA，理由是它对
非工程领域的需求也适用。

## 三、评估淘汰（ACH）

**核心性质：用证据杀假设，不用证据挑假设。**

评估的是**不一致性**——哪条证据与哪个假设矛盾——而不是"哪个假设支持得最多"。
这个方向与"从证据推出 B"一致，也是它能对抗确认偏误的原因。

### 自动化边界（调研实测，两份一致）

| 交给工具 | 必须人或强模型做 |
| :--- | :--- |
| 一致性矩阵计算与记账 | **问题/假设的最初成型（framing）** |
| 诊断性排序 | **证据真实性与依赖性的底层研判** |
| 敏感性测试 | **最终裁定** |

**不能端到端自动化。** 这不是缺陷，是分工——
而本工作流本来就有人类确认这一环（阶段一的完成条件）。

## 四、存储校验（结构约束）

**"每条主张挂证据"必须是结构约束，不是文档纪律。**

### v1：schema 级校验

B 用与 A 相同的做法：结构化对象 + 程序校验。
每条主张必须有非空的 `依据` 数组，**校验不过就不是合法的 B**。

这与机制 1 同构，可复用同一套校验思路。

### v2：RDF 知识图谱 + SHACL

两份报告在技术选型上一致指向：把 B 表示为 RDF 图，
用 **W3C SHACL** 在**写入层**做拓扑校验，机械拦截**孤立主张（orphan claims）**。

SHACL 比 schema 校验多出来的能力是**图拓扑**：证据链、循环支撑、
"作为依据的那条证据自己有没有依据"。

**v1 不上 SHACL。** schema 校验已能拦住主要失效（主张无依据），
图拓扑问题在 B 还很小的时候不会出现。**先能跑。**

## 五、GRADE：不直接搬，只借模板

**明确的负面结论。** GRADE 底层极度偏好随机对照试验，
非医学领域缺这类实验，直接套用会**导致证据评级全军覆没**。

可借的是它作为**结构化决策记录模板**的部分——记录哪条证据、什么强度、
支持哪个结论——**不是它的证据分级标尺**。

改良版参考 Navigation Guide（取消"观察性研究即低质量"的铁律）。

## 六、需要的确定性工具

按"判断交给模型、执行交给确定性工具"的原则，本机制的工具需求：

| 工作 | 性质 |
| :--- | :--- |
| 交叉一致性评估（morphospace 剔除） | 逐对比较，纯确定性 |
| ACH 一致性矩阵计算与排序 | 纯确定性 |
| 主张—依据挂接校验 | 纯确定性 |
| 敏感性测试 | 纯确定性 |

**四项全部是确定性的。** 这一机制里模型只做三件事：
提取参数、成型假设、最终裁定——其余交给工具。

具体工具与 skill 的配置属 `04_skills_and_tools/`。

## 六之二、四项检查全过，不等于 B 成立

**它们确立的是"B 良构"，不是"B 正确"。**

| 四项检查能确立 | 它们碰不到 |
| :--- | :--- |
| 候选内部无矛盾 | **B 是否真的满足 A**——承重关系没有被任何一项触及 |
| 假设经受住了不一致性证据 | 证据本身是否为真 |
| 无孤立主张 | **参数提取有没有抓对维度** |
| 结论不过度依赖单条证据 | |

第三项最要紧：**形态分析只能在你提取出的参数空间里生成候选。
维度抽错，所有候选都错，而四项检查会全部照过。**

**B 是否正确，由阶段四确定。** 这正是"测试由证据推导、不由 B 推导"那条规则的意义——
用 B 自己的结构去验证 B，永远验不出维度抽错。

两个问题分开处理，是设计而不是疏漏。

## 六之三、工具本身需要被测试

四项确定性操作要交给工具，而**验证 B 的工具如果自己有 bug，
它会安静地放行错的 B**——这类失效没有任何东西会报警，
正是本项目反复付费的那个形状。

**待办**：为四个工具各建最小测试——喂进已知该被拒的输入，确认它拒。
优先级排在工具实现之后、投入使用之前。

## 七、v1 不做的

- 不上 RDF / SHACL
- 不做 ASPIC+ / Carneades 这类形式论证引擎
- 不做 GRADE 的证据分级，只借决策记录结构
- 形态分析的参数提取靠模型，不做自动化
