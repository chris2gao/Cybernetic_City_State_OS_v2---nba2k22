# 01 · 需求建模

把几句话的需求，通过持续追问，变成立体的需求建模 A。

**完成条件不是"问够了"，是双方陈述同一需求时指的是同一件事。**
这是全流程唯一一处人类确认属于结构性而非程序性——没有任何产物能独立证明两方所指相同。

## 核心机制

**追问机制。**

## 输入 / 输出

- 输入：人类给出的原始需求
- 输出：**A**，结构化，供下游证据收集与结果建模消费

## 已有结论（T1 调研，两路并行）

**选型：不用单一现成方案，三段拼装。** 详见 `../../_dev/T1_MERGE_追问机制选型.md`。

| 取自 | 用它的什么 |
| :--- | :--- |
| `github/spec-kit` `/clarify` | 交互形状——一次一问、依赖序、问题预算、**答案写回结构化产物**而非留在对话里 |
| 类型化 elicitation | 产出形态——停止 = **schema 在约束下填满**，产出类型化对象 |
| ReqElicitBench | 评测——问题效率、遗漏需求覆盖率、对话修复行为 |

**两路独立调研共同证明的空白**：全世界的追问停止条件只有四种——问满 N 个、
槽位填满、模型主观判断、用户喊停。**没有一种是认识论意义上的判据。**
