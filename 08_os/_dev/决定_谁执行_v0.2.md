# 决定 · 谁执行 v0.2（D2）

状态：**活动**。取代 `决定_谁执行_v0.1.md`。

裁决：沿用现有后端执行角色（Codex / Antigravity），由工作流收窄派单与加载面，
不为第二代 OS 另造执行角色。

## 边界语义

- 收窄派单与 clone/worktree 只属于 `workspace_partition`：它们组织工作目录、Git
  状态和默认加载面，不构成 `enforced_access_boundary`。
- 有 shell 或等价文件能力的执行者仍可能读取未加载的兄弟路径。真技术拒绝只能来自
  经正负例验证的 ACL、容器、受限 tool root 或网关。
- 现有 Windows DACL 证据只覆盖受测正常读取路径，未建立拒绝越界的强隔离结论。
- 执行者仍必须使用最小上下文、结构化显式 handoff 和精确 publish allowlist；这些是
  降低污染与泄漏风险的必要纪律，但不得被描述为访问控制。

## 下游约束

阶段六继续加载外部后端执行角色，而不是驱动一个新内部角色。活动导航、开发设计、
registry、boot 与 validator 只引用本版本；v0.1 只供历史审计。

任何未来强隔离实现都必须另行声明威胁模型，并通过允许与拒绝两类测试。仅增加
worktree、clone 或收窄提示词，不能把 `workspace_partition` 升格为
`enforced_access_boundary`。
