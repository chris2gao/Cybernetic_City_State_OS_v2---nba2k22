## 记忆单元 1：核心焦点球员核验（步行者 哈利伯顿事件）与洁净基线原则

- **历史背景与事故触发**：
  在早期尝试生成全联盟大汇总单一文件时，由于单文件数据量过于庞大，不仅导致模型多次输出超时与上下文挤压，而且在局部写入中意外污染了步行者核心焦点球员（泰雷斯·哈利伯顿 Tyrese Haliburton）的关键数值与属性，险些破坏整个 MyLEAGUE 的比赛模拟稳定性。
- **人类的关键警示与洞察**：
  > “核心焦点球员核验（步行者 哈利伯顿），这个如果没发现，那么我们的数据混乱直接就让游戏错误运行了。这个核心焦点球员核验，让我不用把所有数据看一遍就知道了问题所在，现在你给改了，我如果没有运气碰到新的数值错误，就无法发现可能存在的类似问题了。另外你重新生成的这个 json 文件是很大的，这就是我之前为什么要做每个球队的单独研究，就是生成的 json 很小，我让执行模型每次执行一个，不会出错。”
- **永久固化的业务准则**：
  1. **坚决废弃全联盟大汇总单一巨型文件**：绝不再次尝试输出千人级别大 JSON，坚决回归“一队一文件”的模块化架构；
  2. **锁定洁净原始存档基线**：游戏存档必须使用刚完成真实交易后、数值完全未受污染的纯净版本（如 `mc_haliburton_pristine` / `restart_validation_20261016` 镜像），所有后续更新必须基于干净基准做纯差分叠加；
  3. **焦点球星作为全联盟抽验哨兵**：每次全联盟任务发布前，必须以哈利伯顿、恩比德、约基奇、库里等关键大核为基准哨兵，抽检关键字段（Touch Proposals, Scoring Options, Key Tendencies），哨兵通过方可放行。

## 记忆单元 3：30 队教练设置“模拟侧重”底层 12 字节逆向与标准化装配

- **遗漏点与发现**：
  人类指出教练设置界面中存在专门的“模拟侧重 (Simulated Focus)”页面（终结顺位与 6 大攻防 POE 重点），在早期方案中被遗漏。
- **底层逆向突破与假数据清理**：
  - **历史误区**：早期 REA 发现中，前三项 `0x178 + i*2` 被误当成无关哨兵值并填充了假数据 `65535`，属于占位污染；
  - **实证确立**：主教练 `GAMEPLAN` 结构体（`stride 880`）的 `0x178` ~ `0x183` 构成连续 12 字节专属数据块：

    - `0x17E` ~ `0x183`：六大攻防 POE 侧重滑块（各占 1 字节 `uint8`，纯数字枚举 1..21）。
- **固化成果**：
