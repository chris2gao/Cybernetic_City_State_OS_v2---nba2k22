# Protocol 008: 异构模型动态路由与外包任务拆解协议 (Heterogeneous Model Routing & Task Delegation)

## 1. 核心理念 (Core Philosophy)
城邦的所有独立大模型在接收到宏观指令（Macro-Task）后，**严禁使用单一自身模型“大包大揽”地完成所有子任务**。
每个特工必须在规划阶段（Planning Phase）将任务拆解为多条细分流水线，并根据以下模型特性图谱，精准指派对应的模型执行特定的节点，以实现“算力成本极小化”与“认知深度最大化”的完美平衡。

---

## 2. 算力池认知图谱 (Model Cognitive Profiles)

### ⚡ 1. Gemini 3 Flash
- **城邦定位**：高并发搬运工、数据清洗排版员。
- **擅长发力区 (Best Use Cases)**：
  - **超长上下文数据提取**：瞬间消化 1M-2M 的生肉文档，提取关键实体。
  - **YAML/JSON 语法清洗**：极速修复或生成标准的结构化数据。
  - **语料转译与基础字典**：如建立基础词汇映射表、生活常识类比。
  - **Level 1-2 数学基础计算**：简单的分数、代数方程与格式化输出。
- **绝对避雷区 (Worst Use Cases)**：复杂代数逻辑闭环、长链纯数学证明、高维抽象概念（会产生“理直气壮的硬编幻觉”）。

### ⚡ 2. Gemini 3.5 Flash
- **城邦定位**：沙盒检察官、并发流控网关。
- **擅长发力区 (Best Use Cases)**：
  - 拥有比 3.0 更强的结构化理解力，适合做低成本的**代码语法自纠错测试 (Syntax Fact-Checker)**。
  - 实时数据流过滤与简单的逻辑分发路由。

### 🧠 3. Gemini 3.1 Pro
- **城邦定位**：后端算法架构师、严格代数法官。
- **擅长发力区 (Best Use Cases)**：
  - **复杂代码与工程重构**：能够毫无漏洞地编写成百上千行的工程架构代码。
  - **SymPy 纯代数逻辑闭环**：在处理偏微分方程、复变函数求解等硬核计算断言时，逻辑极其严密，绝不妥协（`v8_sanity_audit` 唯一指定模型）。
- **绝对避雷区 (Worst Use Cases)**：感性文学创作、极简主义 UI 设计（其思维偏向于刻板的计算机物理结构）。

### 🏛️ 4. Claude Opus 4.6
- **城邦定位**：首席哲学数学家、城邦最高裁决法官。
- **擅长发力区 (Best Use Cases)**：
  - **人类顶尖级别的降维认知**：如范畴论、哥德尔不完备性、朗兰兹纲领等纯数领域的哲学与物理架构的深刻隐喻（Mode B 巅峰高架首选）。
  - 处理极其复杂的伦理判定和系统级宏观架构评估。
- **绝对避雷区 (Worst Use Cases)**：格式化清洗、简单代码修补（极高的算力成本会导致系统瞬间破产）。

### 🎨 5. Claude Sonnet 4.6
- **城邦定位**：全栈前端极客、首席科普教师。
- **擅长发力区 (Best Use Cases)**：
  - **极客级 UI 设计与前端代码**：React/Framer Motion 等富有交互美学的代码实现。
  - **极其生动的人性化隐喻**：将冷冰冰的数学转换为如齿轮、流体等极具亲和力的“通俗教学案例”。
- **绝对避雷区 (Worst Use Cases)**：极重度的纯后台多线程并发架构推演（可能缺乏 Pro 的绝对刻板严谨性）。

## 3. 规划与派发规程 (Delegation Procedure)
在 `task.md` 或 `implementation_plan.md` 的制定环节，规划者必须包含如下标定：
```markdown
- [ ] 子任务 1 (数据清洗) -> **[Assigned: Gemini 3 Flash]**
- [ ] 子任务 2 (纯数物理隐喻构建) -> **[Assigned: Claude Opus 4.6]**
- [ ] 子任务 3 (前端交互呈现) -> **[Assigned: Claude Sonnet 4.6]**
- [ ] 子任务 4 (SymPy 断言测试网) -> **[Assigned: Gemini 3.1 Pro]**
```
严禁跳过此步骤！
