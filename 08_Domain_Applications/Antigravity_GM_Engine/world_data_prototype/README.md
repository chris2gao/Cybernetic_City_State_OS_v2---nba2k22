# NBA2K22 per-save world database — full-system development

Task: `nba2k22-world-data-full-implementation-01`. This is an **in-progress engineering candidate**: executable all-domain structure, historical adapters and an operator-bound live game/player adapter; full live-source coverage, whole-system acceptance and independent review are outstanding.

## Implemented structure

**Schema v16: 84 STRICT SQLite tables, 1,306 columns**. The 59-table approved provisional catalog is implemented with explicit game/finalization/source observations, team state, draft/prospect/waived state, stored opponent-plan/training/mentor observations, qualified settings words, complete native record-book observations, native stat/source/reference tables and distinct league-history/message/transaction/award-matrix/control observations. Typed contracts, badges, vitals, health and morale retain source-only native subjects as well as matched current canonical players. The original 16 table names and observations are preserved. See [table cards](TABLE_CARDS.md), [complete field dictionary](field_dictionary.json), executable [DDL](schema.sql) and its [catalog generator](schema_model.py).

The database covers player/team/staff identities, typed attributes and named tendencies, vitals/contract/health/morale/training, badges/play types, schedule/period scores/Box/season totals, coaching/tactics/mentors, finances/market/draft, actual settings/rules, awards/records/news, native source governance, external transaction/readback contracts and season closure. **Having a typed table does not establish the Native source for its columns.** UNKNOWN ranges and source gaps remain explicit. Contract field widths and stored base badge encoding now have current native metadata/code evidence; salary/sentinel/UI semantics and effective badge context remain separate.

One independent game save has one immutable fact-file identity. No cross-save ancestry or relation is introduced. Identity, event, observation, season totals, finalization and external receipts have different tables. SQLite FK/unique/check constraints and atomic units enforce ordinary paths. Unknown team names stay NULL; no invented team label or historical event is substituted.

## Commands

Increment 21 adds `refresh-world PID SAVE_DIRECTORY LOADED_FILENAME NEW_OUTPUT_DIRECTORY [--families FAMILY ...]`. One explicit invocation runs the thirteen existing source adapters serially: schedule/player context, organization, market, planning/training, settings, player contracts/base badges, player state, affiliations, skills, news/transactions, record book, honor stats and league history/awards. The default is all thirteen. A selected subset runs in dependency order. It does not install a scheduler or change the game.

Each source keeps its independently atomic capture unit, source time, completeness and Native gaps. The batch is not one global point-in-time snapshot. Before and after every source, the controller checks the unchanged operator save binding, freshly opens the explicit game process, checks PE build and process creation time, resolves current roots and checks the game-season year. No prior dynamic address is reused. Completed/annual-skip claims are matched to committed LIVE_READ units of the exact expected source and native year. Annual history/awards use their existing once-per-save/game-season-year guards; a skip retains its earlier source time.

The owner `refresh-report.json` records the requested plan, code hashes, per-source unit receipts, completed/skipped/failed/pending status and selective rerun families. Raw context/API traces stay in owner files. Failure stops subsequent sources and preserves already committed observations. An unverified failed adapter may have committed before its error; the report retains that uncertainty instead of claiming rollback. CLI exits2 for a partial batch. Inspect the child evidence and retry selected failed/pending families in a **new output directory** with a fresh PID/loaded filename. Existing output directories are never overwritten. Completion means the requested adapters finished or had a verified annual skip, not complete Native coverage or final acceptance.

Increment 20 makes `game DB GAME_ID [--unit-id UNIT]` return the latest single successful observation unit for that game. States, periods and both Box families come from that exact unit; a newer partial unit never borrows older rows. An explicit missing or out-of-scope unit returns no fallback. Available unit metadata and the append-only history commands support inspection of earlier captures. Selection compares timezone-normalized acquisition timestamps, including microseconds.

Game score output distinguishes literal state fields with their source provenance, sums of captured Native in-use rows, and canonical player sums qualified against the same captured Native window. `season DB SEASON_ID [--phase-code CODE] [--limit 1000]` and `player-seasons DB PLAYER_ID [--season-id ID] [--phase-code CODE] [--limit 100]` expose the latest totals per exact season/phase and, for players, exact team scope/team ID. Both commands and Game Box support the existing `--as-of` acquisition cutoff.

## Query, freshness and privacy

Increment19 adds `--as-of TIMEZONE_AWARE_ISO_TIMESTAMP` to public player/team/staff/prospect/game/schedule, Native source/history/award/settings/planning and export commands. This is a cutoff in **host acquisition observed_at**, not a native game date, event occurrence time or a claim about unobserved changes. Output wraps the normal result with `observation_scope`: normalized UTC cutoff, save/schema identity, committed successful unit count and a scope fingerprint. Python callers can use `observation_scope.query_at(DB, TIMESTAMP, 'player_card', PLAYER_ID)` or hold `observed_as_of(DB,TIMESTAMP)` around existing public query functions.

Each request freezes the eligible committed unit IDs once. Query connections open the original facts database read-only and apply temporary observation projections; no database copy, fact update or game access is required. Fields keep their own actual observation ages. Static player/team/staff/game/pick/season records are shown only when their public source evidence is visible, so a later-introduced identity is not exposed through an earlier card. Existing decoder/schema interpretations still apply; this is not a replay of a historical UI or a lifecycle identity certification. Ordinary roles still receive only controlled results, not a raw SQLite connection or owner source artifacts.

`history-page DB OBSERVATION_TABLE [--entity-key KEY --entity-id ID] [--limit 200] [--cursor-json CURSOR] [--as-of TIMESTAMP]` uses deterministic timestamp/primary-key pages and returns `has_more/next_cursor`. The cursor binds the cutoff, save/schema observation ledger and table/entity filter. Tied timestamps do not drop rows. If a late-committed/backfilled unit changes that ledger, resumption refuses a mixed view and requires a fresh page sequence; a held Python observation scope remains pinned. The older `history` command remains a bounded list. Historical JSONL export counts only eligible rows before applying its explicit no-truncation limit.

Player-card PlayType results now contain the last non-NULL observed value per ordered slot, preserving a prior slot's own age if a newer partial read omitted it. Native code0 (NONE) is an actual observed clear value; it is not treated as missing. All original slot observations remain in `history`/`history-page`.

`query.player_card` returns each field's last actual non-NULL observation with its own unit, timestamp and source grade. A newer partial record never refreshes an older field. `query.history` returns bounded history; `query.export_jsonl` streams all selected rows and refuses a limit that would silently truncate history.
