## ADR-01：One save = one SQLite fact database

- 一个真正独立的游戏存档对应一个**独立SQLite事实数据库文件**，含其自身赛季、实体身份、比赛、Native来源、当次观察、历史、荣誉与未来真实外部事务的账本契约。**不存在跨存档分叉/继承/合并、任何跨存档人物身份自动继承或引用**。
- 每个库内部记录稳定且不可变的`save_id`（或`save_uuid`）及真实游戏来源指纹、创建与Schema版本。游戏真实文件/存档与我们的SQLite事实数据库不是同一个文件；禁止把复制SQLite文件误当作世界线分叉。
- 跨档统一查询不是第一任务默认事务语义；每档独立连接/权限/备份/升级，必要的外部只读索引清单仅列数据库文件元数据，**不存跨档FK或制造跨档实体谱系**。
- Codex实现时须证明单库导入、事务、迁移与恢复不能把另一存档数据写入当前库；包括来源bundle引用、原生ID冲突与缓存键也须隔离。
- SQLite `PRAGMA foreign_keys=ON`、`PRAGMA integrity_check`、库的`save_id`一致性检查应成为工程默认验证项；准确物理主外键细节留给Codex工程实现，可依据真实Native身份调整。

## ADR-02：typed family snapshots + relational ordered/collection children

- 可预测字段较多且采集频繁的对象（尤其PLAYER Attributes、Tendencies）按**类型化字段族宽快照表**保存：一位球员在某个**真实、已成功验证的一致性采集单元**中产生一条该字段族的真实观察。字段真实值即使与旧观察相等，新观察也保留，不因值相等做去重。
- Badges/PlayTypes 为**独立关系子表**：徽章编码、级别、已拥有/未拥有、UNKNOWN 的区别和PlayType顺序不压成单个字符串；同样保留采集批次、原生来源与合法状态。
- 现有研究登记的字段、offset、bit编码/原生值域属于候选证据，不能据此假设全部可读或冻结无根据的`CHECK`范围。每个实际业务字段需Native来源、准确含义/类型/单位/合法取值域和来源等级；以后新增确证字段可用有版本的迁移增加typed列/子表。
- **部分失败**：失败字段或来源单元不会覆盖当前可信值或使`NULL`冒充真实游戏`0`；宽表的提交原子单元、字段有效性、新鲜度需要由Codex以可运行逻辑和证据保证。无证孤立缺失不得通过“空值填充”假装完成全组。
- **权限隔离**：球员隐藏Potential不能出现在普通GM可直接查询的宽表、导出或聚合投影中。现有V0.1将`potential_restricted_raw`列在普通能力快照表里，仅为早期设计候选，**必须在下版改为受控的独立数据范围或不授权收集状态**，具体安全实现由Codex给出并测试。
- 未来允许混合使用稀疏独立子表与原始来源元数据，但不得以“万能EAV/JSON”逃避已证真实字段的物理字段字典和业务含义。
