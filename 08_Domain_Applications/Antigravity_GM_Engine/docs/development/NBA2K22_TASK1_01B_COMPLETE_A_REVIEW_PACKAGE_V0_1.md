## 1. 第一任务与明确排除范围

交付能够按独立存档、赛季、实际时间、采集时间追溯的 **NBA2K22 PC 离线 MyLEAGUE** 文字和数值底层数据库。游戏真正存在、实际可读且获准保存的字段保留原生来源/显示值与必要转换。单存档可达100年；正常每赛季约20余次、通常不超过40次真实观察；全部获准的可变字段允许回看采集历史。不同游戏存档永不分叉、继承、合并或跨档复用身份。

**不做**：AI球员人格、GM交易谈判/选秀/教练决策、写入原版游戏程序、独立新高级统计指标体系、每36分钟类别全面建模、实时预测或独立维护的职业时间轴数据库、最终 SQL DDL（待03）。职业时间轴仅允许现有真实基础事实的普通关联查询。

## 3. 逻辑数据关系和不可变语义

- `save` 严格隔离 `season`、`player`、`team`、`staff`、`game`、`draft_asset`、`capture_run` 等逻辑身份。原生编号必须与其可靠游戏范围配合使用，绝不按相同姓名串联不同存档。
- `game` 属于某个真实赛季/游戏类别，并连接主客 `team` 和各有据的球员统计；`team` 与 `player` 在给定实际时间及观察时点关联归属；`staff` 到 `team` 的映射必须有证。
- `contract` 的可证事实、`transaction_fact` 的真实外部成交与 `execution_receipt`、`game_observation` 相互引用，彼此不冒充；若同一状态存在来源冲突，旧已确认事实不变，另立待Human决策记录。
- `current_read_view` 仅展示最近可靠观测值及其字段新鲜度；`capture_observation` 为真实当时的不可变读数；`finalized_season_fact`/已完成比赛结果等历史事实只追加；`historical_backfill` 只针对实际存在的遗漏，必须幂等；冲突使用 `PENDING_HUMAN_DECISION`。
- `intended_configuration`、`observed_game_configuration`、`configuration_reconciliation` 按具体开档上下文与世界线版本保留；Human审批的关键字段读回失败，则后续依赖操作不允许执行，但仍能继续只读诊断及真实异常采集。
- 多域采集由 `capture_run` 下的已证一致性单元提交；单元失败不能污染当前值，也不能将过期字段冒充本次读取。历史只追加，失败单元仍可保留异常。

## 4. 查询与导出结果的示意契约（逻辑字段，不是 SQL 列）

| 查询场景 | 最小逻辑输出内容 | 不得发生 |
|---|---|---|
| 单球员某次采集 | save、球员身份、实际字段名/原生或显示值、source、observed_at、freshness、权限及缺口 | 将隐藏Potential暴露或用旧值冒充新读数 |
| 某场比赛 | save、赛季、game、主客team、游戏事实状态、Box行、游戏可读高阶项、来源及可访问窗口 | 推造未读高级数据或跨档拼错game |
| 某球队某赛季 | 球队身份、真实名单/轮换设置、球队状态/统计、观测时点或最终赛季标记 | 把轮换计划当实际出场时间 |
| 开档验证 | save、开档上下文、worldline_version、目标字段与值、读回值、验证结果、关键级别、依赖阻断 | 执行器宣称成功就标记游戏验证通过 |
| 外部真实成交 | save、event、参与球队与球员/员工/资产、已证业务条款、写入回执、游戏复读与对账结果 | 把一次归属变化解释成未经证实的成交 |
| 历史事实 | 来源、事实真实发生时间、写入或补录时间、冲突/裁决链接、是否最终定稿 | 更新/删除原事实，或因存在争议静默替换 |

每项结果根据实际用户角色作最小授权输出，可对未知/不适用/未读取提供可理解的状态，但不得泄漏无权访问的原生数值。支持以存档、赛季、对象、时间、当前/历史/定稿状态做基本结构化筛选和导出。

## 6. 最低验收场景

1. 两个原生编号相同而不同存档的球员、球队、比赛和资产，历史/查询绝不串档；没有“同存档继承分支”概念。
2. 同一球员能力改变后，旧观察原样存在，新观察可靠来源可查；Q21字段失败时保留最后有效值及旧观测时间。
3. 历史事实冲突建立证据与`PENDING_HUMAN_DECISION`，不覆写；缺失旧事实只追加一次真实补录；进行中赛季不得定稿。
4. 一场旧比赛基本Box可查而高级数据无法可靠访问时，明确区分游戏值、转换值与无法读取缺口。
5. 非本次成功的训练/球队映射单元不能影响已验成功领域；当前视图不假装全批成功。
6. 游戏关键设置读回失败，阻断依赖的外部模拟操作而不阻止诊断和真实异常采集。
7. 外部交易事实及执行回执、游戏再观测可相互引用；重复登记幂等、未验证结果不冒充已成功写入。
8. 普通GM的字段查询、跨表联合和结构化导出不泄漏隐藏Potential。
9. 数据容量/查询策略需适合单存档100年及定期采集历史，物理性能测试方案待03提出。

**这些是目标验收场景，不代表现有软件已通过测试。**
