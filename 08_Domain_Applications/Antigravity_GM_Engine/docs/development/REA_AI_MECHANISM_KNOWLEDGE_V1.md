# AI角色机制知识原型 V1

本稿随Issue9工程原型交付。事实与未知由[机读卡](../../research/rea_ai_prototype/data/knowledge_cards.json)和[机制图谱](../../research/rea_ai_prototype/data/mechanism_atlas.json)持有，具体命令见[原型README](../../research/rea_ai_prototype/README.md)。不是当前可直接执行游戏的接口。

## Coach可读示例：防守重点

**机制是什么。** 游戏存在教练防守重点的原生字段。当前构建的元数据和枚举已核对：无偏好、保护禁区、中性防守、限制外围分别对应0、13、14、15。这里只解释菜单/数据中的重点标签，尚不知道比赛AI选择与应用它的完整过程。

**什么时候可能会用。** 外部教练若观察到对手内线威胁，可以提出“保护禁区”候选意图，并评估外围出手机会的风险。这是外部教练的篮球推理，不是已破解的2K原生选择算法。不同教练可以作不同判断，本原型没有用固定阈值假扮独立人格。

**什么已经知道。** 本轮当前PHI和IND教练的防守重点存值均为14，进攻重点均为5中性进攻，相关29份对手Gameplan投影稳定。原生位域与枚举通过REA核对。字段与对手计划的存在不是比赛生效证明；目前没有精确引擎AI/Human控制位来源。

**什么还不知道。** 不知道AI何时选择、谁读入比赛缓存、是否会被其他状态覆盖、真实效果多大，也没有取得安全原生Setter或完整Memory生效合同。短trace没有事件，只表示该窗口没观察到。

**如何行动。** Coach只能提交逻辑意图`COACH_SET_DEFENSE_FOCUS`，说明对象、场景与理由。当前真实游戏路由会返回NO_SAFE_PATH；fixture演示能运行，但不能据此直接写游戏。角色不会拿到裸RVA或指针。

**什么会使建议失效。** 构建/存档/场景变化、目标身份不清、控制旗标与AI假设冲突、知识来源不适用、只看存值却没有消费者证据，都需要重新核对。高置信度的字段读数不能替代未知的行为效果。

## Player与GM可以怎样使用其余部分卡

- Player/Coach知道导师徽章有进度和最后检查日期等研究接点，可以提出观察计划；CatchAndShoot成长阈值未知。比赛效果参数及MyCAREER Human升级点数不能变成自然成长条件。
- GM知道AI-AI交易的提议、评估、资格判断、commit和联动资产应分别验证。只有球员队伍ID变化不足以宣告完成交易；双方引擎控制状态未证或只有玩家确认分支时不能使用AI-AI执行资格。
- 角色知识投影按GM/COACH/PLAYER和模式筛选，内部研究字段不会因为逆向可见就自动下发。源数量和独立实证数量分开，旧run的多个文件保留共同origin。

三张卡都允许带UNKNOWN推理或提出请求，当前`can_execute=false`。真正具备可验证的游戏动作后端是后续技术资格问题，不能由模型自称角色、接口类存在或Human给了开发权限直接推出。
