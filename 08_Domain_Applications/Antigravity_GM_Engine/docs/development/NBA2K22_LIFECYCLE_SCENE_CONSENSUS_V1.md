## Q1 — 场景存档组织：Human 已批准 A

**Human 原决定**：`下一任务需求共识建模 Q1，我选择 A。请记录该项裁决，并继续下一个真正需要讨论的问题。`

**A 的已选含义**：从当前专用测试世界线开始，由 Human 亲自将 NBA2K22 游戏推进至后续研究窗口，在关键节点另存可回到的检查点；原则上用这条连续世界线验证对象状态、关系和历史跨阶段的变化，而不是默认使用互不相关的独立场景档。

**已继承而非新裁决的边界**：

- Human 负责游戏进度、检查点保留与主动触发模型采集。Codex 不自动操作、推进或覆盖游戏。
- **一档一库与原历史不可变依然生效**。同一世界线的另存检查点 **不自动等于数据库同一存档身份**；不同文件名、拷贝、分叉、回档的物理绑定和历史连续性须有 Human 场景 manifest 与来源证据，不因相同球员、游戏年份、文件名称就自动合并事实库。具体检查点恢复与绑定方案留待 Q2 / 01b / 原型设计明确，不在 Q1 偷定数据库规则。
- 既有 v24 数据库、原游戏文件及 Human 声明的 `nba2k22_test_01 / MyLEAGUE0003` 绑定不得被规划操作覆盖。v25 独立副本也不自动更换原 `save.json`。
- 研发 S1–S8 是取证场景，不是正式产品自动采集时间表；阶段采集不自动唤起 GM/Coach/Player。
- 当前仅记录 Q1；不开始 Codex 开发、Windows 机器操作或游戏 Native 读取。

**Q1 后续需要验证，而非已经证明的事实**：检查点前后真实连续身份、旧 Box 冻结、动态名册/奖项窗口、场景反复进入的读取行为，以及新的 Native 年度补录是否能在实际游戏证明。

## Q2 — 场景退出门槛：Human 已批准 C

**Human 原裁决（2026-10-26）**：「C · 风险分级制」——离开后可能消失的关键来源，必须优先取得最小可复查证据；其他复杂字段登记缺口，留待后续研究；Codex 提供场景取证状态，由 Human 决定推进还是暂停。

- 普通可后续再次读取的项目可以标注欠缺字段、原因、影响及下一触发时机，不因一个未解评分或字符串绑定自动无限卡住窗口。

- “最小证据”不等于字段完成验收；不得将理论上可能的重读或检查点回档视为已经取证成功。每个场景的具体必保项目在 01b/02 建模后确定，不由此处自行发明。

## Human 对下一阶段总目标的补充（2026-10-26）

Human 明确本轮需求不只是继续取证：**先对既有二十余轮/现有 v25 真实能力做重复开发排除；多场景查漏补全可读来源；在需求阶段分类只读事实、基本一次性配置和可经常修改的状态；随后建立统一采集与经授权写入的底层框架，支持按字段合法值域、Native 对象约束、前置条件、写后读回、失败恢复进行自动化批处理。**

这是 Human 已明确提出的产品目标，**但并未裁决“下一次单一 Codex 任务应同时实现全部功能”，也不是实时游戏写入授权。**

建议先用一套 01/01b 需求及原型成果统摄项目，再分有界工程交付：
1. **A：全生命周期 Native 来源覆盖与增量观察闭环**：以 v25 20 族 Reader 与现有槽位/历史工程为输入，先盘点实证，真正缺什么补什么；验证 S2–S8 及 S7 子窗口。
2. **B：字段读写能力、变更权威、频率和操作依赖契约**：只读终局比赛/荣誉；低频全局/世界线设置；频繁变化且可能同时被原生引擎和经批准外挂操作影响的球员/教练/球队状态。字段级说明是否可写、游戏何时自动变化、合法范围来源、依赖、敏感级别、是否需要跨字段/跨对象操作；“可写”绝不等于无条件任意改。
3. **C：统一 Native I/O/CRUD 与有界批量执行框架**：重用已实现的 SQLite/采集/审计/恢复，不造平行数据库；确定性定位、版本与旧值前置校验、权限白名单、计划/预检、分批执行、写后读回、幂等、冲突、失败/恢复与审计。计划、抽象接口和离线测试不授权现实游戏写入。
4. **D：受控实机写入及端到端大批量验收**：另获 Human 对测试档、字段族、影响范围和现场操作的明确授权才可执行；验证保存/重载、Native 反写/自然成长、关联副作用、批次失败和性能。不可承诺零风险或凭模拟断言全量成功。

**细节界限**：
- Human 所说“设置成熟后只设置一次”是**低频写入期望**；关键世界线/配置在新开档、真正写后和依赖模拟前仍须低成本读回核对。不能把“不再反复调参”误写成“永远不做防漂移验证”。
- 比赛与自然成长仍由 Native 引擎权威产生；普通角色不能修改原生终局统计；仅有明确授权的字段和状态转移才进入写操作许可清单。
- 用户预期批量数千/数万字段可靠执行，是工程目标，要求失败可报告、可定位、可恢复、可证明，而不允许文字保证绝对零错误。
- 旧研究文档可能有 RETRACTED 或候选身份，不能因含“可写”二字就升格为当前已证写入能力。
- 独立审核和 master 发布门禁保持；PR #8 的业务契约仍待正式主线整合。
