# NBA2K22外挂游戏循环与DEV29研究职责边界（玩家2026-10-21确定）

> **本文件是玩家确认的运行流程/研究边界记录，不是新Agent框架设计、行为规范、人格规则、API、数据库表或技术开发授权。** 一切角色人格如何模拟、谁能要求什么/拒绝什么、博弈规则与模型提示词由**未来独立开发任务**确定。DEV29/R04只提供真实游戏的知识与可供利用的输入输出原料。

## 一、每一轮外挂系统的六个独立模型执行步骤（权威顺序）

1. **采集模型**：从NBA2K22当前存档/进程拿到最新数据源，保存身份、游戏时间、来源与同批状态。职责是完整、可靠地观察游戏能产生的事实，不选择球队策略。
2. **数据分析模型**：把原始数据加工为真实比赛、球员/球队、训练、阵容、合同及其它模型要求使用的可追溯信息；不以赛季汇总代替逐场证据。
3. **独立教练模型**：作为每支球队实际教练，基于阵容、对手和比赛反馈开展执教工作，并**可以向GM提出**轮换、人员、交易或技战术等要求和理由。**教练人格与决策系统尚未开发**；DEV29仅研究可用于执教的原生设定、菜单、动作及数据。
4. **独立球员模型**：作为全部或部分现役球员，依据其未来的人格与生活模拟系统自主经历职业生涯、表达需要和选择。**球员人格与行为系统尚未开发**；原生球员属性、倾向、徽章、合同动机、伤病、训练等只是供该系统读取/可能作用的游戏信息与接点；DEV29不决定人格算法、不把每个角色按固定规则驱动。
5. **独立球队GM模型**：成为各支球队的经理，汇总教练与球员提出的要求，结合真实联盟状态、球队管理/文化、资金、阵容与个人目标进行球队运营决策。**GM是目前已有的主要人格/决策系统**；未来如何处理不同角色意见另由角色系统任务研究，不能在DEV29把互动示例固化为统一规则。
6. **执行信息汇总与执行模型**：汇总前面各队GM、教练、球员的**已确定拟执行事项**，按现有玩家批准/合法原生字段/当前存档身份/执行器条件交给执行模型落实并验证游戏真实改动。不同于前面各主体自主决策，执行模型不替主体重新规划人格和球队目标。只有游戏读回/持久性取证后才是实际更新的世界事实。

一个循环结束后，以游戏随后的真实比赛、数据和状态变化作为下一循环输入。**典型触发节点**：新赛季开始、常规每个月、交易截止日前一天、季后赛每一轮、休赛期。调度触发由玩家和后续独立流程系统控制；DEV29不自动创建定时任务或推进游戏。

**媒体与其它可能的未来角色**：可以研究所需公开数据、报道相关原生/外部信息及可用输出方式，但**媒体不是用户此次明确六阶段流程中的强制第七步**。加入流程须另行设计与批准。

## 二、DEV29现在到底交付什么（仅原材料）

每个研究主题必须从NBA2K20–23官方手册、玩家社区、攻略和游戏画面中尽可能完整地发现：

- **游戏机制与玩法**：菜单入口、名词含义、选项全集与取值、操作方式、不同机制怎样共同作用、模式/平台差异、模拟与真实3D比赛差异；
- **可读事实**：每场比赛Box、伤病和实时健康、合同、阵容、个人资料、属性、倾向、徽章、角色/训练及历史记录；数据是否动态、留存多久、游戏中是否公开；
- **可写动作/设置**：游戏本身允许改哪些、受哪些约束、修改后可能怎样影响原生游戏；原生候选是否已在项目Registry/读写执行器注册，技术证据如何区分；
- **素材索引与差距**：来源链接、实机截图/许可、版本、字段身份、社区争议、已验证/待认证PC22、当前是否采集/查询/执行，以及分别可能供Coach/Player/GM/Media使用什么资料。

**DEV29不交付**：人格模型、智能体决策树、目标权重、拒绝/同意协议、角色调度机制、模型之间的辩论程序、谈判引擎、媒体传播模型、固定剧情、程序化的涌现目标函数、数据写入代码。即使研究中用“角色可能这样讨论”举例，也只是为了说明**需要哪些数据和动作接点**，不是替后续系统设计行为。

## 三、R04审核后的具体澄清

[R04八个互动案例](catalogs/PLAYER_AGENT_INTERACTION_ATLAS.md)只是**游戏信息如何可能被不同未来模型利用的八组假设例子**；**不得**据此创建代理工作流、给Coach/Player/GM设置强制话语权或决策规则、自动赋予否决权，也不得把对话分支当真实2K22游戏功能。上面角色“可请求/可拒绝”只表示**可研究的候选能力或内容需求**，最终由独立人格/角色系统任务决定。

[R04 109项双语义侧表](catalogs/PLAYER_FIELD_DUAL_SEMANTIC_R04D_V1.json)有**72项静态原生Profile已登记字段和37项未映射研究候选**，不是NBA2K22全体球员字段全集，也不是109项当前游戏值已采集。R04另外保存99原生Tendency槽位（部分未解）、外部99标签、PlayTypes、Badge/人格动机资料，但未认证的映射和原生当前值继续待DEV28/Antigravity发现。目录中的`role_rights`/`action_rights`只是研究注释，**不是已批准的人格逻辑或法律性原生球员拒绝权**。

**受控写入安全底线保留**：玩家本人明确批准真实存档修改、合法交易/合同/字段执行核验，不准普通运营直接修改Ability/Potential/Badge作为增长手段；历史线特例仍需单独批准。这属于现有项目安全/世界线规则，**不是R04新增人格规范**。外部人格状态未来怎样存储和建立，由对应独立开发任务处理；目前不要为了模型研究就占用原生游戏字段。

## 四、R05起的研究纪律

R05研究财务/薪资帽/合同/选秀权/球探/员工/市场、球队经济与可用交易/签约操作：重点列出**游戏提供的具体数据、规则、玩家能怎么操作和实际设置选项**，而不是预设一个球员会选多少钱、GM会怎么谈判或模型多轮协商该如何编程。结果应交由未来GM、Coach、Player模型各自决定，研究者仅标注原生机制、项目外挂替代机制和UNKNOWN之间的边界。

R05研究要与K03/K12球员合同偏好互相引用，但不因此新增人格编排或报价权重系统。所有资料仍由网页版研究GPT逐轮提交GitHub，最终Codex只做研究材料、静态目录与DEV28技术接口的工程收尾；人格系统另立任务，不在R05/DEV29/DEV28中顺手构建。
