# 1984 届历史新秀名单重构与增强规范标准指南 (1984 Draft Class Standard)

## 一、 背景与架构机理

在 NBA 2K22 中，官方历史选秀名单（从 1960 年代至 2021 年）均具有预设且固定的内存组织结构：
1. **槽位固定性**：无论在任何 MyLEAGUE 存档中载入 1984 年官方选秀名单，游戏引擎都会将当届新秀载入固定的选秀池槽位（Slot 590 ~ 649）。
2. **官方预设球星分布**：2K 官方在 1984 名单中原生配置了 6 名拥有官方真实面补与身体骨骼的真实球星，固定占用 **Slot 590 ~ 595**：
   - `Slot 590`: Hakeem Olajuwon (中锋，面补 952，原生 213.4 cm)
   - `Slot 591`: Michael Jordan (得分后卫，面补 1759，原生 198.1 cm，216 磅)
   - `Slot 592`: Sam Perkins (大前锋，面补 1747，原生 205.7 cm)
   - `Slot 593`: Otis Thorpe (大前锋，面补 2019，原生 208.3 cm)
   - `Slot 594`: Kevin Willis (大前锋/中锋，面补 318，原生 213.4 cm)
   - `Slot 595`: John Stockton (控球后卫，面补 163，原生 185.4 cm)
3. **身体骨骼与体型绑定机制 (`APPEARANCEDATA`)**：
   - 2K22 的身高、体重体型在底层是通过球员结构体偏移 `0x90` 处的 64 位指针引用的独立外观数据块控制；
   - **历史踩坑教训**：若按照历史真实选秀顺位（如第 1 顺位奥拉朱旺、第 2 顺位鲍韦、第 3 顺位乔丹、第 16 顺位斯托克顿）机械顺序覆盖 Slot 590 ~ 649，会将鲍韦写入 591 槽位（覆盖乔丹）、将乔丹写入 592 槽位（继承帕金斯 2.06 米大前锋骨骼）、将斯托克顿写入 605/615 槽位（继承 2.18 米大中锋骨骼），导致严重的体型错乱！
   - **核心准则**：**严禁重排槽位顺序**！真正的选秀顺位取决于休赛期各队选秀大会抽签与选择结果，球探预估与选秀行情完全由球员能力值与潜力决定，与内存槽位序号无关。
4. **三基石不可篡改守则 (`0x88`, `0x90`, `0xF4`) 与日历模拟防闪退铁律**：
   - **事故排查教训**：在 1984 届巴克利（Slot 623）调试过程中，曾因输入切片长度不足导致装配器分配全零内存块，致使 `0xF4` 唯一球员 ID 被覆写为 0。游戏在读档时未报错，但在推进日历模拟（Calendar Sim）时，后台哈希表索引空指针导致游戏即刻闪退（CTD）。
   - **三基石定义**：
     1. `0x88`：头部微变形（HeadMorph）堆指针；
     2. `0x90`：体型外观（Appearance）堆指针（步长 0x40 字节）；
     3. `0xF4`：全局运行时唯一 ID（UniqueId）。
   - **永久准则**：今后任何年份（1984、1985 等）选秀名单注入或球员捏人雕刻，装配脚本必须从槽位原结构体读取并继承这三个字段，绝对禁止覆写或清零！
