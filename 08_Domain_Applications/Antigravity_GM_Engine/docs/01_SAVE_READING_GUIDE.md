# NBA 2K22 存档数据读取与标准化抓取操作指南 (Save Reading Guide)

本文档定义了如何从 **任意 NBA 2K22 存档**（包括辉煌生涯 MyCAREER、终极联盟 MyLEAGUE、传奇经理 MyGM 或自建名单 Roster）中完整、安全、有序地提取全联盟数据并建立标准化本地数据库的完整规范。

---

## 一、数据读取前置条件与核心生命周期

1. **游戏运行状态要求：**
   * `NBA2K22.exe` 必须处于运行状态；
   * **至关重要：** 必须先在游戏内**加载并进入具体存档**（或进入名单编辑器），因为 2K 引擎在主菜单时仅常驻基础物理与渲染模块，只有加载存档后，系统才会在堆内存中分配并填充 30 支现役球队与 450+ 球员的完整结构体。

2. **读取权限：**
   * Python 脚本通过 Windows 原生 API（`OpenProcess`, `VirtualQueryEx`, `ReadProcessMemory`）直接读取进程内存，无需挂载调试器，对游戏帧率零损耗。

---

## 二、标准化读取流程与执行时序（Order of Operations）

整个数据抓取引擎严格按照以下 **5 个标准阶段** 顺次执行：

```
[Phase 1: 进程探测与基址绑定]
       │
       ▼
[Phase 2: 现役 30 支核心球队定位与过滤]
       │
       ▼
[Phase 3: 主教练战术体系与风格画像抽取]
       │
       ▼
[Phase 4: 球队大名单与球员细分能力/合同解析]
       │
       ▼
[Phase 5: 本地关系型数据库持久化 (SQLite / JSON)]
```

### Phase 1: 进程探测与基址绑定 (Process Attachment)
1. 通过 Windows `CreateToolhelp32Snapshot` 枚举进程，锁定 `NBA2K22.exe` 的 Process ID (PID)；
2. 调用 `OpenProcess(PROCESS_ALL_ACCESS, False, pid)` 获取句柄；
3. 枚举模块基址，锁定 `NBA2K22.exe` 主模块基址（通常为 `0x140000000`）。

### Phase 2: 现役 30 支核心球队定位 (Team Array Scanning)
1. **内存特征锚点扫描：**
   * 在动态内存区（`0x7FF4E0000000 ~ 0x7FF4E8000000`）扫描步行者队名特征码（`Pacers` 的 UTF-16LE 字节序列：`50 00 61 00 63 00 65 00 72 00 73 00`）；
   * 通过 `+0x56` 字节处校验缩写 `IND`（`49 00 4E 00 44 00`），锁定球队结构体原点。
2. **步长遍历法（Stride Walking）：**
   * 2K22 现役球队在内存中为严格等长的连续数组，**步长精确为 `0x1258` 字节（4,696 字节）**；
   * 从锚点向前向后遍历各 35 个槽位；
   * **白名单过滤规则：**
     * 读取偏移 `0xCA8`（`UNIQUE_ID`，必须 `< 35`）；
     * 读取偏移 `0xEEB`（`TEAM_TYPE`，低 5 位必须为 `0`，即 `NORMAL` 现役球队，严防经典历史队和全明星队混入）。
3. **提取字段：**
   * 城市名（`0x2E6`）、队名（`0x2B4`）、缩写（`0x30A`）、总薪资（`0xCBC`）、实际发放薪水（`0xFF4`）、运营预算（`0x1014`）、更衣室气氛（`0xEC4`）。

### Phase 3: 主教练体系与建队哲学抽取 (Coach & Tactics)
1. 遍历对应球队的主教练结构体（`STAFF.json` 规范）；
2. 提取八大战术体系（偏移 `0x10A/0x10B`）：
   * `0`: 均衡 (BALANCED)
   * `1`: 铁血绞杀 (GRIT_&_GRIND)
   * `2`: 跑轰与空间 (PACE_&_SPACE)
   * `3`: 外线主导 (PERIMETER_CENTRIC)
   * `4`: 内线主导 (POST_CENTRIC)
   * `5`: 三角进攻 (TRIANGLE)
   * `6`: 七秒跑轰 (SEVEN_SECONDS)
   * `7`: 防守至上 (DEFENSE)
3. 提取建队偏好（偏移 `0x114~0x116`）：
   * `7`: 偏爱三分射手 | `9`: 偏爱高大化体型 | `11`: 偏爱硬汉防守 | `12`: 偏爱快攻推反击。

### Phase 4: 球队名单与球员完整画像抽取 (Player Profiling)
1. **球员结构体规格：**
   * 每个球员内存块精确为 **`0xDF0` 字节（3,568 字节）**；
   * 姓氏位于 `0x0`（UTF-16LE），名字位于 `0x28`（UTF-16LE）。
2. **能力值换算公式（AttributesValue）：**
   $$\text{2K游戏内评分 (25~99)} = 25 + \left\lfloor \frac{\text{内存原生值 (0~255)}}{3} \right\rfloor$$
   * 三分球（`0x426`）、中投（`0x425`）、近投（`0x424`）、外防（`0x42E`）、内防（`0x42D`）、抢断（`0x432`）、盖帽（`0x431`）、速度（`0x437`）、控球（`0x428`）、传球准确度（`0x42A`）。
3. **战术角色分配 (PlayType)：**
   * 读取偏移 `0x16A`：`PLAY_INITIATOR`（是否为主控球战术发起人）；
   * 读取偏移 `0x168/0x169`：4 个专属战术槽位（挡拆持球人 `4`、挡拆顺下人 `7`、定点射手 `13` 等）。
4. **合同与选项：**
   * 剩余年限（`0x32E`）、本季薪水（`0x1A4`）、各年递延薪资（`0x1A8~0x1B8`）。

### Phase 5: 数据入库与格式化输出 (Persistence)
1. 自动在本地 SQLite（`database/league_state.sqlite`）中执行更新操作；
2. 同步导出包含全景指标的 `database/league_snapshot.json`；
3. 供外部 GM 决策系统随时读取和运行撮合算法。

## 三、任何新存档的一键读取命令

以后无论你新建了什么 MC 存档、或者开了一个全新的终极联盟存档，只需保持游戏在后台运行，打开终端运行：

```powershell
python "e:\games\NBA 2K22\Antigravity_GM_Engine\src\dumper.py"
```

该工具将在 **2 秒内** 自动完成探测、扫描、解析与全套数据库建档！
