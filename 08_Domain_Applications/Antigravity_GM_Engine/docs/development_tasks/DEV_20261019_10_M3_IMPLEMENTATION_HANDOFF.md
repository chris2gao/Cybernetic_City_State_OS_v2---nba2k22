## 2. 首版必须选择的实现取舍

- 不做自动球员总估值/胜率引擎；事实、确定性指标、可解释角色与独立方案足够支撑GM判断。GM给出各队目标/条件，代码保存并校验，不替GM发明结论。
- 不创建新的全员JSON分页发布服务；继承M0本地有界查询，工作台按队存/按需读，GitHub精简导出。
- 球队累计统计投影是必须修补的实际接口缺口；合同常规/双向分类、持久身份、poss和FA资格仍可明确UNKNOWN，不以新增采集为M3前置。
- 两方接受与portfolio冲突是M3核心；不能用`accepted=true`或`no_conflicts=true`自报字段绕过实际条款和资产检查。
- 当前交易执行器的同队不重叠限制要体现在selected portfolio准备状态；不能把经济上可行误写为现有执行器已支持。
- 不建立CBA自动规则替代玩家外挂经济规则；M1情景/UNKNOWN原样消费。未定义硬预算不妨碍比较成本与机会，禁止声称可用额度。
- 三Web连接、现金、签约实机、额外比赛与保存重启继续延后；代码交付不以这些为验收门槛。

## 3. 直接相关验证集合

使用[设计场景](dev10_m3/DESIGN_CASES_V1.json)作为行为要求，不把它当已运行测试。实现时合并相近断言，每一类只证明本次行为，不回归整套采集/执行器。

1. **来源/计算**：两组明确合成累计数，验证区间比率重算、0样本和负增量局部UNKNOWN；同名/同face歧义不计确证成长。新增q_team_stats真实只读查询及旧快照缺来源路径。
2. **访问/覆盖**：缩短页返回但仍有cursor时继续读取；完整名单精确集合相等，人数相等但缺一人/替一人不通过；staff缺口只影响员工维度；pool筛选不冒称全池逐项已读。
3. **独立报价/组合**：双方同版接受可建立候选；反报价撤销旧接受；候选可重复竞逐但selected不可重复出售；同队不同笔、同字段不同目标与依赖动作给准确状态。
4. **状态/交接**：并发预期revision冲突保留旧版；final只有一个当前指针；M1/M2已有行仍可读。真实离线教练生成结果被引用，伪digest不被当生成回执；外部approved/EXECUTED声明拒绝。
5. **同批本地演练**：只用已有M02静态副本；30队事实/名册准备、GSW/SAS/OKC按需钻取，明确未填30队GM判断；合成30队研究fixture走完P1–P5及HOLD/冲突案例。开发样例只能放_exports，不能保存为本局正式策略或W03档案。

真实M02演练证明接口可读取/计算，不能证明已完成当前30队经营，也不能把历史GSW高工资自动设为争冠、SAS设为卖方、OKC设为重建。研究角色可以给三队开发候选对比，必须标DEVELOPMENT_CANDIDATE，不延伸到正式GM批准。无需再跑M1/M2全部测试；仅当共享Store修改影响既有读写行为时选最小相关存储检查。
