# DEV29 V2 — NBA2K20–23 终极联盟“游戏万事通”知识库：网页 GPT 多轮研究执行计划

> 2026-10-20 / 玩家最新组织决定。**覆盖 DEV29 V1 中的具体执行组织方式**；V1背景、K01–K11研究域及事实证据规则继续有效。PR #12 已确认合并后，此知识研究是 DEV28 全量输入/输出透明化开发的强制前置。此文档仅授权**研究计划、资料库骨架与交接说明**；真正连续的大规模网页研究仍由玩家新开 GPT 开发规划/研究窗口逐轮触发，不自动启动 Codex，不做游戏写入。

## 1. 责任人重排（区别于V1）

- **主责：新网页 GPT 的游戏机制研究窗口**。主动广泛搜索 NBA2K20/21/22/23（PC、主机本世代、次世代）官方指南、社区攻略、论坛经验、菜单截图与视频/图文指南；中文产出详尽、实用、可按需检索的游戏机制攻略。**以NBA2K22为目标游戏，系列其它作品通用经验有用则直接作为机制参考，精确菜单/原生字段另标平台**。
- **其它网页模型**：GM审核经营影响与可操作项，Analytics审核Box Score/高级统计的数据需求，开发规划模型维护总目录/验收与来源质量。可在不同窗口接力，不依赖单一上下文。
- **Antigravity**：后续针对确切游戏版本、菜单、数据结构和可修改性难题做只读内存和UI检验；必要时玩家按类型提供游戏截图。**不是DEV29全面检索的主责**。
- **Codex**：只在网页GPT完成**足够覆盖和来源整理的研究后**执行一次**有界的工程收尾包**（源文件链接/图片路径检查、机器可读索引生成/一致性校验、已有Registry/M0/DEV14/SQLite与机制能力需求对照、DEV28最小差距清单）；不派Codex搜遍论坛、整理上百篇攻略、凭技术工具猜玩法。
- **玩家**：确定研发优先级，偶尔提供网上无法取得的真实PC22截图；不承担基础游戏攻略解释任务。

## 2. 统一资料库

唯一新资料库根路径：`docs/game_mechanics/`。不另建与之冲突的百科副本，也不要把研究成果只存聊天窗口。

```text
docs/game_mechanics/
  README.md                       # 新窗口启动入口、用途和阅读方式
  PROGRESS.md                     # 分轮完成度、下一轮入口和来源/争议待办
  SOURCES.md                      # 每个可核验来源的source_id、版本、范围、链接
  MECHANISM_CARD_TEMPLATE.md      # 每个玩法条目的固定结构及证据边界
  guides/                         # 各领域可读“游戏攻略”与当前研究结论，按需创建主题文件
  visuals/
    README.md                     # 截图采集、出处、版权与图片证据规范
    EXTERNAL_VISUALS.md           # 网页截图索引：原始URL、图所在页面、描述、用途、版本
    approved/                     # 仅在必要、来源权利合适时保存用户自供/获许可图片
  catalogs/                       # 逐主题机器可读索引/GM可用值域（完成一批再创建）
```

这里是**结构契约**；文件夹只在有首个文件时建立，不必先创建几十个空文件或1000项`UNKNOWN`条目。最先保存的是`README/PROGRESS/SOURCES/模板/截图索引`。每个主题可采用`K01_GAME_LOGS`、`K04_COACH_PLAYBOOKS`等稳定ID，供GM、Analytics、Codex查找。

## 3. 每一张机制卡必须回答的内容

1. **WHAT**：游戏中这一机制的实际菜单、对象、显示数据、完整已证选项/范围，名称（原文+中文）；
2. **HOW**：正常玩家怎样操作、哪些动作会被AI覆盖/重置，是否与新档/换帅/赛季切换有关；
3. **WHY**：篮球或经营意义、用途、权衡；玩家常见误用、bug和有效攻略；
4. **INTERACTIONS**：与其它机制具体怎样共同作用（Playbook↔PlayTypes↔Run Plays↔Play Discipline，训练↔疲劳↔伤病↔员工等）；
5. **OBSERVABILITY**：游戏显示哪些动态事实、多久更新、跨赛季/逐场保留窗口、原生/派生/推断分级；
6. **GM & DEV28**：GM能凭它做哪些实际决定？要读哪些游戏数据？可选项是否已入源目录？缺少的内存来源/执行步骤交给谁？
7. **SOURCES/VERSION/EVIDENCE**：官方/社区/攻略/截图来源真实链接、版本、平台、可信度、争议和待PC22原生验证处。

**完整**是指所有关键菜单/统计/控制领域均已明确研究或明示UNKNOWN，**不是承诺穷尽未知私有引擎源码和1,392条战术的全部预览动画**。

## 4. 图文材料：先研究文字，不足才用截图，引用与图片本体分开

- 图文攻略如果已经可靠说明菜单和值域，就提取事实、写中文说明并登记原始链接；不用为了“看起来丰富”重复保存图片。
- 只有图片能证明菜单、选项、位置、步骤、统计标签时，必须建立截图证据：`visual_id/source_id/url/page_url/game_version/mode/platform/menu_path/description/observed_values/source_quality/license_or_permission/status/related_card`。同一张图片用于多个条目时复用`visual_id`。
- **不要擅自抓取并提交第三方带版权/水印的截图到公开GitHub**。优先保存原始页面地址、稳定图链接与准确来源；可以存用户提供的自己游戏截图、允许再分发的素材或明确获得许可的图片。允许外链图片作为研究定位线索，但必须保证即使链接失效文字卡片也有完整的菜单/机制说明。不去水印，不假装截图来自PC22。
- 游戏截图来源可能需要几十张，可以**按版本/菜单/类型/研究批次分批获取**，不要求玩家一次给出整个游戏所有截图；网页资料已足够的机制不应再要求用户截图。
- 视频指南如能读取字幕/说明，则索引`url/timestamp/observed_menu/steps/evidence_quality`；无法准确取得画面内容时不写“已看见”。
- 任何图片、官方手册、社区文本均避免大段转载。用自己的中文摘要、少量必要术语、链接/截图证据锚点，保持可追溯。

## 5. 分轮研究流程（新GPT窗口独立运行）

**各轮完整完成一个或多个主题并写GitHub，不在同一长运行中等待用户回复。** 推荐按下列顺序：

| 轮次 | 优先研究内容 | 核心交付 |
|---|---|---|
| R01 | **统计与比赛数据**：Game Logs、Schedule、每场球员和球队Box、Per Game/Per36/Advanced、Shot Chart、阵容和对手、数据留存与计算 | K01/K02完整菜单图谱、原生与高级指标分级、给Analytics的采集字段要求；不能只留赛季平均 |
| R02 | **教练与攻防控制**：Coach Gameplan、POE、ACE、防守个人/整体、Playbook、Freelance、战术12分类、真实联动、Play Discipline | K04机制卡与可操作项、战术命名和使用方法、对DEV28-1的原生缺口 |
| R03 | **球员与训练成长**：球员菜单/倾向/徽章/角色、个人/球队训练、疲劳、伤病、员工作用、自然成长 | K03/K06与训练/健康/动态来源缺口 |
| R04 | **经营和休赛期**：工资帽/CBA、员工、选秀球探、自由市场、交易、老板预算、联赛流程、自动化 | K07/K08/K09及虚拟GM已覆盖/不再复制的真实机制 |
| R05 | **世界/赛场设置与历史**：PC 3D gameplay滑块、联赛规则、统计/成绩口径、2023 Eras参考、赛季事件、存档覆盖与AI重置 | K05/K10/K11及版次差异 |
| R06 | **交叉关系/缺口复核**：补全此前资料不足的可观察菜单，整合“GM决定→证据→合法操作”表，删去重复/矛盾研究 | `FRANCHISE_MECHANICS_ATLAS`索引、`GM_DECISION_TO_EVIDENCE_MATRIX`、`FEATURE_DATA_CONTROL_MATRIX`研究版与明确待认证清单 |
| FINAL-CODEX | **仅研究完成后的Codex工程收尾** | 校验路径、图源、研究索引与数据合同，按现有Registry/M0/DEV14/SQLite提出DEV28按需求的具体实施清单；如需生成机器索引可写最小确定性脚本，不主动新增游戏采集或执行器 |

轮次为建议的**研究批次而非必须固定六个或一次做完**。可以按资料量拆R02-A/R02-B并增量更新`PROGRESS.md`，每轮写清：新知识、新来源、GAME_SETTING/OBSERVED_DATA/GM_DEPENDENCY、未证事实和下一轮入口。若运行中断，下一个窗口只需读README/PROGRESS与当前主题卡片。

## 6. 防止“万事通变成百科堆积”——每轮验收

- [ ] 真实资料来源已打开并有版本/模式属性，至少能追到正文或截图，不是只复制搜索摘要；
- [ ] 能回答该主题的玩法和对GM的实际意义，列出游戏菜单、可选项与联动；
- [ ] 明确`COMMUNITY_REPORTED / OFFICIAL_VERSION_SPECIFIC / PLAYER_UI_CONFIRMED / PC22_NATIVE_VERIFIED / INFERRED / UNKNOWN`，冲突有并列记录；
- [ ] 对比赛数据区分单场真实数据、赛季累计和高阶派生，不因玩家攻略有统计页面就声称生产SQLite已采到；
- [ ] 已将研究交付GitHub，链接可读，更新`PROGRESS`状态、SOURCES图源以及下一批；
- [ ] 如技术执行难以认证，不占用Codex做更多资料搜集，把疑问写入DEV28定向逆向清单即可。

**当前阶段的唯一目标是消除游戏玩法与资料视野的系统盲区，让GM真正知道所有主要“看得见、能设置、会互动”的功能。** DEV28再做透明化原生数据接入和审批写回。研究是GM能力的基础，不是额外游戏修改授权。
