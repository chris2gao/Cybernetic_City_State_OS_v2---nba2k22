### 二、各阶段逆向突破与实机证实

#### 1. R02-PLAYER-HISTORY：Player 生涯链与投篮图谱
- **生涯索引链实机验证**：
  - 成功在 Slot 1 现役球员结构体中定位 `+0xFC..+0x127`（共 44 字节，22 个 `uint16` 槽位）。
  - 对样本球员 0 解析出 5 个有效索引（`[6432, 574, 573, 572, 571]`），其余槽位正确填满 `0xFFFF` 哨兵。
  - 读取对应的 Slot 24（`PlayerStat`，步长 48 字节）行数据，观测到严格递减的赛季代号：
    - 行 6432：赛季代号 `0x7A`（当前赛季）
    - 行 574：赛季代号 `0x79`（前一赛季）
    - 行 573：赛季代号 `0x78`
    - 行 572：赛季代号 `0x77`
    - 行 571：赛季代号 `0x76`
  - 对样本球员 1 解析出 8 个有效索引（`[6433, 7056, 7055, 7054, 7053, 7052, 7051, 7050]`），赛季代号由 `0x7A` 连续递减至 `0x73`。
  - **结论**：彻底证实了 Slot 1 `+0xFC` 数组直接索引 Slot 24 作为球员逐年生涯统计的历史链路，彻底推翻了“Slot 39 是逐年生涯统计”的旧假设。
- **敏感字段保护与投篮图谱（Slot 26）**：
  - 球员姓名仅在 `+0x00..+0x40` 严格白名单化提取，严格封锁了 `Potential` 及其他敏感属性范围。
  - 针对 Slot 26（`PlayerShotChart`，步长 114 字节，1,023 条记录）成功提取了 3 条候选投篮切片，验证了 114 字节边界。

#### 2. R03-DRAFT-RELATIONS：选秀权所有权与关联令牌（Slot 42）
- **结构体验证（32 字节）**：
  - `+0x00`（8B）：当前拥有球队指针（指向 Slot 8 中的 Team 对象）。
  - `+0x08`（8B）：原始选秀权球队指针。
  - `+0x18`（4B）：关联令牌（Token）。
  - `+0x1C`（4B）：元数据位域（含 `bit17` 模式分支）。
- **简单选秀权 vs 交易选秀权对照**：
  - **Pick 0（简单自持）**：拥有者与原始者均为 `0x7FF4E7314210`，Token 为 `0xFFFFFFFF`。
  - **Pick 1（交易所得）**：拥有者为 `0x7FF4E7314210`，原始者为 `0x7FF4E7310B08`，Token 为 `0x02E0001F`。
  - **Pick 5（交易所得）**：拥有者为 `0x7FF4E7323088`，原始者为 `0x7FF4E731D4D0`，Token 为 `0x02E00015`。
- **球队身份与关联令牌（GetLinkedPick）**：
  - 解析拥有者球队指针在 `+0xCA8` 的 TeamID 为 `14`，其 `+0x00` 前 96 字节由 12 个 64 位球员指针组成（球队大名单）。
  - 实机验证了 Codex 反汇编的 `0x947330` 逻辑：当 `bit17` 置位时，系统生成 32 位关联标识，用于处理跨球队选秀权链接。
  - 在当前静态上下文中未观测到复杂乐透保护/交换条件触发，按规范如实标记为 `NOT_OBSERVED_IN_CURRENT_CONTEXT`，不虚构保护位掩码。

#### 3. R04-COACH-BOOK：战术手册 68 战术位与轮换假说否决（Slot 22）
- **结构体验证（360 字节，84 个手册）**：
  - `+0x54`：Lookup Key 字节。低 7 位（`& 0x7F`）依次呈现为 `0`、`1`、`2`。
  - `+0x58..+0x167`：连续 68 个 32 位战术 ID（uint32）。
- **边界与轮换假说彻底否决**：
  - 最后一个战术字 `play_words[67]` 结束于 `0x58 + 4*67 + 4 = 360` 字节（即偏移 359），无任何推测余量。
  - 3 本战术手册的尾部 4 个战术均共享相同的基础战术字（`0x45281adc`, `0x85476f25`, `0xc1c056fe`, `0x7945b809`）。
  - 彻底终结了“Slot 22 是 48 分钟轮换网格”的假设（48×5×uint16 需 480B，物理上无法装入 360B 记录）。

#### 4. R05-GM-CAP：DeadCap 伸展薪资与 TradeException 实体验证
- **Slot 61 DeadCap（136 字节，222 条记录）**：
  - 发现明确的多年度伸展薪资记录结构：
    - 条目 0：`+0x10`、`+0x14`、`+0x18` 连续三个 dword 均为 `92,857`（即每年 92,857 美元，分 3 年支付）。
    - 条目 1：金额为 `1,039,080` 美元。
    - 条目 2：连续两个 dword 均为 `8,856,969`（即每年 8,856,969 美元，分 2 年支付）。
  - 这与 NBA CBA 劳资协议中买断/裁掉球员后的 Stretch Provision 支付结构完全一致。
- **Slot 71 TradeException（112 字节，144 条记录）**：
  - 在 `+0x10` 处直接解析出 UTF-16LE 球员姓名字符串：
    - 条目 0：`"Theis"`（丹尼尔·泰斯交易产生的特例）
    - 条目 1：`"Porter J"`（小波特交易特例）
    - 条目 2：`"McGee"`（贾维尔·麦基交易特例）
  - 真实 NBA 交易特例实机证实，彻底澄清了历史将 Slot 67 误当 TPE 的错误。
- **Slot 35 彻底澄清**：
  - 证实为 `CustomUniformData`（4,020 字节服装资源），非财务总账；工资总额与奢侈税维持静态前端消费者汇总。

#### 5. R06-RECORD-BOOK：NBA 历史纪录簿分类与身份解构（Slot 39）
- **结构体验证（52 字节，69,040 条记录）**：
  - 前 20 字节：记录类别/球员名 ASCII 字符串。
  - 20~39 字节：球员姓氏 ASCII 字符串。
  - 40~43 字节：记录数值（float32）。
  - 44~47 字节：打包元数据（`dword >> 21 & 7` 为类别码）。
  - 48~51 字节：历史球员 ID（`uint16`）。
- **实测纪录簿榜首数据**：
  - 记录 0：`Wilt Chamberlain`，数值 `100.0`（单场得分历史第一纪录），类别码 `4`，历史球员 ID `15584`。
  - 记录 1：`Kobe Bryant`，数值 `81.0`（单场得分历史第二纪录），类别码 `4`，历史球员 ID `15761`。
  - 记录 5：`Wilt Chamberlain`，数值 `36.0`（单场进球历史第一纪录），类别码 `4`，历史球员 ID `15584`。
  - **重要发现**：同一球员（张伯伦）在不同纪录中的尾部 ID 均为 `15584`，证明此 ID 为 2K 引擎内置的全球历史球员字典编号，而非当前 Slot 1 的 3,390 现役球员数组下标。
