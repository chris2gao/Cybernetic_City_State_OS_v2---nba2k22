## 一、最低五轮硬规则

**标准模式**：完整30队严格分成**前三个深度研究回合，每轮10队**，并在全部30队有合格成果后，继续至少**两个专门用于决策及执行准备**的回合。合计**不少于5个实质GM审议回合**。不能以先前浅层30队扫描、自动摘要、未通过质量门槛的表格取代正式逐队研究。

| 实质审议轮 | 研究对象 | 必须交付 |
| --- | --- | --- |
| D1 | 10队（固定组A） | 每队完整诊断/原生教练现值核对/阵容互补与角色/轮换方向/真实合同选秀权/市场倾向/建议HOLD或调整，附机器可读工作底稿，GitHub归档 |
| D2 | 10队（固定组B） | 同样深度，追踪与D1交易候选的资产依赖与双边初步意向，GitHub归档 |
| D3 | 10队（固定组C） | 同样深度；至此30队**各至少有一个完整、有源可追的球队档案**，生成一次只读30队整合索引与冲突清单，GitHub归档 |
| D4 | 全联盟二次裁决 | 对全部30队跨队利益、对手战术、阵容拼图、候选交易报价/反报价、资源冲突、经济/健康/成长机会成本进行整体优化；仅在双方各自有理性理由并接受完全一致条款时提出双边协议，不因早期候选已发表就自动视为同意；GitHub归档 |
| D5 | 终局定案与执行准备 | 独立复核每项动作，形成**唯一最终提案**（批准/不执行/HOLD/有条件延后）、完整球员/选秀权及教练业务意图、各队保护红线、来源证据、Codex交接规范、玩家审批清单，GitHub归档；**无用户批准不得游戏写入** |

**质量优先改为每轮5队**：当需要逐人能力、阵容组合、教练原生字段、关键对手、实际先前交易与市场候选多方谈判等深究时，GM可主动将30队拆为**6个D轮，每轮5队**，其后仍须至少**D7全联盟裁决 + D8终局执行准备**，因此合计**至少8轮**。只有玩家明确允许才可再改变每批球队数；不能把“5队×3轮=15队”的半套工作冒充30队完成。每队可在原轮内深挖，必要时额外增轮，**不设五轮上限**。

**固定分组与不重不漏**（M02本赛季当前经营默认，后续节点可按业务需要先锁定名单并归档分组，但每队仅有一个主研究轮）：
- 组A：PHI、MIL、WAS、CHI、CLE、BOS、LAC、MEM、ATL、MIA。
- 组B：NOP、UTA、SAC、NYK、LAL、ORL、DAL、BKN、DEN、IND。
- 组C：DET、TOR、HOU、OKC、SAS、PHX、MIN、POR、GSW、CHA。
- 若5队模式，每组按列顺序一分为二，完成A1/A2/B1/B2/C1/C2，随后另开全联盟整合轮与终稿轮。不可随机跳队、漏队或重复计为两次进度。

**本轮判定标准升级（2026-10-18）**：每支球队的深度档案必须符合[GM_DATA_TO_DECISION_V1](manuals/GM_DATA_TO_DECISION_STANDARD_V1.md)与[机器可读球队合同](schemas/GM_TEAM_DECISION_CONTRACT_V1.json)。先有全大名单的`player_assessments[]`和球队累计/增量事实，再有六独立维度`D1_STAFF/D2_TACTICS/D3_ROSTER_USE/D4_MARKET/D5_ASSETS_AND_DEVELOPMENT/D6_TEAM_IDENTITY_AND_MONITORING`、至少两种有证据的方案比较、经营目标、风险和下一批复盘指标。**没有主教练/其他员工效应证据时可以合规`STAFF_HOLD`，不能编造员工评级、训练加成或直接换人。** 历史线人物能力定制完全不在本轮GM目标内，只允许正常交易/签约/教练模拟时代逻辑。必要时降为每轮5队，不降研究深度。相关人物定制只在独立[开发规划专项](../docs/development_tasks/DEV_20261018_HISTORY_GRAVITY_GM_BOUNDARY_V1.md)中讨论，需另批。

**2026-10-18 玩家最新经营内容纠偏优先**：仍严格遵守前三轮10队、后两轮跨联盟裁决与执行准备，**但研究核心必须是两批累计比赛数据的真实增量、投篮分布、对手攻防和球员能力 → 当前教练字段 → 可执行篮球方案**。不能为了填六维表格给球队编造从当前阵容倒推的“赢球文化/哲学”。员工评价明确延期至解决大文件/SQLite读取之后；此节点`STAFF_DEFERRED_BY_PLAYER`合法，非质量未通过。交易名单与未来资产照常研究；不能把尚未读取的球员池/员工池说成已分析。详见[最新数据决策规则](manuals/GM_DATA_TO_DECISION_STANDARD_V1.md)。

## 二、深度研究轮“质量验收门槛”：真正决策，而不是数据分析模型的模板重复

每队至少交付：
1. **可追溯真实现状**：比赛/累计与跨批增量严格区分；球队轮次、战绩、攻防、资金与合同字段来源；源批次一致且身份无混淆（MC/Haliburton身份需严审）。
2. **实际战力与内部调整**：核心+替补真实强弱和55项能力中的关键差异、位置/搭配、谁持球/无球、投篮/防守互补；未观测项清楚写UNKNOWN，不虚构OVR、逐场或伤病。
3. **教练剖析**：本队真实19项当前值中与决策相关者、Active/PreferredSystem、原生POE、Playbook、Freelance、BenchDepth、BenchUtilization，与球队特长错配的证据；指定对手18项仅在有明确目标时按owner文件读取；无因果证据不许声称胜率必涨。
4. **轮换与长期成长**：只能经AI动态轮换与BenchDepth/BenchUtilization间接影响使用；考虑核心负荷、年轻人场上成长机会、历史时代角色；精确个人分钟与训练全部交游戏AI，不追求精确操纵或训练外挂。
5. **合同选秀权与市场动机**：至少区分当前核心不可动/可议价/可交易资产；选秀权逐条实测当前持有与2022–24三年窗口；代理薪资、异常cash不当法定空间。
6. **本队独立决策与备选**：至少比较 `HOLD`、内部阵容调配、教练方案、交易或签约的成本/收益；给出适配目标、可被推翻条件、风险、证据不足状态。重建队长期争冠目标可以压过本期少数胜场。
7. **交易候选多方独立性**：不能因A队想要就自动断言B队已接受；中途可列`NEGOTIATION_CANDIDATE`，最终双边同价只在跨队复核D4后升为`GM_BILATERAL_AGREEMENT_PROPOSED`。资产不允许在多笔候选里无冲突地重复使用。
8. **归档可接续**：每回合保存日期、decision_id、source_batch_id、实际研究球队、10/5队完成清单、证据链接、HOLD/PROPOSED与尚未核实问题到GitHub；总论、细节和可机器处理意图分离。不得仅给30队一行摘要而标“深度完成”。

**质量不过关**：本轮不得标COMPLETE；标`REWORK_REQUIRED`并在后续轮或同轮补证，不计入3轮/6轮的完成数，必要时主动改为5队。没有有效结论也可以经详尽评估后HOLD，而非强制造交易/教练变化。

## 三、来源冻结、审批与游戏写入安全

- 一个GM节点的D1→D5/D8使用相同已审计`career_id/source_batch_id/game_date`作为事实基准；新的批次出现不能静默替换。玩家中途主动推进并重新采集时，明确标记`SOURCE_CHANGE_REBASE_REQUIRED`，复核之前已分析球队与交易资产，不需重复没有变化的推理，但不可当旧数据可直接写游戏。
- **前3轮不请求玩家批准游戏修改**，只完成详尽分析档案与候选。首次有资格形成全联盟双边议价、组合裁决与最后可批清单是在全部30队审查后。早期源字段目标可以作为非执行建议，但必须重新评审才能进终稿。
- D4确定性评价双边交易成立条件及教练动作风险；D5选择终稿。玩家可以在此时提出修改，若修改复杂允许增设D6+；不能为了赶时间跳过D4/D5。
- D5所称“形成执行”是**形成执行意图、经验证的交接文件及审批材料**，并非由网页GM自行改变游戏。交易需玩家明确批准具体双方球员、合同/选秀权流向后交Codex核验；教练则还须离线脚本生成完整`batch.json/dry_run.json/gm_verdict.json`与真实`batch_digest`、完整action_ids，向玩家第二道精确摘要审批后才能Codex受控写入。无法生成合法摘要时标`EXECUTION_PREPARATION_PENDING`，绝不能伪造digest或称已获执行授权。
- 严格区分`PROPOSED/REVIEWED/FINAL_PROPOSED/PLAYER_APPROVED/EXECUTED`状态。玩家批准与Codex执行是两个独立触发，不因D5结束就默认批准。游戏训练、精确分钟、五项Sim与普通球员能力/徽章/倾向仍禁直接写入。
- **每次回合必须由用户发起/继续**；不能要求用户重复贴原始M02数据，网页GM通过GitHub读取。阶段间的GitHub归档属于GM记忆工作，不触发游戏操作或下一轮自动运行。
