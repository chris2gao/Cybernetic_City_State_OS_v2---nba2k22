# 网页 GM v2.0 工作规程：外挂系统主导、赢球优先

本 SOP 的详细经营论证与可开发能力见 [GM_DECISION_MECHANISM_V2.md](GM_DECISION_MECHANISM_V2.md)。用户2026-10-17明确纠正过“原生NBA2K交易引擎为裁判”的错误：**外部两队GM自行协商，双方同意且玩家批准后交Codex执行；无需游戏CPU同意，不使用游戏交易难度/原生交易匹配做硬性成交闸门。** 士气与化学反应只是影响赢球的次级风险，不能因可能不满就阻止合理的轮换/交易。

**玩家后续2026-10-18修正优先适用**：保留已批准V3最低5轮结构，但每队分析首先按M01→M02实际新增比赛的场均净胜、球队与对手的eFG/两分/三分命中和出手分布，结合现有球员技术能力，对应当前教练真实字段、给出有依据的`raw_before→raw_target`候选；HOLD需用攻防真实数据说明。**不再从当前阵容编造球队文化、胜利哲学或员工能力作用。** 员工与球员全池巨大JSON/SQLite技术读取问题延后至本节点GM决策结束，当前全名单逐队JSON和教练/比赛JSON足够继续正常教练和市场提案；员工`STAFF_DEFERRED_BY_PLAYER`不阻塞研究。玩家批准实机修改后再由他实际进入游戏验证，不要求先证实固定胜率提升。

## 经营决策的权威内容标准：`GM_DATA_TO_DECISION_V1`

**2026-10-18玩家新增要求**：每队先**逐球员动态竞技与能力评估**，再从主教练/制服组、19项教练默认+18项针对对手OVERALL、阵容搭配与AI轮换、交易签约、资产与自然成长、球队赢球哲学六个维度推导经营结论。详见[GM数据驱动六维决策标准](manuals/GM_DATA_TO_DECISION_STANDARD_V1.md)与[每队结构化合同](schemas/GM_TEAM_DECISION_CONTRACT_V1.json)。不能把数据分析模型提供的模板总结直接当GM深度诊断。

**员工机制证据闸门**：本局员工8个岗位×30队已证实双向归属，但员工游戏效果/具体等级带来的胜率或成长影响尚未在当前PC局验证，员工雇佣/岗位变更也未完成完整写入验收。正式可提出`STAFF_REVIEW`，但不能把换帅直接当作已批准可执行教练战术修改。应先比较保留教练并调整合法战术字段的较低成本方案；有机制证据与安全执行器后才规划员工任免执行。

**历史线分工**：正常GM仅通过建队、教练、交易/签约尽量符合历史球队发展和王朝逻辑，但按本局真实比赛结果独立求胜；人物历史重力的例外定制、受控属性修改与开发验收交由开发规划基线按[独立历史专项交接](../docs/development_tasks/DEV_20261018_HISTORY_GRAVITY_GM_BOUNDARY_V1.md)负责，玩家单独批准后Codex才可按已验收执行器操作。普通球员自然成长由游戏AI，GM不直接修改、不将历史专项当常规交易附件。

## 1. 真实架构、权威与边界

- **游戏本体**：提供真实比赛、角色自然成长与可观测数据；不是外部GM交易谈判仲裁者。
- **Codex 数据基线**：在玩家触发后，采集/验证本局，维护SQLite、发布生产数据。
- **网页分析基线**：Python/SQL聚合有证据的量化分析，并按其职责发布 `ANALYSIS_ONLY`。
- **网页GM**：代表30支球队的独立GM，读取数据、做建队/战术/轮换/双边交易协商等**经营裁决**。
- **玩家**：批准明确动作和版本，控制游戏进程。
- **Codex执行基线**：只在获具体批准后修改**实现了受控执行器**的游戏数据，写后回读，分别报告内存/存盘/数据库状态。暂缺执行器就给开发基线，不能用旧脚本单一team_id写入假装交易。

权威顺序：玩家最新明确指令 > `config/gameplay_policy.json`、`docs/26_GAMEPLAY_ROLES_AND_WORLDLINE_RULES.md`及治理文档22 > 最新审计通过的本局数据 > 当前已批准经营决策 > 本 SOP / v2机制 > 旧概念方案。旧 `docs/04_GM_DECISION_ENGINE.md` 和 `docs/15_DATA_FEEDBACK_LOOP_AND_DUAL_SYNC_SYSTEM.md` 的原生CBA否决/单字段直接交易内容不得覆盖此处；`docs/16` 自标为历史已停用。

## 2. 一个赛季一个GM聊天；每个30队经营节点至少五个实质审议回合

**玩家2026-10-18最新决策（强制）**：原“每节点至多三轮/默认一轮定案”全部失效。遵守[GM五轮以上深度决策协议V3](GM_DECISION_ROUNDS_V3.md)；先将30队分3轮、每轮10队进行深度经营研究，30队完成并形成归档后再用至少2轮进行跨队利益整合与真正的最终决策及执行准备，**总计至少5轮，必要时更多，绝不以速度牺牲质量**。工作过于复杂时每轮5队，须研究6轮才能完成30队，然后至少2轮整合/定案，**总计至少8轮**。

**聊天生命周期**：一个赛季一个派生GM经营聊天。月度、季后赛和事件节点只在玩家明确触发后开启、逐轮继续。整季窗口不因本节点结束而自动关闭；从GitHub赛季索引及记忆恢复阶段。

- 深度研究分组（每轮10队）：A=PHI/MIL/WAS/CHI/CLE/BOS/LAC/MEM/ATL/MIA；B=NOP/UTA/SAC/NYK/LAL/ORL/DAL/BKN/DEN/IND；C=DET/TOR/HOU/OKC/SAS/PHX/MIN/POR/GSW/CHA。各轮必须保存有证据的各队深入档案和明确HOLD/候选，不靠原始统计榜单替代。
- 三组做完之后单独开一轮全30队整合：检验前几轮候选之间的冲突，独立代表双方GM谈判，对教练战术与阵容/轮换/成长风险做跨队比较；不能因为某队先提出报价就把对方视作已同意。
- 再单独开一轮终稿/执行准备：总览全部30队、确认唯一最终方案，交易与教练可用接口合法性、审批对象与程序生成器真实摘要。网页GM形成执行**材料**，**不**等于已经获批准或可游戏写入。
- 各轮绑定锁定`career_id/source_batch_id`；玩家中途更新游戏数据要显式核对rebase，不能悄悄用旧名单报价。每轮结束应更新赛季时间线、阶段档案与GM记忆；玩家下一次明确“继续”才开始后续轮。
- **当前W03/M02特殊情况**：旧R01一次性30队粗扫只是初步候选，未完成V3逐队研究。后续`W03/R02`组A、`R03`组B、`R04`组C、`R05`全联盟整合、`R06`终稿；若五队模式增加研究轮，并后移最终两轮。旧R01的12项教练+1笔交易**没有玩家批准、不得直接执行**，需全部重新论证。
- 数据分析基线、Codex、玩家审批属于不同职责，不能代替规定的GM实质研究回合。`NO_ACTION/HOLD`允许，但须有完整推理，不得填字数或造交易凑轮数。
- 如需更多深度，可在玩家触发下增加额外回合，不设置轮数硬上限。

## 3. 数据输入与30队研判

- 读取 `web_gm/memory/GM_CURRENT.md`、本 SOP、v2机制；从 `published/index.json` → 当前 `latest.json` → 批次 `manifest/source_coverage/league/calculations/draft_assets` 读取，按需深入球队、球员、员工和分析基线同批报告。
- 未观测时间为 UNKNOWN；`month_closed=false` 是检查点；赛季累计不冒充当月；NULL不等于0。没有伤病、OVR、轮换、士气、球员交易要求证据，不可编造。
- 数值用已发布确定性计算或Python/SQL工具，不能模型虚构。同队与同位置比较考虑游戏已认证55项能力、真实样本、效率、薪资、合同、战术、选秀权。
- 按V3和`GM_DATA_TO_DECISION_V1`，**每队对当前大名单逐人形成数据评估记录**，再完整审查`STAFF/TACTICS/ROSTER_USE/MARKET/ASSETS_AND_DEVELOPMENT/TEAM_IDENTITY_AND_MONITORING`六维；每队都生成可追溯、含真实证据/替代方案/下轮观测计划的深度档案，`HOLD`也须证明为什么不变。不把10队一行或数据分析模型模板当GM深度研究。
- 首要经营目标为本队**最大化赢球与长远争冠能力**。重建队可理性选择未来更高竞争力而非本月短期胜场。士气/化学反应若有实测信号仅作为赢球相关风险，不当作不可调整的理由；游戏内交易设置、CPU是否愿接受和交易难度不参与外部GM裁决。
- 既有 `config/gm_policy.json` 如标 `PROPOSED`，不能把其中阈值当玩家已经认可的强制指令；`docs/team_dossiers` 的NBA历史属REFERENCE。

## 4. 交易：双方独立GM真正达成同一份外部协议

1. A队主动需求或卖方挂牌；各自从本队阶段、竞争机会、阵容、薪资、真实比赛表现、未来选秀权和资产机会成本出发建立最低/最高理性接受条件。
2. 本轮内部最多三次精确报价/反报价，工资和资产差走Python/SQL，选秀权必须来自最新 `draft_assets.json` 的实际 `asset_id` 和当前持有人；只交易后三届已验证的简单选秀权。不能用同一球员/签位支持两笔同时执行的成交。
3. **A队愿意、B队也愿意且接受完整一致报价** → `GM_BILATERAL_AGREEMENT_PROPOSED`，向玩家**直接提交可批交易**；无重叠区间则 `NO_DEAL`，不让玩家代替模型逐轮谈判。
4. **外部GM意愿**既不声称现实球队同意，也不需要游戏内CPU同意。现实NBA的CBA薪资与合同知识可用于提高合理性，但除非玩家为外挂系统另行确定具体硬规则，**2K内置薪资配平、交易难度/交易规则都不能否决双方外部同意**。
5. 玩家明确批准 `decision_id/version/action_id` 后由Codex完成**全关联、可回读**的转队/资产更新；未有已验收执行器则 `APPROVED_BLOCKED_EXECUTOR` 并交开发基线。交易不授权能力/潜力编辑。
6. 如果有已验证球员提出交易申请 → 外部GM把其列入 `TRADE_BLOCK_CANDIDATE_REQUESTED` 并试着以球队利益达成交易；**挂牌到外部系统本身可以是经营状态，游戏内挂牌字段修改仍要特定批准**。只凭少分钟或主观猜测不算球员申请。

## 5. 轮换、角色、战术：事实支撑+胜率收益

- 读取当前球员累计出场场次/分钟/产出/能力/同位置候选、球队战绩与失分情况；尽可能获取**当前计划轮换分钟**、角色、伤病、真实球员交易请求和士气。
- 如果替代者在球队需要的方面有可信优势，GM可以先提出小幅试验性调整，再跟踪赢球与效率变化。**即使某球员士气下降，仍可优先提高胜率**；只有可量化或有明显证据表明不满损害整体表现才改变建议。
- 仅有累计场均分钟，不能假造原计划分钟；仅一两场不能判定被雪藏/要求交易。**玩家已实测：游戏AI经常重置/重新分配个人分钟，外挂精细写入容易被覆盖。** GM只分析实际分钟与球队整体轮换方向，不提交`player_id,minutes_before,minutes_after`式精准写入请求，也不要求Codex继续开发分钟锁定/循环复写。
- 教练操作只采用本项目最新V2接口、同批来源与合法原生字段字典；旧TEAM策略setter及历史`ON_BALL_PRESSURE`假设不作为教练操作入口。具体变更由玩家审批后交Codex。
- 改变之后对比独立、同口径的后续比赛数据；无证据不得声称已提高若干胜场。士气/化学反应只作为附加复盘项。

## 5A. 球队内部调配与教练：并列于交易的核心经营杠杆（2026-10-18玩家新规则）

**玩家经营经验：** 教练机制直接影响游戏比赛结果，也会影响球员随游戏AI发生的长期自然成长。此判断来自玩家和其他长期模拟终极联盟玩家的多赛季经验；纳入GM实际建队准则，但不把它误说成已经证实某一个raw教练字段会让球员能力固定增长多少。GM**不依靠外挂直接编辑普通球员能力/倾向/徽章**，成长仍交给游戏自身机制。

**训练功能永久不纳入当前经营范围（除非玩家日后明确恢复）**：当前外挂没有训练机制；训练交给游戏AI处理。GM不得为训练设定方案，不研究训练效益，不列训练数据/接口研发待办，不把任何训练操作伪装成19项教练设置。

每个30队节点必须并行考虑以下改善途径，而不是只提出交易：

1. **阵容搭配**：现有球员优势是否互补，外线/内线/持球/无球/空间/防守职责能否重新组合；分析球员角色、首发与替补衔接，优先识别“人才不合适”还是“现有人没有用好”。阵容搭配规划不等于已认证任意首发/位置写入接口。
2. **上场分钟与轮换**：基于实测球员出场分钟、真实样本、体力需求与年轻人成长机会，评估球队总体轮换是否过短或过深，以及哪些角色受益/受损；不提出需锁定的个人分钟数。已确认的`BenchDepth`是**轮换人数上限**、`BenchUtilization`是**替补使用率**，不能把它们当成某名球员的分钟设定。**精确上场分钟由游戏AI持续分配，并可能随时复写外挂操作；用户已决定不追求这类精细控制。** GM只借助已验证的BenchDepth/BenchUtilization和整体阵容/教练机制间接影响，不把个人分钟当待开发能力、待接口确认项或执行目标。
3. **教练与球队战术**：按最新同批`coaching/teams.json`与`field_dictionary.json`，检查19项默认设置，包括POE、双体系、Playbook、Freelance、联防、协防及替补利用；对实际重要对手按需读owner的opponent文件，设计18项`VS_OPPONENT_DEFENSE`/OVERALL整体方案。五项Sim禁止GM操作，Tempo含义UNKNOWN，不直接操作训练、个人属性或个人防守。
4. **必要的交易/签约**：内部调配和教练优化无法弥补人才硬缺口、合同风险或争冠窗口时再考虑交易及签约；双方独立GM仍须达成完整一致报价，玩家批准后交Codex。不能为了“先战术后交易”人为拖延明显有利的双边成交。

**短期胜率与长期成长一起评估**：过度消耗核心可能提高体能/伤停风险，缺阵损害后续胜场；合理角色、比赛机会与教练体系也可能影响自然成长。缺本局伤病、疲劳、轮换计划与长期归因数据时，风险和成长机会用定性描述，不编造伤病概率或具体属性加成。教练改变上场行为分布，与直接写入底层`tendency`是两种不同操作。

**逐队决策输出**：每队均需有`LINEUP/ROTATION/COACHING/TRADE/SIGNING/HOLD`的经营选择与理由；教练明确标`COACHING_PROPOSED`或`COACHING_HOLD`。仅有合规、同批、审计通过的教练来源才能给具体raw写入目标，否则标`COACHING_SOURCE_UNAVAILABLE`，仍继续用真实数据分析。执行时玩家批准完整`career_id/batch_id/decision_id/version/action_ids/batch_digest`，Codex按文档40校验并提交，GM不擅自推进比赛验证成果。

完整细节、风险和GM操作边界以[GM教练操作手册](manuals/GM_COACHING_OPERATIONS.md)最新修订为准。

## 6. 按球队经营、历史世界线与禁区

- 30队各自保有战略人格，优先当前游戏赢球事实，不强制复制现实联盟交易。
- `Tyrese Haliburton` 玩家保护资产，对本局的 `Ty Hali` 等同名克隆必须按对象位置和校验身份区分。其它保护与目标按用户实际批准记录判断。
- 普通球员能力、潜力、徽章、倾向、动作、性格编辑**永远不能作为一般经营手段**；历史重力仅限玩家专项批准具体值和恢复，MC成长继续 `DISABLED_DEFERRED`。
- 1984—2020历史新秀逐届循环，进度须玩家确认。2022—2024等游戏选秀权年份和历史新秀届次不是同一种日期。

## 7. 一次提交玩家的审批结果包

**仅在V3前3轮（或5队模式前6轮）深入研究全部30队、后续独立全联盟谈判与终局裁决完成后**提交唯一终稿：①确认独立双方GM同价同资产的一致交易；②证据充分的战术/AI轮换间接调节；③员工留任或已验证可执行的任免方案（不具安全接口时仅研究候选）；④签约/资产与风险；⑤每队的六维度理由和有据可查的HOLD；⑥行动集合、源身份和玩家审批闸门。前几轮的交易意向不得提前宣布可执行。

教练方案按 [GM 教练操作手册](manuals/GM_COACHING_OPERATIONS.md) 使用 `COACHING_BATCH_CHANGE`，逐队 HOLD/PROPOSED，默认设置与指定对手 OVERALL 分开。只使用实际已发布且校验为同批的教练来源，按需读取一个 owner 的对手文件。五项 Sim 不属于 GM 操作。开发中的白名单或未部署分支不能冒充 main 已有能力；玩家批准具体批次后才交执行角色，不能自动采集、模拟比赛或写游戏。
