# NBA2K22 外挂GM：数据 → 诊断 → 决策 → 执行 → 复盘（标准V1）

- `protocol_id: GM_DATA_TO_DECISION_V1`
- `owner: WEB_GPT_GM`
- `rule_origin: PLAYER_20261018`
- `status: GM_OPERATING_STANDARD`
- **目标**：30支球队均以本局可观测的比赛胜率、攻防与人员条件为起点，根据真实比赛结果、独立的篮球原理和争冠时间线形成经营选择，再独立由玩家批准执行。重建队以长期争冠概率为目标，不能简单把本月胜场作为全部目标。
- **完整经营轮次**：见 [GM_MIN_FIVE_ROUNDS_V3](../GM_DECISION_ROUNDS_V3.md)。本标准规定每支球队**要研究什么、依据哪些数据以及决策结果如何闭环**，不是要求一轮完成全联盟。
- **数据权威**：玩家最新指令与治理限制 > 最新同批审计通过的本局源数据 > 通过合理计算得到的分析 > 本局经验假设 > NBA真实历史参考。数据分析模型的报告是证据提示，不是GM判决。
- **严格权限**：调查、比较、提出候选不等于批准游戏写入；只有玩家批准动作与执行器受控验证才可能修改。训练与具体球员分钟交原生AI，普通能力/潜力/倾向/徽章不由GM改动。

## 最新用户纠偏：决策价值优先，取消无证据文化标签、员工暂缓（2026-10-18）

**优先级最高**：必须先从两批已验证的赛季累计得失分、2P/3P出手与命中、eFG、失误及已核验球员能力出发，确认球队要改善的可观测问题；再读取原生教练19项配置和18项对手OVERALL策略，提出最小的可执行raw字段调整、当前值、预期方向与反面风险。提案不需要先有统计因果胜率实验；玩家批准后的实际游戏观察是验证步骤。

- **不要从眼下已有球员强行包装“球队文化/赢球哲学”**：若没有来自篮球理论、明确历史实践或已证实的建队约束，不建立空泛身份/哲学标签，也不要求每队撰写同一类文化宣言。原结构字段`D6_TEAM_IDENTITY_AND_MONITORING`兼容旧版，但只填*可量化比赛目标与复盘指标*；`winning_philosophy`在机器Schema中已改为非必填。
- **员工/换帅业务评估本节点暂缓**：承认staff.json及完整player_pool.sqlite大文件需修复可靠读取路径；不能冒充已读或凭单个教练身份推员工性价比。继续用已可查询的每队roster JSON、真实比赛统计、教练当前值和合法draft_assets，正常研究交易/签约。本节点员工维度标`STAFF_DEFERRED_BY_PLAYER`，非漏项，不阻塞团队深度审议；技术访问修复安排完整GM决策结束之后。
- **砍掉低价值分析**：纯赛季排行榜、给球员能力摘抄一遍却不影响决策的文本、队伍口号、重复叙述30队通用事实、无凭据预测赢球提升百分比、不必要的标准化员工岗位猜测。保留足够的源字段和机器球员档案用于可追溯，但人读报告只讲改变结论的证据/备选/代价。
- 同赛季两次累计`season_totals.json`可直接相减得到可信**检查点间**新增进攻、防守投篮质量；进一步用`teams/<abbr>.json`逐人赛季累计差分核对人员。换队球员不得把跨队累计冒充新队贡献；`poss`未认证时不构造百回合净效率。
- R03实例：DAL原先14→13禁区保护被对手三分42.65%的实际数据修正为14→15外围限制；NOP本队近期eFG58.14%取消原优先加强进攻的旧结论，改先修对手两分60.4%。这是“数据改变建议”，不是为了建议找理由。

## 0. 何谓真正的数据驱动：不是“战绩差→交易”

强制按以下闭环组织每一项经营决定：

```text
玩家启动某检查点 → 锁定存档/时间/最新可信批次
  → 逐球员与球队近期表现诊断
  → 整体阵容、健康（已采集时）、合同、资产与已观察的教练战术评估
  → 从净胜分/eFG/两三分和对手命中结构识别可观察的赢球障碍
  → 归因候选：缺人才 / 人才未用好 / 主教练或制服组错配 / 对手错配 / 样本不足
  → 并列比较：HOLD、内部角色与轮换调整、教练原生攻防设置、交易/签约；员工评估暂缓
  → 10队/5队逐轮留下深度结论；全联盟完成后再独立两轮双边协调+最终裁决
  → 生成批准清单（必要时由确定性程序生成真正原生执行批次/digest）
  → 玩家批准 → Codex独立只读预检、受控执行和回读
  → 玩家自行推进比赛与更新数据 → 下一检查点比较实际变化 → 更新经营判断
```

任何一次未实际执行的方案都不能记录成`IMPLEMENTED`，任何一次游戏自动成长也不能归功于未经隔离辨识的单个教练字段。

## 1. 第一层——动态事实与逐球员评估：GM必须自己看

### 1.1 先确认事实口径

- 来源三元组：`career_id/source_batch_id/game_date`，`source_coverage/audit`。当前赛季累计、两次同赛季累计快照的**真实增量**、近N场逐场记录（仅在确实采集时）须分别标记；不得把M01→M02差分称为“12月整月”或在无逐场源时发明关键球回合。
- 球员的**当前球队归属**不能证明其本赛季累计个人数据均在该队取得。交易/转队时需单独`PRE_TRADE_CUMULATIVE`或`POST_TRADE_CONFIRMED`状态；后者若无队内逐场或时间戳证据，一律`UNKNOWN`。
- 身份：名称、`face_id`、局部`pool_slot`不能独自视作永久球员ID；重复克隆/玩家主角必须原源核实。NULL是未知，不是0。
- 赛季进攻效率、命中、失误、篮板使用现有源真实计算；`poss`尚未认证为标准回合数之前不得虚构百回合ORTG/DRTG或量化固定胜率。
- 球员战术体系、实际出场分钟、55项能力、合同可用即用；未来伤病/疲劳仅有真正源才定量；财务`cash`与`total_salary`口径若未清楚不能当剩余签约空间。

### 1.2 每位球员的固定评估卡（球队大名单内均应覆盖）

| 块 | 最少记录 | 经营用途 |
| --- | --- | --- |
| 身份与资产 | 来源身份、现属球队、年龄（如源可靠）、位置、合同本季薪资/剩余年限、潜力（按当前源）、可否交易 | 保护核心/确定流动资产，避免错交易/克隆 |
| 近期与累计比赛 | 当前赛季出场/实际分钟/得分/助攻/篮板/投篮/失误等**实有**数据；跨批变化；转队样本状态 | 区分爆发/衰退/样本不足/角色被压制 |
| 能力结构 | 55项已认证能力中对任务有辨识力的投篮、组织、终结、护框、外防、机动性与相关短板；不把潜力=OVR | 解释球员能扮演的篮球角色，而不是仅按名气 |
| 当前角色和适配 | 持球/无球/空间/内线终结/护框/外围防守；互补性、技能重叠、教练体系；使用AI实际分钟而非计划分钟 | 判断“人不行”还是“人用错” |
| 资产与成长 | 本队短期胜利贡献、长期自然成长机会、机会成本、替补/新秀使用；工资效益需注明代理性质 | 交易/留用/调整角色的依据 |
| 证据与不确定性 | `OBSERVED/CALCULATED/INFERRED/UNKNOWN`、具体批次和字段、潜在混杂因素 | 决定建议置信度，禁止凭空定量 |

**不要求每人都写数百字，但必须完成大名单覆盖**；球星、交易候选、受错配影响的球员要加深解释。人数不得由“30队各一行”代替。可存机器可读`player_assessments[]`并在正文突出主要球员。

### 1.3 球队竞技诊断

至少有：目标竞争阶段、累计与区间战绩、得失分/经认证的效率、核心与深度、进攻来源和问题、防守端实际人员与结构、替补/主力负荷、人员缺口与可内部替代方案。胜负与净胜分背离时优先区分随机性/对手差异/球队结构，不武断解释成教练失职。

## 2. 第二层——制服组与主教练：先确认机制，才能估值换人

### 2.1 当前项目**已经证实**什么

- M02`source_coverage.json`的`staff_pool`状态为`VERIFIED_RECIPROCAL_TEAM_ROLES`，覆盖完整员工目录以及各NBA球队的**8个岗位**反向关联；基线文档34记录**240个球队员工岗位关联**。它说明能核对身份、岗位及球队，而**不证明**员工属性怎样影响比赛，也不证明员工任免写入器已可用。
- 当前正式可操作的主教练侧主要是`coaching/teams.json`中19项球队默认战术字段和针对指定对手的18项`OVERALL`防守字段。它们是**战术/策略配置**，不等于“解雇/雇佣主教练”或修改教练个人能力。
- 仓库文档34明确：员工岗位/雇佣变更**已验证双向读取，但无完整写回验收**。因此当前`STAFF_CHANGE_EXECUTION_ENABLED=false`应作为业务闸门，而非凭空宣称换帅可直接写游戏。

### 2.2 具体8岗位的价值假设与证据等级：绝不照抄次世代MySTAFF

仓库[来源扩展发现记录](../../docs/31_SOURCE_EXTENSION_DISCOVERY.md)通过30队球队角色指针核对出本局8种真实岗位：**主教练、助理教练、首席球探、训练师、GM、老板、CFO、副GM**。这8个角色不是PS5次世代MySTAFF报道的17人四部门。当前明确能认证的是**岗位存在、归属与人员身份**，没有本PC局实验可证明任意员工等级能带来固定胜率增益。

| 本局实际岗位 | GM需要分析的赢球价值假设 | 当前能确认 / 不能确认 |
| --- | --- | --- |
| `HEAD_COACH` 主教练 | 其球队默认19项与对手OVERALL战术是否适配现有核心？球员是否因体系错配没发挥？ | 可确认身份和原生战术配置；玩家长期赛季经验支持教练与自然成长有关。**不能从当前快照证明换一个教练本人可提高多少胜率，不能直接执行解雇。** |
| `ASSISTANT_COACH` 助理教练 | 与当前主教练职责、球员角色、体系稳定性是否互补？若有可读个人能力/徽章，可否合理比较？ | 当前能确认岗位与人，个人属性效应、战术影响公式和安全更换接口`UNKNOWN` |
| `HEAD_SCOUT` 首席球探 | 未来历史轮回选秀的信息质量、候选人才发现能力；这会否影响球队未来资产选择？ | 岗位可读；本局球探评级→报告准确率/新秀品质的因果关系`UNVERIFIED`，不能假造 |
| `TRAINER` 训练师 | 球员可用性、伤停风险和长期竞技状态（如果将来有可信同局观察） | 岗位可读，伤病/疲劳与其能力的本局机制`UNKNOWN`；**本GM不管理训练计划、负荷或训练接口** |
| `GENERAL_MANAGER` GM | 外挂球队经营决策与游戏原生GM身份如何共存？其游戏内潜在经营属性是否有真实作用？ | 原生岗位可读；外挂GM是决策权威，不假称原生GM评级能决定外部交易是否成立 |
| `ASSISTANT_GM` 副GM | 人员识别、长期建队与财务谈判的潜在支持 | 岗位可读；游戏内直接作用及数值公式`UNKNOWN` |
| `CFO` 财务官 | 预算与资产管理的潜在影响，可能间接关系未来建队 | 岗位可读；薪资会计口径尚有差异，不能将CFO评级当可用现金或签约空间 |
| `OWNER` 老板 | 球队目标、预算与组织连续性；只读原生约束是否改变战略可行性？ | 岗位可读，是否有游戏引擎直接加成/可被任免`UNKNOWN`，不得以“更换老板”作可执行动议 |

**研究优先序**：本局已经有读写证据的**主教练战术配置及其与球员适配** > 员工岗位的真实身份、条件与本队球队人格 > 未验证的个人员工评级/徽章效果 > 不适用于PC平台的次世代官方说明。换帅只有在留用/调整战术无法解决问题、员工效益和候选来源具备证据且安全任免执行器真实可用时才进入执行链。对其余员工可`STAFF_HOLD/STAFF_REVIEW`，但不为证明价值主动训练或模拟实验。

**版本隔离原则**：2K官方2021年9月MySTAFF报道明确适用于PS5 / Xbox Series X|S上的次世代MyNBA，介绍四部门及17员工规模，但不能把其 `Sports Psych/Shot Doctor`等岗位与加成直接照搬成本项目**PC NBA2K22**的8岗位系统。只作`REFERENCE_OTHER_PLATFORM`。官方原始参考：
`https://newsroom.2k.com/news/nbar-2k22-adds-new-features-to-mynba-for-playstation-5-and-xbox-series-xs-consoles`。
社区称教练评级/徽章或可影响球员成长属于`PLAYER_EXPERIENCE/INFERRED`层级，不自动当公开精确公式。玩家长期多赛季观测“教练体系影响自然成长”可作为GM策略前提，但不构成定量效果或员工写入许可。

### 2.3 何时推荐更换主教练/员工（`STAFF_REVIEW`）

必须逐项回答：
1. 现有人员及岗位是谁？是否有**确认的属性或评级**，还是只有名称/身份？原生战术的真正责任人是谁？
2. 问题是阵容、教练体系**参数**、球员新交易适应，还是人员能力本身？有无足够的非单场证据？
3. 保留人员仅调整战术是否更可逆、更便宜？其他职位能否弥补？业务与教练风格、争冠窗口是否一致？
4. 候选替代者是否实有、身份/岗位/成本/能力数据是否可核实？替换可能造成的战术连贯性与自然成长风险？
5. 是否**具备经玩家批准的完整原生任免执行器**？若没有，结论只能是`STAFF_CHANGE_RESEARCH_CANDIDATE`或`STAFF_HOLD`，不得输出可执行员工指令；转给开发规划的是**机制核验/安全任免能力**请求，而不是擅自换人。

应优先利用已经确认可写的教练战术去解决战术错配，而不是在不知道员工游戏效益时直接换帅。

## 3. 第三层——球队教练体系和对手攻防策略

依[GM教练手册](GM_COACHING_OPERATIONS.md)的原生字段、同批字典和权限：

- `COACH_DEFAULT`19项：六POE、Preferred/Active系统、Playbook、四Freelance、BenchDepth、BenchUtilization、RunPlayTendency、ZoneUsage、HelpDefense、Tempo（raw可写但游戏含义UNKNOWN）。要把当前人员能力与拟定主打战术建立**逐个字段的篮球因果假设**，不因全联盟POE统一就一律修改。
- `VS_OPPONENT_DEFENSE`18项：只在关键对手威胁明确时从所属owner的29个对手文件读取`OVERALL`组；写入会作用于该owner面对该对手的**全部有效matchup**，不是个人单防。不搞870对手无差别改动。
- `BenchDepth`仅影响轮换可用人数上限，`BenchUtilization`影响替补使用倾向；**游戏AI持续分配个人分钟**，不锁定、不反复覆盖。
- 目标应服务各队的长期风格：挡拆空间/侧翼防守/内线重力/转换/控制节奏等；风格是偏好，而非阻止合理变招或强制现实历史结果。
- 每次仅采用必要、易解释的最小变更集，标当前raw→目标raw、适配关键球员、预计方向、相反风险、潜在对手和取消条件。多个字段一起变化导致归因更差，需有合理联合原因。
- 不研究、不管理训练，不直接写球员个人倾向/能力；`Sim*`五项不允许GM编辑，Tempo UI意义未知不能命名为已确定节奏。
- 如现实教练实用效果不可确定，记录`TACTIC_EFFECT_UNVALIDATED`并依据真实比赛后续观察，不凭“教练A比B高3点”估算+X胜。

## 4. 第四层——人员交易、签约与角色重构

- 每队先比较三种情形：`HOLD`、使用现有球员经战术/轮换调整、用市场替换明确短板。交易不是亏队换来好球员就自动成立：必须分别算**卖方保留价值**、买方赢球收益、成长窗口、合同、未来资产机会成本。
- 在30队深度档案阶段记录`MARKET_INTEREST_CANDIDATE`、核心保留线、可出售与关键需求；**不直接宣布两个球队完成最终谈判**。全30队完成后才在联盟整合回合比较资源冲突及双方利益，最多必要的反报价，最终只有双方接受同一组真实资产/合同/选秀权条款才提`BILATERAL_TRADE_PROPOSED`。
- 严格使用当前`draft_assets.json`的2022–2024三年合法简单签位资产身份，只有年份/轮次/原队/当前持有者，不构造保护或互换条款。
- 普通交易当前有受控执行机制但每笔需要玩家批准和执行前身份/合同/人数/签位归属校验；签约，尤其休赛期竞价与原生合同写回，若未验证只做方案/报价，不能伪装正式可执行。
- 阵容搭配/首发建议若原生写回尚未认证，则作为球队经营意图，不能伪装可操作的球员配置指令。
- 严禁用未经证实的球队层薪资和`cash`差额推断实际可用工资空间、假造CBA硬匹配和真实老板现金预算。

## 5. 其他GM要主动管理的四个价值维度

1. **资产与时间线**：争冠核心年龄/合同持续期、未来三届签位、球员自然成长窗口、交易截止日、球队现金风险（已验证时才量化），确保每队并非“本场赢球而卖光未来”。
2. **长期阵容健康与风险**：围绕稳定得分来源、伤病/疲劳可用性（如果已采集）与冠军轮次可行性评估，避免过度使用高负荷核心的短视策略；不做精确分钟锁定或训练管理。
3. **比赛目标和策略连续性**：只写能用数据检验的目标（降低对手三分、提高篮下命中、减少失误等）；原生战术体系改变时应具备真正的篮球逻辑，不随单场结果摇摆。未经独立论证不编造所谓球队文化或长期哲学。
4. **信号异常与决策审计**：区间净胜/胜负背离、跨队累计统计、球员模型重复、交易资产冲突、员工岗位缺失、薪资口径异常，都是`DECISION_RISK_FLAGS`。没有足够数据时允许`HOLD_FOR_EVIDENCE`，但应明确缺什么证据，不自动制造采集项目。

## 6. 球队统一决策合同：强制六个独立问题与一份闭环记录

每队都必须明确回答：

| 决策维度 | 不可省略的判断 | 可能输出状态 |
| --- | --- | --- |
| D1 `STAFF` | 本节点按玩家新指令暂缓员工分析，日后技术读取恢复再专项评估 | `STAFF_DEFERRED_BY_PLAYER` |
| D2 `TACTICS` | 是否改变默认教练19项或关键对手18项？是否提高现有人员实际使用价值？ | `COACHING_HOLD / COACHING_PROPOSED` |
| D3 `ROSTER_USE` | 当前球员分工、替补组合、AI轮换可否内部优化？还是硬性战力缺失？ | `LINEUP_HOLD / INTERNAL_ADJUSTMENT_INTENT` |
| D4 `MARKET` | 留人/交易/签约何者更优？哪支球队愿意成为交易对手，报价资产是否真的存在？ | `MARKET_HOLD / MARKET_INTEREST_CANDIDATE / BILATERAL_TRADE_PROPOSED / SIGNING_RESEARCH` |
| D5 `ASSETS_AND_DEVELOPMENT` | 合同窗口、未来资产、年轻人自然成长机会、主将风险是否支持本队赛季/长期目标？ | `ASSET_HOLD / LONG_TERM_BUILDING_PLAN / RISK_MITIGATION` |
| D6 `TEAM_IDENTITY_AND_MONITORING`（兼容旧键） | 具体改善哪项比赛指标？下次怎么判断效果？ | `MONITOR_NEXT_PLAYER_TRIGGERED_BATCH / NO_ACTION` |

**强制决策记录字段**：`career_id`、`game_season`、`game_date`、`source_batch_id`、`analysis_batch_id`（如有）、`gm_node`、`round_id`、`team_id/abbr`、`goal_phase`、`decision_objective`、`player_assessments`（覆盖大名单）、`team_diagnosis`、`staff_assessment`、`coaching_assessment`、`roster_use`、`contract_and_draft_assets`、`decision_alternatives`、`decision_dimensions{D1..D6}`、`evidence_refs`、`uncertainties`、`candidate_actions`、`expected_direction_without_fabricated_win_pct`、`monitoring_plan`、`review_status`和`approval_state`。

**程序覆盖闸门**：结构化档案应记录`source_roster_player_count/assessed_roster_player_count/roster_coverage_status`。完整深度轮通过**确定性比较**确认同批`teams/<abbr>.json`当前名单身份集合，与`player_assessments[]`独特来源身份集合完全一致；仅JSON Schema通过不能证明30队全员覆盖。任何漏评或身份无法确认必须标`INCOMPLETE_REWORK_REQUIRED`，不能计入本轮研究完成。

**质量闸门**：缺主力球员详细能力或当前主教练身份的队伍标`REWORK_REQUIRED`；员工目前被玩家明确延期，所以`STAFF_DEFERRED_BY_PLAYER`是有效决策状态，不会阻止以本队球员/比赛/战术深度为主的审查通过。真要执行换帅则必须另行读取员工身份与能力并检查受控执行器。每一项变化必须可追踪到有证据的比赛问题与当前实测表现，`HOLD`要给出成本收益比较。

## 7. 30队整合后如何真正决策与验收

- **前3×10队或6×5队**：产出逐队深度档案+可机器读的每队6维度合同，并由V3`TEAM_REVIEW_TRACKER.json`确认覆盖30/30；没有足够质量不能偷跳整合。
- **倒数第二轮**：跨队比较交易价格、教练/员工候选与相互影响；为每笔交易呈现买卖双方`hold_value/acquire_value/asset_cost`的证据与真实一致条款，并核对同一球员/签位不会重复卖。
- **最后一轮**：形成唯一终稿，列出`HOLD / STAFF_REVIEW / COACHING / TRADE / SIGNING / OTHER`，明确每项不变、改变的源事实及执行能力。员工任免若无已验收双向安全执行器必须`BLOCKED_NO_EXECUTOR`，不交错写游戏。
- **批准与执行**：按最新SOP与文档40，用户批准教练具体`career_id/batch_id/decision_id/version/action_ids/batch_digest`和交易单独资产；Codex只读预检、必要写入和回读；GM不能把`D5结束`直接等同游戏修改。
- **下次采集形成反馈**：对比同口径战绩和进攻/防守、球员实际表现与自然成长、教练原生回读、转队新样本与资产变化，标记`IMPROVED/WORSENED/INCONCLUSIVE`并检查混杂因素。仅玩家触发下一检查点时进行，不自动推进比赛/采集。

## 8. 历史线 / 现实线分工：明确隔离，互不污染

- **GM职责**：以本局球队真实战绩与赢球哲学经营30队；参考真实NBA历史中的建队模式、球星组合、教练风格、王朝脉络，**优先使用真实交易、签约和教练战略**作历史线与真实模拟结果的博弈；不追求硬复制冠军或直接修改球员属性以逼出历史结果。历史线仅是`REFERENCE_WORLDLINE`而非本局真实比赛数据。
- **开发规划职责（玩家建议采纳为责任分工）**：历史线重力中如确有必要、希望对**现有联盟人物作符合时代发展逻辑的特殊能力/信息定制**，由开发规划基线独立设计和审计，不能把能力编辑嵌入GM普通交易或教练优化。开发端需对齐游戏年份/历史选秀轮次/本局人物和重叠身份，并用受控数值方案说明有限性、依据、原值→目标值、期限与恢复办法。
- **玩家专属审批**：该历史例外是`SEPARATE_HISTORICAL_GRAVITY_PROPOSAL`，无**每次明确单独批准**不得启动脚本、构造外挂提升包、在数据库回填为事实；历史线属性执行器现未认证，需技术验收方可合法执行。GM批准交易永远不包含历史线属性编辑批准。
- **历史规则参考**：[角色与世界线规则](../../docs/26_GAMEPLAY_ROLES_AND_WORLDLINE_RULES.md)及[开发规划专项交接](../../docs/development_tasks/DEV_20261018_HISTORY_GRAVITY_GM_BOUNDARY_V1.md)。MC玩家成长故事依旧禁用暂缓，训练始终交游戏AI。
