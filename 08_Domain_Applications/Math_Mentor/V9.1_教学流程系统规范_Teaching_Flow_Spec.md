Status: manual-chat teaching execution-flow specification.

This file is the human-facing execution-flow specification for Math Mentor manual teaching tests. It aligns with:

- `LESSON_PLAN_SCHEMA.md`
- `TEACHING_AGENT_CONTRACTS.md`
- `BRIDGE_SLOT_TEACHING_CONTRACT.md`
- `EXAM_HANDOFF_STATE_VECTOR_SCHEMA.md`
- `STUDENT_LEARNING_STATE_SCHEMA.md`

It does not override later accepted LRP contracts. If this file conflicts with those contracts, the later accepted contract controls and this file should be repaired.

This file does not activate runtime, production Coordinator execution, external tools, apps, MCP servers, node generation, bridge generation, learning-state writes, learned-history writes, or spaced-review scheduler writes.

## 1. Authority And Namespace

Plan 3 authority routing is separate from Math Mentor teaching lanes.

```yaml
authority_namespace:
  Plan3_Engine_A: "code, deterministic implementation, tests, and tooling"
  Plan3_Engine_B: "human-moderated knowledge teaching and semantic judgment"
teaching_lane_namespace:
  MathLane_A: "computable algebra lane"
  MathLane_B: "pure structure lane"
  mixed: "reviewed transition between MathLane_A and MathLane_B"
```

Do not use `Engine_A` or `Engine_B` as Math Mentor lane values.

Legacy `Mode A` and `Mode B` wording may appear in old documents. In current teaching state, translate them as:

- `Mode A` -> `MathLane_A`
- `Mode B` -> `MathLane_B`

## 2. Teaching Lanes

### 2.1 MathLane_A: Computable Algebra Lane

Use for foundational and computable material, including L1-L3 default teaching and designated computable L4-L6 branches.

Primary intuition:

- everyday physical models;
- low-friction examples;
- computable special cases;
- formal definition after intuition.

Tool boundary:

- deterministic tools may be requested only in future authorized tasks;
- no Z3, SymPy, Python, PyTorch, calculator, sandbox, or app execution is claimed unless `tool_status: run_with_log` and a concrete `log_ref` exist.

### 2.2 MathLane_B: Pure Structure Lane

Use for abstract pure-structure domains such as topology, functional analysis, measure-theoretic structures, category-like abstraction, and named meta-logic exceptions.

Primary intuition:

- LLM-architecture mapping;
- attention, residual stream, embedding space, tensor-shape or representation-flow analogy when supplied by node evidence;
- semantic audit, not machine proof.

Mode B canonical teaching must not use household, factory, fluid, or ordinary-object metaphors as the primary mapping. If a MathLane_B node lacks valid LLM-architecture mapping evidence, teaching must request re-prep rather than silently substituting a daily metaphor.

### 2.3 Mixed

`mixed` is allowed only for a reviewed transition from computable intuition to pure structure. It is never a fallback for uncertainty.

## 3. Loading And Evidence

Manual chat teaching uses lazy loading by exact need.

Required loading behavior:

1. load the current Human target request;
2. load `AI_Bootstrap_Sequence.md`, Plan 3 authority, and the Math Mentor entry prompt when starting from a new context;
3. load this Teaching Flow Spec;
4. load `LESSON_PLAN_SCHEMA.md`, `TEACHING_AGENT_CONTRACTS.md`, and `TOOL_TRUTHFULNESS_POLICY.md`;
5. load the exact target node only after the target is resolved;
6. load immediate prerequisite nodes only when the lesson needs them;
7. load matching bridge records only when their endpoints match the target or prerequisite evidence;
8. load learned-history evidence only when bridge gating, prerequisite satisfaction, or review state matters;
9. record every physically read file under `actually_read_files`.

Forbidden loading behavior:

- full repository ingestion;
- full Math Mentor directory ingestion;
- reading every node YAML for one target lesson;
- reading every bridge file before target matching;
- routine use of `数学知识路线图_全部.yaml`;
- claiming a file was read when it is not in `actually_read_files`.

## 4. UI-Visible Compressed State Dump

For manual chat tests, Coordinator must expose one compressed UI-visible `SYSTEM_STATE_DUMP` per target node. This is for student transparency and model-test audit. It is not a full YAML dump.

Required fields:

```json
{
  "Target_Node": "<node id, file, and title>",
  "Math_Lane": "MathLane_A | MathLane_B | mixed",
  "Routing_Basis": "<domain/subdomain evidence, named exception, or reviewed transition>",
  "Core_Definition": "<compressed definition or criterion>",
  "Sub_Topics": ["<source subtopic names>"],
  "Bridge_Slots": [
    {
      "Node_ID": "<n_xxx or BRIDGE-XXX>",
      "Name": "<concept or bridge title>",
      "Bridge_Type": "intra_layer | cross_layer | prerequisite_bridge | forward_outlook_bridge",
      "Learned_Status": "learned | teaser_only | hidden | unavailable",
      "Connection": "<one sentence>"
    }
  ],
  "lesson_plan_contract": "LESSON_PLAN_SCHEMA.md",
  "prep_to_socratic_payload_contract": "TEACHING_AGENT_CONTRACTS.md#Prep-To-Socratic Contract",
  "tool_truthfulness": "not_run | run_with_log | unavailable | semantic_only | planned | review_required",
  "actually_read_files": [],
  "unavailable_files": [],
  "Next_Node_Outlook": "<one sentence teaser or unavailable>",
  "Mapping_Status": "mode_a_physical_primary | mode_a_ai_teaser | mode_a_ai_formal | mode_b_llm_architecture | re_prep_required",
  "Current_Agent_Active": "Guided_Socratic_Router"
}
```

节点无可解引用 bridge 记录时，`Bridge_Slots` 取空数组并附 `bridge_evidence: none`，禁止占位字符串。

## 5. Canonical Teaching Flow

### Phase 1: Human Target Request

The Human names a concept, node id, or exact file target. This request authorizes manual chat teaching only unless it explicitly authorizes more.

### Phase 2: Coordinator Minimal Context Loading And MathLane Routing

Coordinator resolves the target, loads only required evidence, chooses `MathLane_A`, `MathLane_B`, or reviewed `mixed`, and emits the compressed `SYSTEM_STATE_DUMP`.

Routing must use domain/subdomain and node evidence. Level number alone is not sufficient.

### Phase 3: Prep_Architect Wrapper Output

Prep_Architect outputs exactly one JSON code block with this top-level wrapper:

```json
{
  "lesson_plan": {},
  "coverage_map": {
    "source_subtopic_count": 0,
    "planned_subtopic_count": 0,
    "coverage_status": "complete | incomplete"
  },
  "handoff_status": "ready | blocked | request_reprep",
  "evidence_trace": {},
  "tool_truthfulness": {}
}
```

`lesson_plan` must comply with `LESSON_PLAN_SCHEMA.md`. Every source `sub_topics` entry maps exactly once into `lesson_plan.subtopic_plan`.

### Phase 4: Socratic_Router Guided Explanation-First Teaching

Socratic_Router consumes the Prep wrapper. It may accept a nested `lesson_plan` object, but must preserve `coverage_map` and `handoff_status` when they are available.

Teaching order:

1. occurrence crisis;
2. lane-consistent intuition model;
3. formal compression;
4. bridge slot activation when evidence allows;
5. full subtopic coverage;
6. one compact forcing question per interactive turn;
7. repair once before correction;
8. student definition restatement.

Pure interrogation before teaching is invalid.

### Phase 5: Exam_Agent Independent Classroom Test

Socratic_Router stops teaching and emits `SYSTEM_INTERRUPT: EXAM_HANDOVER` only after:

- every subtopic is covered;
- formal bridge checks are complete or explicitly unavailable/teaser-only;
- the student restates the definition or criterion.

The handoff must use `EXAM_HANDOFF_STATE_VECTOR_SCHEMA.md` field names.

Exam_Agent tests independently. It does not teach a replacement lesson.

### Phase 6: Learning-State / Spaced-Review Placeholder

If Exam_Agent returns `classroom_passed`, this means only the current classroom trap passed.

It does not mean:

- long-term graduation;
- spaced-review pass;
- scheduler write completed;
- learned-history state updated.

When scheduler write is not separately authorized, emit a placeholder:

```yaml
review_scheduler_status: "placeholder_not_written"
actual_scheduler_write_performed: false
next_authorized_action: "Future Human-approved scheduler task may create the review item."
```

Exam_Agent must not directly write to `数学间隔重复调度表.md`.

## 6. Tool Truthfulness

Allowed tool evidence states:

- `not_run`
- `run_with_log`
- `unavailable`
- `semantic_only`
- `planned`
- `review_required`

`v8_sanity_audit` is treated as semantic or high-density prompt evidence unless a real `run_with_log` tool report exists. It must not be described as executed, verified, computed, rendered, or machine-proven without a concrete log/report reference.

## 7. Manual Chat Test Readiness

A Human can run one manual teaching test without activating runtime:

1. name a target node or concept;
2. ask the Coordinator to state `actually_read_files`;
3. verify the compressed `SYSTEM_STATE_DUMP`;
4. ask Prep_Architect for the wrapper JSON;
5. ask Socratic_Router to teach the first subtopic;
6. require explanation before the first question;
7. after all subtopics and definition restatement, hand off to Exam_Agent;
8. verify Exam_Agent returns `classroom_passed`, `failed`, or `needs_reprep`;
9. verify any review/scheduler output is a placeholder unless separately authorized.

### Dry-Run Outline: MathLane_A

- Target: a basic computable concept.
- Expected intuition: everyday physical model.
- Tool status: `not_run` unless a real log exists.
- No claim of actual target YAML loading unless the target YAML path appears in `actually_read_files`.

### Dry-Run Outline: MathLane_B

- Target: an abstract pure-structure concept.
- Expected intuition: LLM-architecture mapping.
- Tool status: `semantic_only` or `not_run` unless a real log exists.
- No household or factory metaphor as primary teaching model.

Manual chat-based teaching tests are ready when Coordinator, Prep, Socratic, and Exam prompts all follow this flow.
