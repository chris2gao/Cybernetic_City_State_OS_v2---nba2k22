# Math Mentor Tool Truthfulness Policy

## 1. Purpose

This policy defines how Math Mentor may speak about deterministic tools, semantic audits, visualization systems, apps, and future runtime support.

It is a documentation contract only. It does not run Z3, SymPy, Python, PyTorch, calculators, visualization generators, MCP servers, browser apps, or production Coordinator logic.

## 2. Allowed Claim States

Every tool-related statement must use one of these states:

| claim state | meaning | allowed wording |
| --- | --- | --- |
| `not_run` | No tool was run. | "No deterministic tool was run." |
| `run_with_log` | A tool run occurred and a concrete log/report ref exists. | "The attached log reports the tool result." |
| `unavailable` | The capability or dependency is unavailable in the current task. | "The deterministic tool is unavailable in this context." |
| `semantic_only` | The model reasoned conceptually or reviewed semantic consistency only. | "Current evidence is semantic-only." |
| `planned` | Capability is future design only. | "This capability is planned for a future authorized implementation." |
| `review_required` | Evidence is insufficient or contradictory and requires review. | "This requires review before any deterministic claim." |

`run_with_log` is the only state that can support a statement that a deterministic tool ran.

## 3. Safe Wording Table

| situation | unsafe wording | safe wording |
| --- | --- | --- |
| v8 audit exists but was not executed | "SymPy verified the audit." | "A SymPy-style audit exists, but no execution log is present." |
| Mode B semantic review | "The theorem is machine-proven." | "The mapping passed semantic review only." |
| missing dependency | "The calculator checked it." | "The calculator capability is unavailable; no tool run is claimed." |
| future visualization | "Here is the generated graph." | "A visualization could be generated in a future authorized task." |
| contradictory output | "The tool confirms the lesson." | "Tool evidence is contradictory; mark `review_required`." |

## 4. Forbidden No-Log Phrases

Without a concrete command/log/report reference, do not say:

- "verified by Z3";
- "computed by SymPy";
- "checked in Python";
- "tested in PyTorch";
- "confirmed by calculator";
- "generated by the app";
- "rendered by the visualization tool";
- "machine proof";
- "sandbox passed";
- "tool execution succeeded".

## 5. Semantic Audit Versus Machine Proof

Semantic audit means:

- LLM reasoning checked conceptual consistency;
- Mode B mapping is coherent enough for teaching;
- natural-language proof or analogy boundaries were inspected;
- no deterministic execution is implied.

Machine proof or deterministic calculation means:

- an authorized tool runner executed a concrete command;
- the command used explicit inputs and environment;
- output/error/status were logged;
- a report ref is available;
- the lesson payload records `tool_status: run_with_log`.

Semantic audit can support teaching explanation. It cannot replace a deterministic command log.

## 6. Contradiction Handling

If semantic reasoning and deterministic tool output conflict:

1. Set claim state to `review_required`.
2. Preserve both evidence refs.
3. Do not suppress the contradiction.
4. Do not present either side as final truth until reviewed.
5. Re-prep the lesson only if the contradiction affects the current teaching path.

If two deterministic logs conflict, mark `review_required` and escalate to Human/ChatGPT review.

## 7. Missing Dependency, Timeout, Or Unavailable Handling

| failure | required state | required action |
| --- | --- | --- |
| tool missing | `unavailable` | State dependency unavailable and continue semantically if safe. |
| timeout | `review_required` or `unavailable` | Preserve timeout log if present; do not claim result. |
| unsafe input | `review_required` | Stop tool handoff and request sanitized input. |
| malformed output | `review_required` | Preserve output ref and block deterministic claim. |
| no log ref | `not_run` or `semantic_only` | Use safe wording only. |

## 8. Citation, Log, And Reference Requirements

A deterministic tool claim must include:

```yaml
tool_truthfulness:
  tool_status: "run_with_log"
  capability: "deterministic_calculation"
  tool_family: "Z3 | SymPy | Python | PyTorch | calculator | other"
  log_ref: "<required>"
  report_ref: "<required or null>"
  input_ref: "<required>"
  output_ref: "<required or null>"
  error_ref: "<required if error occurred>"
  environment_ref: "<dependency/runtime info>"
  timestamp: "<UTC timestamp>"
  limitations: []
```

If these fields are absent, use `not_run`, `semantic_only`, `unavailable`, `planned`, or `review_required`.
