# V9.1 神经符号双擎 (NeuroSymbolic Dual-Engine) 防崩溃指南

## 系统崩溃诱因 (V7/V8 时代的血泪教训)

在赛博城邦系统从 V7 迈向 V8 的过程中，我们曾遭遇过严重的系统级宕机。其根本死因并非大模型的幻觉（Hallucination），而是**底层算力引擎的物理死锁**。

当我们将 Z3 SMT 求解器和 SymPy 作为唯一的“绝对真理裁判”时，产生了以下致命的 P0 级崩溃：

1. **无穷维度的量词爆炸 (Quantifier Explosion)**：拓扑学和泛函分析中充斥着 $\forall x \exists y$ 以及集合的无限嵌套。Z3 在处理带有普遍量词的非线性连续空间理论时，极易陷入无穷循环的项匹配（Matching Loops），导致 CPU 死锁并引发系统级 Timeout。
2. **符号表达式的过度解析**：大模型生成的非标准纯数描述，强行扔进 Python `eval()` 或者 SymPy 解析器中，引发大面积的 Syntax Error，导致前台的对话状态机直接崩溃。

为彻底防御这些物理级灾难，V9.1 架构全面实装了**“认知物理同构”与“语义降级”**的安全策略。

## 🛡️ V9.1 防崩溃核心防线

### 防线一：总线级拓扑量词隔离 (Semantic Audit Fallback)
在 `city_state_bus.py` 中，我们部署了硬编码的**双轨分类网关**。
一旦总线探测到交互中出现了高危的纯数词汇（如 `topology`, `banach`, `compactness`, `拓扑`, `流形`），将立刻截断其通往 `sym2z_validator.py` 的物理链路。
**应对策略**：将验证任务强行降级为大语言模型内部的 **Semantic Consistency Audit（语义连续性审计）**。宁可让系统容忍少许语义模糊，也绝不让 Z3 触碰无限维度的量词陷阱。

### 防线二：知识库断言隔离 (Knowledge Prompt vs Direct Eval)
在新版 `Pure_Math_Intuition_DB/schema.yaml` 数据库中，虽然我们引入了极其暴力的 `v8_sanity_audit.sympy_pseudo_code`。但是：
- **严禁后台 `eval`**：总线不会在后台自动提取这段 Python 脚本并使用 `exec()` 或 `eval()` 执行。大模型经常会在其中加入无法解释的变量名，直接执行会导致灾难性的宕机。
- **降级为高密度的知识上下文 (High-density Knowledge Prompt)**：这段严密的测试脚本（如雅可比非奇异性断言），将直接作为 Context 喂给教官大模型。让模型**读着代码的逻辑**去向学生发难。这就相当于给模型戴上了防毒面具：它借用了底层算理的杀伤力，但免除了执行崩溃的风险。

### 防线三：早停降维机制 (Scaffolding Breakout)
监控苏格拉底剧本中的 `frustration_index`（学生受挫指数）。
当学生连续 3 次无法理解“高维泛函空间”的隐喻时，教鞭核 `Socratic_Router` 会被强制触发 `[V8 P1 DYNAMIC SCAFFOLDING TRIGGERED]` 警报。
**应对策略**：教官必须立刻放弃所有关于“流形”、“张量”的装逼词汇，进行**褪色协助 (Fading Assistance)**，直接把问题拍扁到一维坐标轴（令 x=0）进行傻瓜式提问，强行打断可能耗尽 Context 窗口的死循环。
