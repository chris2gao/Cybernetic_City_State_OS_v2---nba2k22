# V9.1 赛博城邦认知映射总线 (Domain Classifier Bus) 实战解剖手册

## 背景与危机
在旧版 V7.x 动态总线架构中，所有数学推导指令都会被无差别送入 `sym2z_validator.py`，经由 Z3 SMT 求解器进行绝对真理验证。
但这造成了一个严重的工程灾难：**算力黑洞**。当用户或系统尝试推演高等泛函分析或拓扑流形时，所涉及的“极限”、“紧致集”、“同胚映射”包含着无穷维度的嵌套与普遍量词（`\forall`）。将这些扔给仅擅长可满足性模理论（SMT）的 Z3 引擎，会瞬间导致匹配循环 (Matching Loops) 死锁和算力超时。

为了彻底解决这一物理极限问题，V9.1 总线在 `city_state_bus.py` 中引入了最核心的**双轨领域分流网关 (Dual-Lane Domain Classifier)**。

---

## 🚦 V9.1 核心机制：双轨分流网关

总线接收到校验请求后，不再盲目执行。它首先提取文本特征，通过严格的分类学将请求分发至两条完全物理隔离的车道：

### 1. `[COMPUTABLE_ALGEBRA_LANE]` (计算代数快车道)
- **触发关键词**：`积分`, `导数`, `方程`, `极限`, `矩阵`, `点乘`, `方差`, `variance`, `integral`, `limit`, `matrix`。
- **执行逻辑**：凡是涉及具体计算和初等微积分的过程，系统必须坚决送入 **V8 潜意识引擎 (Z3 + CEGAR 协程)**。Z3 将发挥其作为底层数字裁判的绝对威力，验证等式的恒真性或边界条件。
- **系统挂载点**：YAML 对象中的 `v8_sanity_audit` 若包含方差计算等明确代数命题，会自动落入此车道。

### 2. `[PURE_STRUCTURE_LANE]` (纯数抽象高架桥)
- **触发关键词**：`拓扑`, `流形`, `泛函`, `希尔伯特`, `同胚`, `紧致`, `群论`, `topology`, `manifold`, `hilbert`, `banach`, `compact`。
- **执行逻辑**：总线会进行**高危拦截**！一旦侦测到这些触及无限维度和高阶集合的词汇，总线会立即越过 Z3 求解器。系统不再强求数学级的形式化证明，而是降级采用 **“大模型语义连续性审计 (Semantic Consistency Audit)”**。
- **系统挂载点**：这部分推演完全交由前台的 `Socratic_Router_v8.0` 和后方的 `Fact_Checker` 利用 YAML 中的 `pure_math_definition` 进行基于文本与物理映射规律的逻辑推断。

## 🛠️ 实战总线拦截流 (Execution Pipeline)

1. **请求到达**：学生提交一段涉及 Attention 缩放因子的论述草稿。
2. **关键词扫描**：总线检测到 `方差 (variance)` 和 `d_k` 维度缩放。
3. **路由判决**：网关打出 `[V9 DOMAIN CLASSIFIER] [COMPUTABLE_ALGEBRA_LANE] Routing to V8 Z3+CEGAR Validation...`。
4. **验证触发**：系统调用后台 Z3 引擎运行预设的 SymPy 断言（如验证 $\text{Var}(q_i k_i) == d_k$）。
5. **反制与重写**：若 Z3 返回 `unsat`（验证不通过或存在危机），总线立刻抛出 `[ACTION_REQUIRED: FRONTEND_REWRITE]`，并把 Z3 的计算死因甩回给前台的教官大模型。
6. **教官接管**：教官接收到总线发来的底层计算崩溃报告，结合 YAML 中的 `llm_physical_mapping` 向学生发难，引导其走向高维泛函空间去寻找缩放解。
