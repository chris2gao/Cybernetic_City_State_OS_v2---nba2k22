## 1. 结论

凭现有仓库信息，外挂系统能弄清大部分参数**在内存里的位置和编码**，但大多**不知道它对应游戏里的哪个选项**，所有参数都**不知道改了以后对比赛有什么影响**。

现阶段能做出正确测试的，只有“读到的值对不对”这一类：解码回归测试，以及拿游戏界面对照的读回测试。**“改了参数比赛会怎样”这类测试现在做不出来**，因为缺少能据以判定对错的因果依据和基准。

## 2. 评估层级

逐级评估，后一层以前一层为前提：

| 层 | 含义 | 对应 R07 证据等级 |
|---|---|---|
| L1 知道位置 | 有地址、偏移、存储类型 | `PROJECT_NATIVE_STRUCTURE_LOCATED` |
| L2 能读到值 | 在真实游戏进程或存档里读到过原始值 | `TARGET_SAVE_RUNTIME_READBACK_VERIFIED` 的前半 |
| L3 知道含义 | 读到的值和 PC 版游戏界面显示的一致 | `TARGET_PC22_UI_AND_VALUE_VISIBLE` |
| L4 能写入并读回 | 写入后读回一致，并能回滚 | `HUMAN_APPROVED_NATIVE_EXECUTION_WITH_READBACK…` 的前半 |
| L5 存档后保留 | 存档、重载后值仍在 | `…AND_SEPARATE_POSTSAVE` |
| L6 知道效果 | 对比赛或模拟结果的影响有经过验证的因果依据 | R07 中所有组均为 `NO_PROVEN_CAUSAL_FORMULA` |

## 4. 具体风险与矛盾

1. **登记含义可能有错。** `max_contract_rating`（`global.632b498.21c.uint32`）登记范围 70–99，2026-10-24 实机读到 40，夹具标为 `OUTSIDE_REGISTERED_CANDIDATE; RAW_RETAINED`。可能是地址对错了项，也可能是登记含义错了，现有资料无法区分。
2. **难度预设编号的含义没核实。** `tunedata.preset` 读到 4，`settings.json` 的标签写“4=名人堂”，但语义状态是 `REGISTERED_PRESET_CODE_UI_LABEL_UNVERIFIED`。
3. **两份核心评估早于实机读取。** R06A 与 R07 都写于 2026-10-21，早于 2026-10-24 的读取；R07 状态是 `R07_RESEARCH_PUBLISHED_PENDING_INDEPENDENT_REVIEW`。
4. **推荐文档不是游戏现状。** `docs/10_GAME_SETTINGS_AND_SLIDERS.md` 是推荐配置，不能当事实，也不能当测试的预期值。
5. **2026-10-24 读取是一次性研究夹具。** `source_manifest.json` 标为 `RESEARCH_FIXTURE`，存档 `MyLEAGUE0003`；重放不等于重新从游戏读取。
6. **效果测试的混杂因素已有记录。** R06A `anomalies` 记录了模拟比分归一化异常（`NORMALIZED_SCORE_MULTIPLIER_2K22`）和“PC22 模拟滑块依赖阵容/倾向修改”（`PC22_SIM_SLIDERS_DEPEND_ON_ROSTER_TENDENCY_EDITS`），均标 `not_universal`。
7. **领域运行目录有两种说法。** `08_Domain_Applications/domain.yml` 的 `domain_run_root` 写的是 `01_os/07_content/_runs/`，`08_Domain_Applications/README.md` 也这样写；`CORE_MANIFEST.yml`（2026-11-18 Human 决定）把领域运行目录定为 `08_Domain_Applications/_runs/`。本 run 按 `CORE_MANIFEST.yml` 放在后者。本任务不修正这两份领域文件。
